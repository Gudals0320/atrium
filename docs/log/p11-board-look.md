## 지시

### 목표

판 화면의 생김새를 바꾼다. 사용자는 지금 화면이 읽기 어렵고 못생겼다고 했다. 기준은 HTML 목업 `app/design/board-mock/`이다. 지휘 세션이 symvibe 홈페이지 데모 영상의 실제 화면을 재서 따라 그렸고, 캡처를 겹쳐 보며 다섯 번 고쳤다. 이 목업의 생김새를 React 창(`app/src/renderer/`)으로 옮긴다. **기능은 바꾸지 않는다.** 백엔드도 고치지 않는다.

목업 보는 법은 다음과 같다(인터넷 필요, CDN 글꼴).
- `app/design/board-mock/index.html?scene=ours`: multitask 내용으로 그린 판. 이것이 목표다.
- `?scene=ref`: 기준 장면을 따라 그린 비교용 판.
- `tokens.css`: 잰 색, 크기, 글꼴.
- `board.css`: 부품. `mock.js`: 장면 데이터.
- 잰 값과 고친 경위: `docs/research/board-mock.md`.
- 캡처: `bash app/design/board-mock/tools/shot.sh <png> ours`(Edge 헤드리스, 1528×960).

줌 75%의 화면 값과 월드 값(줌 100%)을 구분해서 읽는다. `board.css`는 월드 값이고 `scale(0.75)`로 줄여 그린다.

### 완료 기준

1. 개발용 판에 목업 `ours`와 같은 구성을 띄워 창을 1528×960으로 찍는다. 구성은 lead와 하위 w1·w2(가지 선), 기다리는 rev, 붙여 묶은 셸 둘(dev, tests)이고, 줌은 75%다. 목업 캡처와 위아래로 쌓은 비교 이미지를 남긴다. 크롬, 콘솔 머리, 상태 알약, 테두리, 영역 이름표, 칩 줄, 명령 입력이 목업과 같은 자리·크기·색인지 보고에 적는다. 다른 곳은 이유를 적는다.
2. 내 차례 흐름이 그대로다. 기다리는 세션이 위 오른쪽 알약과 노드 빛으로 보이고, 알약 목록이나 `N`으로 가며, 승인 줄로 허용·거부한다(창 시험).
3. 배율 여럿(0.12, 0.24, 0.5, 0.75, 1)의 스크린숏. 아이콘 얼굴과 멀리 얼굴의 글이 깨지지 않고, 기다리는 노드가 늘 눈에 띈다.
4. renderer에 외부 URL(글꼴 CDN 등)이 없고, 하드코딩 색은 토큰 파일에만 있다(`rg`로 확인한 명령과 결과를 보고에 적는다). 네트워크 없이 빌드하고 창을 띄워도 글꼴이 나온다.
5. 기존 단위 시험(백엔드 154개, 창 34개)이 통과한다. 화면 구조가 바뀌어 깨지는 창 시험(`app/test/e2e/`)은 선택자를 고쳐 다시 돌린다. 적어도 `faces.mjs`, `p10-zoom.mjs`, `p10-dock.mjs`, `p10-archive.mjs`, `p7-j1.mjs`, `p8-k1.mjs`, `p6c-i12.mjs`를 돌린다. 돌린 것과 결과를 표로 적는다.

## 보고

### 만든 것

- 색은 `app/src/renderer/tokens.css` 한곳이다. `styles.css`, `sidebar.css`는 변수만 쓴다. JS의 색(xterm 테마, 그룹 색 후보, 세션 머리 점, 종류 기호, 상태 색)도 변수 이름이거나 `lib/tokens.js`의 `cssVar`로 읽는다. Electron main의 창 바탕(`backgroundColor`)만 CSS를 못 읽어 `#0f0f0b`를 썼다(옛 `#14161a`에서 바꿈).
- 글꼴: UI는 Geist(한글 Pretendard), 터미널과 숫자는 JetBrains Mono(한글 Nanum Gothic Coding). 맑은 고딕, Consolas 대체는 없앴다.
- 선 아이콘은 `lib/icons.jsx` 한곳(목업 `P`와 같은 24×24 선).
- 새 기능은 없다. 단추는 모두 있던 동작을 부른다. 작은 덧붙임: 새 세션 대화상자가 종류를 미리 고른 채 열린다(레일의 Claude, Codex, 셸), 레일의 "손으로 잇기"는 노드 손잡이를 늘 보이게 하는 표시 전환, 레일의 "루프"는 모든 루프를 있던 `LoopList`로 보인다, 아이콘 얼굴에 이름을 넣었다(지시 6).

7. 목업의 git 알약(왼쪽 아래)과 예시 알약(칩 줄 위)은 넣지 않았다. 판 전체의 브랜치나 예시 기능이 없다. 칩 "모두 멈춤"도 기능이 없어 넣지 않았다.

9. 머리에는 목업에 없는 것(메모리, 모델, 표시들, 동작 아이콘 넷)이 남는다. 좁으면 표시들이 먼저 잘리고 이름이 남는다(이름은 노드 폭의 42%까지).

고친 창 시험 선택자는 없다. 옛 선택자(`.mt-wsbtn[data-name]`, `.mt-chip.need[data-name]`, `[data-action=…]`, `[data-choice]`, `.mt-node-head`, `.mt-pill`)를 새 화면에 그대로 남겼다. 바뀐 것은 판 값을 P11로 돌리는 lib(`p11-board.mjs`, p6c·p7·p8·p10 lib)와 P10 시험의 창 크기다.

### 계획과 다른 곳, 알려진 문제

- `.mt-chip.need`(내 차례 줄)는 이제 펼침 목록 안에만 있다. 목록을 열지 않고 칩을 바로 누르던 옛 시험(`p5-g4.mjs`, `c345.mjs`, `c3-trust.mjs`)은 먼저 `[data-role="inbox"]`를 눌러야 한다. 이번에 돌린 시험에는 없다.
- 영역 이름표의 단추(정리, + 세션)는 마우스를 올리거나 ⌄를 눌러야 보인다. `p6c-arrange.mjs`처럼 `[data-action=arrange]`를 바로 누르는 시험은 이름표에 마우스를 먼저 올려야 한다(이번에 돌리지 않음).
- 승인 줄이 뜨면 터미널 줄 수가 줄어 패널 크기가 바뀐다(답하면 돌아온다). 목업처럼 줄이 터미널을 가리지 않게 하려는 것이다.
- 가까이 얼굴의 승인 줄은 월드 크기라 배율 0.5 근처에서는 글이 화면 8px쯤이다(줄 높이가 터미널 자리라 배율 따라 키우지 않았다).
- ARCH 7.1 "고정 요소"(위쪽 줄, 아래 워크스페이스 단추)와 "승인 카드" 행, `docs/testing.md`(P11 판 감싸개 `experiments/p11/tools/e2e.cjs`)는 내가 고칠 수 없는 문서라 지휘 세션이 고칠 것이다.
- 목업 파일(`app/design/board-mock/`)은 고치지 않았다. 목업 캡처 `experiments/p11/mock-ours.png`는 우리 목업(ours)을 찍은 것이고 데모 화면이 아니다.
