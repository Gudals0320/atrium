상태: 닫힘
날짜: 2026-11-01

## 지시

사용자 요청. 지휘 세션이 직접 고친다.

- 백엔드는 어떻게 도는가. 지금은 명령어 말고 닫을 수단이 없다.
- 백그라운드(트레이) 아이콘을 만들어, 거기서 닫기 같은 것을 자유롭게 쓰게 한다.

완료 기준: 트레이 메뉴로 백엔드를 다시 띄우고, 끄고, 켜고, herdr까지 끄고, 백엔드도 끄고 앱을 끝내는 것을 개발용 판의 창 시험으로 본다. 단위 시험과 빌드가 통과한다.

## 작업 기록

- 지금 구조:
  - 창(Electron)이 백엔드(Node, 떼어 띄운 프로세스)를 없으면 띄우고, 백엔드는 herdr 서버가 없으면 띄운다.
  - 창을 닫아도 백엔드와 herdr, 그 안의 claude는 계속 돈다.
  - 트레이는 설정 `tray`(기본 꺼짐)를 켰을 때만 있었고, 메뉴는 열기, 내 차례, 끝내기(앱만)였다. 그래서 백엔드를 끄는 길은 `mtask backend stop`뿐이었다.
- 고친 것:
  - 트레이 아이콘을 앱이 도는 동안 늘 둔다.
  - 설정 `tray`의 기본을 켜짐으로 바꿨다. 창을 닫아도 앱이 트레이에 남아야 아이콘으로 백엔드를 다룰 수 있다.
  - 메뉴에 백엔드 상태와 다음 항목을 더했다: 켜기·다시 띄우기·끄기, herdr까지 모두 끄기(확인창), 앱 끝내기(백엔드와 세션은 계속), 백엔드도 끄고 끝내기.
  - 백엔드를 끄는 항목은 창을 먼저 닫는다. 열린 창은 꺼진 백엔드를 다시 띄우기 때문이다.
- 개발용 판 `multitask-dev-p14`(포트 47829, `backend/.dev/p14`, 대화 목록은 빈 폴더)에서 `app/test/e2e/p14-tray.mjs`를 돌렸다.
  - 처음에는 마지막 단계(백엔드도 끄고 끝내기)가 실패로 나왔다. 앱은 끝났지만 Playwright의 close 이벤트가 오지 않았다. 백엔드가 Electron의 출력 파이프를 물려받기 때문이다(harness `closeApp`과 같은 까닭).
  - 앱이 끝났는지를 main pid로 보게 고친 뒤 10/10이 통과했다.
  - 끝난 뒤 herdr 세션과 판 데이터를 지웠다.

## 보고

- 트레이 메뉴:
  - 열기
  - 내 차례 n
  - 백엔드 상태(켜짐 · 세션 n / 꺼짐 / …하는 중)
  - 백엔드 다시 띄우기(꺼져 있으면 백엔드 켜기)
  - 백엔드 끄기(창을 닫는다, 세션은 계속)
  - herdr까지 모두 끄기(세션이 끝난다)…
  - 앱 끝내기(백엔드와 세션은 계속)
  - 백엔드도 끄고 끝내기
- herdr까지 끄기는 확인창을 거친다. 다음에 판을 열면 백엔드가 herdr를 다시 띄우고, claude 세션은 이어 가기로 돌아온다.
- 시험(`experiments/p14/p14-tray.json`): 10/10 통과.
  - 아이콘과 기본 상주
  - 다시 띄우기(새 pid, 창이 다시 붙음)
  - 끄기(창이 닫히고, 앱이 남고, 창이 없으면 다시 뜨지 않음)
  - 켜기, 열기
  - herdr 끄기 취소와 확인
  - 다시 열면 백엔드와 herdr가 다시 뜸
  - 백엔드도 끄고 끝내기
- 단위 시험: 백엔드 167(설정 기본값 시험 고침), 창 34, 빌드 통과.
- 알려진 문제:
  - 메뉴 동작은 시험 훅(`global.__mtTray.run`)으로 눌렀다. 실제 트레이 메뉴를 마우스로 누르는 것과 확인창은 사람이 확인한다.
  - 지금 떠 있는 실제 판 앱은 옛 코드라, 앱을 한 번 다시 켜야 새 트레이가 나온다.
