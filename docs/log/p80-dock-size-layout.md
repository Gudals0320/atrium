날짜: 2026-11-07

## 지시

### 목표

덩어리(붙여 묶은 세션)의 크기 막대를 다시 짠다. 배치 틀(비대칭 틀 포함)의 칸 비율을 지키고, 가로형·세로형과 16:9·4:3은 칸 모양에 가장 가깝게, 크게·보통·작게는 세션 수에 따라 단독 세션보다 조금 크게 한다.

### 사용자의 말(P77을 써 본 뒤, 2026-11-07)

"dock 에서 16:9 혹은 4:3 옵션을 선택하면 모든 세션 크기가 동일해짐. 4개 dock 에서 1x3 같이 비대칭 레이아웃을 절대 못쓰는데 어케함? 그리고 dock 칸마다로 하니까 불편함. 크게. 했을 때 의도대로 합쳐진 세션들이 단일 세션의 크게 와 비슷해야 하는데 (여러 세션이 합쳐졌으니, dock 의 크게 옵션은 single 의 크게 옵션보다 큰게 자연스러운게 맞음. 나도 원함.) 너무 커짐. 약간 더 크게알아서 잘.. 해야 함. 그리고 비대칭 dock 들은 어케할건지? 16:9 4:3 및 가로 세로 옵션은 넣는게 좋은데 이게 그냥 무턱대로 칸마다로 적용하니 이상해짐"

P77의 결정("칸 하나 = 같은 값의 단독 세션 크기", 2026-11-07)을 사용자가 되돌렸다. 크기는 "단독보다 약간 크게"를 맡겼다. 아래 설계는 지휘 세션이 사용자에게 알린 안이다.

### 지금(P77, `v0.1.3-dev.5`)

- 덩어리의 방향·비율·단계는 칸 하나의 것이고 칸 하나는 단독 세션 크기다(`dock-tree.mjs cellTree`, `canvas.mjs dockCellOf`, `canvas-ops.mjs dockCell`, 막대 `selbar.js dockState`). 모든 잎이 같은 모양을 지키도록 나무 비율을 다시 정한다. 그래서 H 넷 크게는 7680×1080이고, 비대칭 틀은 틀의 비율이 바뀐다.
- 자세한 것은 `docs/log/p77-dock-cell-size.md` 작업 기록과 보고.

### 할 것

1. **재현.** 사용자의 말 "16:9·4:3을 고르면 모든 세션 크기가 같아진다", "넷 덩어리에서 1 + 3 같은 비대칭 틀을 못 쓴다"를 지금 코드로 재현하고(틀을 고른 뒤 비율을 누르기, 비율을 누른 뒤 틀을 고르기 둘 다) 원인을 적는다.
2. **틀 비율을 지킨다.** 배치 틀(과 Ctrl+끌기로 만든 분할 나무)이 칸 사이 비율을 정한다. 크기 막대(방향·비율·단계)는 그 비율을 바꾸지 않고 덩어리 바깥 크기만 정한다. 비대칭 틀은 비율을 눌러도 비대칭 그대로다.
3. **모양.** 나무 비율을 고정하면 잎마다 모양(너비/높이)은 바깥 모양 W/H에 비례한다(잎 모양 = W/H × k잎). 바깥 모양은 잎 모양이 고른 모양(가로형 16:9 = 16/9, 세로형 16:9 = 9/16, 4:3도 같다)에 가장 가깝게 고른다. 지휘 세션의 안: 잎 넓이를 무게로 log(W/H) = Σ넓이잎 × (log 목표 − log k잎) / Σ넓이잎. 그러면 고른 틀(H, V, 격자)은 모든 칸이 정확히 고른 모양이고, 비대칭 틀은 큰 칸이 먼저 맞는다. 더 나은 길이 있으면 근거를 들어 고른다. 가로형·세로형은 세션 하나의 긴 쪽이다.
4. **크기.** 덩어리 넓이 = 같은 비율·단계 단독 세션 넓이 × √n(n = 덩어리의 세션 수). 예(16:9 크게, 단독 1920×1080): 2 × 2는 바깥 약 2715×1527·칸 약 1358×764, H 넷은 약 5431×764, 둘은 넓이 1.41배, 아홉은 3배. 칸이 너무 작아지거나 커지는 경우(작게에서 아홉, 크게에서 둘 등)를 재어 보고에 적고, 배수를 바꾸는 게 낫다면 근거를 든다.
5. **바깥 테두리.** 전처럼 바깥 크기를 바꾸고 방향·비율·단계 불이 꺼진다. 틀 비율은 그대로.
6. **붙이기·떼기·틀 바꾸기.** 불이 켜져 있으면 위 규칙으로 바깥을 다시 낸다(세션 수가 바뀌면 넓이도 바뀐다). 꺼져 있으면 P73처럼 한다. 덩어리가 커지면 P75의 줄 밀기(`reflowLines`)가 뒤 형제를 민다. 왼쪽 위 자리는 그대로 둔다.
7. **막대.** 불은 지금 덩어리가 위 규칙의 어느 방향·비율·단계와 맞는지로 켠다. "칸마다" 글은 빼고 도움말을 새 규칙으로 고친다(두 사전, 지금 말투).
8. **이미 있는 판.** 뜰 때 덩어리 자리와 크기를 바꾸지 않는다. P73·P77 규칙으로 만든 덩어리는 사람이 막대를 누를 때 새 규칙이 된다.

### 완료 기준

1. 단위 시험을 더하고 통과한다: H 넷·V 넷·2 × 2는 모든 칸이 정확히 고른 모양, 1 + 3과 다른 비대칭 틀은 틀 비율 그대로이고 큰 칸이 고른 모양에 가장 가까움, 넓이 √n, 테두리 뒤 불 꺼짐, 붙이기·떼기·틀 바꾸기, 이미 있는 판 그대로, 단독 세션 크기 그대로. P77 시험의 기대값은 새 규칙으로 고친다.
2. 창 시험(개발용 판, 셸 넷)으로 고치기 전(`v0.1.3-dev.5` 코드)과 고친 뒤를 같은 단계로 찍어 `experiments/p80/`에 둔다: H 넷·2 × 2·1 + 3을 가로형 16:9 크게, 세로형 4:3 보통, 작게로. 1 + 3은 틀을 고른 뒤 비율 누르기와 그 반대 순서 둘 다. 칸 크기 표를 보고에 넣는다.
3. `cd backend && npm test`, `cd app && npm test`, `cd app && npm run build`가 통과한다.

### 시험 환경

- 이 작업은 `dev` 브랜치에서 시작한다. 워크트리를 연 뒤 먼저 `git fetch origin && git merge --ff-only origin/dev`를 한다(워크트리가 `main`에서 시작할 수 있다).
- 너는 사용자의 실제 판 위에서 도는 워커라 셸에 실제 판의 `ATRIUM_*`·`HERDR_*`가 있다. 시험, 개발용 판, herdr, `atrium`은 이 변수를 지운 셸(`backend/.dev/clean-env.sh`, `docs/testing.md`)로 부른다.
- 개발용 판은 너만의 판으로 띄운다(`docs/testing.md`).
  - `ATRIUM_HERDR_SESSION=atrium-dev-p80`, `ATRIUM_PORT=47897`, 창의 원격 디버깅 포트 9377
  - `ATRIUM_DATA_DIR=<워크트리>/backend/.dev/data`, `ATRIUM_APP_USERDATA=<워크트리>/backend/.dev/app`
- 실제 판(`atrium`, 47800)과 다른 판의 포트는 쓰지 않는다. 사용자의 기본 herdr 세션, 실제 판의 herdr 세션(`atrium`), 다른 판의 herdr 서버는 건드리지 않는다. 사용자의 실제 판은 열지도 캡처하지도 않는다. 스크린숏은 창 안만 찍는다(`page.screenshot`).
- 실제 판의 API(47800)와 `atrium` 명령으로 실제 판을 바꾸지 않는다. 시험의 `atrium` CLI는 늘 개발용 판 환경 변수(`ATRIUM_PORT` 등)를 주고 부른다.
- 실제 설치 폴더(`%LOCALAPPDATA%\atrium\versions`)와 실제 데이터 폴더(`%LOCALAPPDATA%\atrium`)는 읽지도 바꾸지도 않는다.
- 대화 목록은 시험 폴더의 대화만 읽는다(`ATRIUM_CLAUDE_PROJECTS`, `ATRIUM_CLAUDE_DESKTOP=none`). 시험 폴더는 `C:\Workspace\mtask-p80-*`처럼 새로 만든다.
- 세션은 `claude --model haiku`와 셸로 띄운다.
- 끝나면 시험 세션, 창, 브라우저, 백엔드, herdr 서버와 세션(`atrium-dev-p80`만), 시험 폴더를 끄고 지운다. 네가 띄운 프로세스가 남지 않았는지 포트로 확인한다.

### 지킬 것

- `CLAUDE.md`를 따른다. 프로세스는 직접 띄운 것만 PID로 끈다. 신뢰 질문은 대신 답하지 않는다.
- 이 저장소는 공개다. 작업 기록, 시험 코드, 커밋 메시지, 그림에 사용자 경로·메일·토큰, 실제 PC·tailnet 이름, IP, 실제 대화 내용을 쓰지 않는다. 커밋 전·푸시 전 검사를 건너뛰지 않는다.
- 화면 글은 영어와 한국어 사전 둘 다 고친다. 한국어 문구는 사전의 지금 말투(`docs/log/korean-copy-review.md`)를 따른다.
- 같은 때 다른 작업자는 없다. 맡은 일에 필요한 만큼만 고치고, `styles.css`와 두 사전은 끝에 더해 합치기 쉽게 한다.
- 자기 브랜치에만 커밋한다. 커밋 메시지에 `Co-Authored-By` 줄을 넣지 않는다. `main`이나 `dev`를 바꾸거나 푸시하지 않는다. `node_modules`는 워크트리 안에서 받는다(`npm ci`, 창은 그 뒤 `node node_modules/electron/install.js`).
- 문서는 이 작업 파일의 작업 기록 절과 보고 절만 고친다. 고쳐야 할 ARCH·BRIEF·testing·README 문장은 보고 절에 짧게 적는다. 살아 있는 문서 예산이 거의 찼으니(70,000자 중 69,998자) 문장은 바꾸는 문장보다 길지 않게 적는다.
- 끝나면 보고 절을 쓰고, 맨 마지막에 `<워크트리>/backend/.dev/p80.done`(브랜치 이름, 마지막 커밋 해시, 시험 수 세 줄)을 만든다.
