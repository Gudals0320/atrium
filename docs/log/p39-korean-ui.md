## 지시

### 목표

사용자의 친구(GitHub `Qualop`)가 Atrium을 macOS로 옮기면서 한국어 화면 글을 새로 번역했다. 그 번역을 우리 창에 가져온다. 사용자의 말은 다음과 같다.
- "macos 자체는 우리의 관심사가 아니다. 우리 개발하는 과정은 windows 에서만 진행한다."
- "이 친구가 한글 번역을 직접 진행하였는데, 이 번역을 가져오고 싶다. macos 관련 내용 말고 텍스트 번역만 가져오자."
- "딱 맞게 있는 부분은 그대로 가져오고, 뭔가 수정이 발생해서 다른 부분은(기능, 위치 등 매칭이 안 되는 부분. 이전 커밋 몇 개 버전을 fork 한 거라 다를 수 있다) 기조에 맞게 너가 번역을 다듬어라."
- "번역 기여자에 Qualop 해당 인원을 기술하자."

### 할 것

1. **키마다 견준다.** 지금 우리 `en.js`·`ko.js`의 키마다 다음 셋을 견준다: 갈라진 때의 영어·한국어, 친구의 한국어, 지금 우리의 영어. 견준 결과로 다음처럼 한다.
   - **그대로:** 갈라진 때와 지금의 영어 뜻이 같고 친구 값이 있으면 친구 값을 그대로 쓴다.
   - **다듬기:** 그 뒤 영어 뜻이 바뀐 키는 친구의 용어와 말투에 맞게 새로 번역한다. 우리가 P29~P38에서 바꾼 기능이 여기에 든다.
   - **새로 번역:** 그 뒤 생긴 키(P29~P38: 덩어리 다리, 호출자, 미션 맵 나무, 데스크톱 앱 가져오기, 워크트리 상자, P36 신뢰 관문 등)는 친구의 용어와 말투로 새로 번역한다.
   - **빼기:** 친구만 가진 키(Gemini, Antigravity, 모델 고르기, 권한 모드·노력 수준 표시 이름 등 우리에게 없는 기능)는 가져오지 않는다.
   - **Windows로 바꾸기:** 친구 값에 macOS 내용(Mac, Command 키, 휴지통, 기본 셸, `/Applications`)이 있으면 지금 우리 영어에 맞게 Windows로 쓴다(PowerShell, Windows 휴지통, Ctrl).
2. **구조는 우리 것.** 파일과 키 구조는 지금 우리 것(`locales/ko.js` 한 파일)을 그대로 두고 값만 바꾼다. 친구의 파일 나누기, `shortcutText`, `en.js` 수정, 코드 수정은 가져오지 않는다.
   - `ko.js` 머리에 한 줄을 둔다: "한국어 번역: Qualop(https://github.com/Qualop/atrium-macos)의 번역을 바탕으로 다듬었다."
   - `en.js`의 영어가 틀렸거나 한국어와 뜻이 어긋나는 곳을 찾으면 고치지 말고 보고에 적는다.
3. **지킬 값.** 자리표시자(`{n}` 등), 복수형(`one`·`other`), 키 집합은 `en.js`와 같아야 한다. 명령 이름, 모델 ID, 경로, `@이름` 같은 코드 글자는 옮기지 않는다.
4. **용어를 하나로.** 화면 전체에서 같은 것은 같은 말로 부른다. 친구 용어표를 따르고, 용어표에 없는 새 기능 이름(호출자, 워크트리 상자, 신뢰 관문 등)은 네가 정해 보고의 용어표에 더한다.
5. **넘침.** 한국어가 길어져 넘치거나 잘리는 곳을 고친다. 고칠 때는 CSS를 최소로 바꾸거나 더 짧은 말을 쓴다. 볼 화면은 다음과 같다.
   - 설정 탭 전부, 새 세션 창, 도구 레일 설명, 아래 칩, 내 차례·검토 목록
   - 영역 이름표, 워크트리 상자, 덩어리 배치 틀, 미션 맵, 데스크톱 앱 가져오기 창, 호출자 탭, 사이드바, 노드 머리줄과 먼 배율 얼굴
6. **시험.** 한국어 문자열을 기대하는 단위 시험(`p16-i18n` 등)과 창 시험을 새 값에 맞게 고친다.

## 작업 기록

- 원본 폴더는 읽기만 했다. 사전 다섯(`ko-core`·`ko-sessions`·`ko-workspace`·`ko-controls`·`en`)을 스크래치 폴더로 복사했고, 갈라진 때의 `ko.js`·`en.js`는 그 저장소에서 `git show 2ce4056:…`으로 글만 꺼냈다. 원본의 코드, 스크립트, `npm`은 돌리지 않았다. 사전 파일도 불러 돌리지 않고, 글자로 읽는 작은 파서(객체 글자만 읽는다)로 값을 뽑았다.
- 친구의 `ko.js`는 넷을 얕게 펼쳐 합친다(`{ ...core, ...sessions, ...workspace, ...controls, thread }`). 같은 맨 위 키가 두 파일에 있지 않아 덮어쓰기는 없었다.
- 견주기(지금 `en.js` 키 1,195개 기준): 갈라진 때와 영어가 같고 친구 값이 있음 1,063, 영어가 바뀜 1(`top.settings`), 그 뒤 생긴 키 131(데스크톱 앱 가져오기, 미션 맵 나무, 판 전체 정리, 호출자, 덩어리 안 연결). 친구만 가진 키 43(Gemini·Antigravity 4, 모델 고르기·고급 인자 12, 권한 모드 표시 7, 노력 수준 표시 6, 가지 펼치기 상한 12, `thread.title`·`settings.tab.branch`). 영어가 바뀐 키가 생각보다 적었다. P36의 신뢰 관문·워크트리 상자는 화면 사전 키를 새로 만들지 않았다(갈라진 때 키를 그대로 쓰거나 백엔드 한국어 글).
- 친구가 `en.js`도 고친 키 12개(셸 → 기본 셸, 휴지통, 모델 고르기 안내 등)는 친구 한국어가 우리 영어와 뜻이 어긋나 우리 영어에 맞춰 다시 썼다.
- 값 바꾸기는 지금 `ko.js`의 글자 자리에 값만 갈아 끼웠다. 키 순서, 절 주석, 줄 구조는 그대로다. 머리 첫 줄에 기여 표기를 두었다. 친구의 복수형 객체 가운데 one·other가 같은 것은 문자열 하나로 줄였다(우리 규칙).
- 처음에 `exit` 절(`normal`, `herdr_stopped`, `trust_declined`, `other`)을 복수형으로 잘못 읽어 키 넷이 빠졌다. `other` 키 하나만 보고 복수형으로 친 탓이라, 모든 키가 복수형 범주일 때만 복수형으로 보게 고쳤다.
- 단위 시험 실패 9개(옛 한국어 기대값)를 새 값으로 고쳤다. 고친 파일: `p16-i18n`, `p21-sleep`, `p33-lib`, `p6c-lib`, `p8-lib`, `renderer-lib`. `p39-ko.test.mjs`를 더했다.
- 창 시험 `app/test/e2e/p39-ko.mjs`(판 도구 `experiments/p39/tools/`)로 화면을 찍고 넘침을 쟀다. 세 번째에 미션 맵 범례의 "명령 입력창"과 사이드바 머리줄의 잘림을 보고 용어를 하나로 맞췄다(아래 용어표). 고친 뒤 `--fresh`로 다시 찍었다.
- 정리: 시험이 셸 다섯을 껐고 창을 닫았다. `mt.cjs herdr stop --yes`, `backend stop`, `herdr session delete atrium-dev-p39` 순서로 껐다. 시험 폴더 `C:\Workspace\mtask-p39-repo`(워크트리 포함)·`mtask-p39-dir`과 `backend/.dev`의 `data`·`app`·`desktop`·`p39-projects`·`p39-claude-sessions`를 지웠다. 시험 대화 기록은 만들지 않았다(셸만 썼고 claude는 띄우지 않았다). 남은 electron 프로세스는 없다.
