상태: 닫힘
날짜: 2026-11-07

## 지시

### 목표

휴대폰에서는 캔버스 보드를 쓰지 않고 세션 목록을 기본 화면으로 한다. 목록에서 미션 맵(누가 누구의 무슨 역할인지, 무엇이 일하는지)을 볼 수 있게 한다.

### 사용자의 말(2026-11-07, `v0.1.4-dev.7`)

"아이폰에서 열어봤는데 닫힘... 우야노? 이거 그냥 안해도 될듯? 그냥 세션 목록만 보여주는 방향도 좋아보인다. 세션 목록만 보여주던 안으로 롤백하는 대신, 미션 맵 보는 기능을 추가하자"

결정이 바뀐다. 지금 BRIEF "원격 보안" 행의 "휴대폰도 보드 화면이 기본이고 탭한 세션을 화면 가득 보며"(2026-11-06, P74·P76)가 "휴대폰은 세션 목록이 기본이고 미션 맵으로 관계를 본다"가 된다. BRIEF와 decisions는 지휘 세션이 닫을 때 고친다.

### 지휘 세션이 알아낸 것(실제 판의 연결 기록, 읽기만 함)

- `dev.7`에서도 iPhone Safari는 보드를 열면 죽었다. P86의 단계 기록은 죽기 직전에 이랬다.
  - `frame`: DOM 483개
  - `fit`: 배율 0.139, 저장한 자리
  - 그 뒤 1.1~1.2초 사이에 `msg session.messages`가 여섯 번 왔다(78KB, 36KB, 43KB, 42KB, 48KB, 95KB).
  - 터미널을 붙이기 전이다. 보드가 노드마다 대화(대화 보기)를 받아 그리다 죽은 것으로 보인다.
- 목록(가벼운 화면)은 버틴다.
- 같은 `boot` 줄(같은 단계, `up 14`)이 부팅마다 되풀이해 올라오고 매번 `light: true`였다. 그래서 "보드로 다시 열기" 뒤에도 가벼운 화면으로 돌아간 것으로 보인다. 한 번 알린 죽음 기록을 지우지 않는 것 같다.

### 할 것

1. **휴대폰은 목록.** 휴대폰 레이아웃(지금 `usePhoneLayout`이 휴대폰으로 보는 화면)은 늘 세션 목록으로 연다. 캔버스 보드와 보드 위 전체 보기(P76)로 가는 길을 휴대폰에서는 없앤다. 코드는 되돌리지 않는다. 태블릿(iPad)·데스크톱 웹과 PC 창은 지금처럼 보드를 쓴다.
   - 목록의 세션 화면(P74: 터미널 하나, 입력 줄, 특수 키 줄, P83의 글자 크기·나가기·높이 보정)은 그대로 쓴다.
   - 목록 머리줄의 "보드" 단추는 "미션 맵"으로 바꾼다.
   - 휴대폰에서는 P84·P86의 가벼운 보드 단계와 "보드로 다시 열기"를 보이지 않는다. 죽음 기록(`boot` 줄)은 남긴다.
2. **휴대폰 미션 맵.** 목록에서 미션 맵 화면을 연다. 자료는 `mission.graph`(이름, 역할, 상태, 부모·하위, 연결)만 쓰고 대화(`session.messages`)와 터미널은 받지 않는다.
   - 세로 휴대폰에 맞는 모양으로 그린다. 예: 워크스페이스 무리(접기)마다 위 → 아래 나무, 부모 아래 들여쓴 하위 세션, 역할 이름표, 연결 선이나 화살표.
   - 일하는 세션은 P85처럼 눈에 띄게, 내 차례는 따로 눈에 띄게, 쉬는 세션은 물러나게 한다. 움직임은 가볍게(정지 화면도 알아보게).
   - 노드를 탭하면 그 세션 화면을 연다. 돌아오면 미션 맵의 자리가 그대로다.
   - 두 손가락 확대가 필요하면 근거를 들어 넣는다. 페이지 자체가 늘어나거나 튕기지 않게 한다(P74).
   - 다크 테마와 지금 휴대폰 화면 말투를 따르고, 두 사전에 넣는다.
3. **죽음 기록 되풀이 고치기.** 한 번 알린 죽음 기록을 지워 다음 부팅이 같은 것을 다시 알리지 않게 한다. 웹 화면 모두에 해당한다. 되풀이가 가벼운 화면 판단을 잘못 이끌었는지 확인해 적는다.
4. **원인 기록.** 위 단계 기록(보드가 노드마다 `session.messages`를 받아 그리다 죽음)을 작업 기록에 적는다. 휴대폰이 아닌 웹 보드에서 대화 보기를 받는 양이 너무 많은지 재어 보고에 적는다. 고치지는 않는다.

### 손대지 말 것

### 원인 기록(실제 판의 단계 기록, 지휘 세션이 읽은 것)

- `dev.7`의 iPhone Safari는 보드를 열면 죽었다. 마지막 단계는 `frame`(DOM 483) → `fit`(배율 0.139, 저장한 자리) → 1.1~1.2초 사이 `msg session.messages` 여섯 번(78, 36, 43, 42, 48, 95KB)이고 터미널을 붙이기 전이다.
- 보드는 중간 얼굴(그리고 L1부터는 가까이 얼굴도)의 세션 노드마다 대화 보기(`ChatView.jsx` `ChatLog`)를 붙이고, 노드마다 `session.messages`(`limit: 60`)를 부른다. 보드가 노드마다 대화를 받아 그리다 죽은 것으로 본다.

### 고친 것

1. **휴대폰은 목록.** `lib/phone.js isPhoneDevice`(손가락 포인터, 짧은 변 430px 이하)·`firstView`. `usePhoneLayout`은 휴대폰이면 늘 목록이고 `mt.phoneLayout` 값(P74·P76의 고름)을 보지 않는다. `main.jsx`는 휴대폰에 보드·목록 단추(`PhoneListButton`)·전체 보기(`PhoneFull`)를 그리지 않는다(코드는 그대로, 태블릿·마우스 보드는 바뀌지 않음).
   - 가로로 돌린 휴대폰도 목록이다. 지금 `usePhoneLayout`은 세로만 휴대폰으로 봐서 가로로 돌리면 보드가 떴고, 같은 이유로 죽는다.
   - 목록 머리줄의 "보드" 단추를 "작업 관계도"(미션 맵) 단추로 바꿨다. 휴대폰 목록에서 가벼운 화면 안내(`LightBanner`)와 "보드로 다시 열기"를 뺐다. 죽음 기록(`boot` 줄)은 그대로다. 휴대폰에는 보드 단계(`html.mt-lite`, `data-level`)도 걸지 않는다.
2. **휴대폰 미션 맵**(`PhoneMission.jsx`, 배치 `lib/phone-mission.js`). `mission.graph`만 받고, 상태는 판의 세션 요약(이미 받은 것)으로 덧입힌다. 판이 바뀌면 0.6초 모아 다시 받는다.
   - 워크스페이스 무리(판 순서, 접기, 머리줄에 일함·응답 필요·세션 수), 무리마다 위 → 아래 나무. 나무 부모는 하위 세션의 부모 > 역할 > 띄움 > 지시이고, 고리면 먼저 띄운 쪽이 뿌리다. 하위 세션은 16px씩 들여 놓고(4단계까지, 더 깊으면 "n단계"), 왼쪽 나무 선(├, └)으로 잇는다. 역할 이름표, 다른 무리의 부모는 "← @부모 (워크스페이스)", 나무에 들지 못한 연결은 "→ @받는 쪽 · 역할".
   - 강조는 P85 등급(`tierOf`, 명령이 도는 셸은 일함): 일함은 초록 테두리·왼쪽 띠·상태 글과 깜빡이는 점(움직임은 이것뿐, 줄임 설정이면 멈춤), 응답 필요는 주황 바탕과 묻는 내용, 오류는 빨강, 쉼은 조금, 잠듦·끝남은 많이 흐리고 점선. 줄 순서는 띄운 순서로 고정해 상태가 바뀌어도 자리를 옮기지 않는다.
   - 줄을 탭하면 세션 화면(P74·P83 그대로). 화면은 `history.state`(`mtMission`, `mtPhone`)에 두어 뒤로 단추와 브라우저 뒤로 가기가 미션 맵으로 돌아온다. 마지막 그래프와 스크롤 자리는 모듈에 두어 돌아오면 그대로 그린다.
   - 두 손가락 확대는 넣지 않았다. 줄은 화면 폭에 맞춰 접히고 글은 목록과 같은 크기라 확대할 것이 없다. 페이지 확대·튕김은 P74 설정(`html.mt-phone-on`)이 그대로 막는다.
   - 미션 맵에서 연 세션 화면의 뒤로 단추는 "목록" 대신 "관계도"라고 적는다(창 시험 뒤에 고침, 단위 시험·빌드만 다시 돌림).
   - 두 사전에 `phoneMission`(한국어 이름은 기존 "작업 관계도"). 다크 테마 토큰만 쓴다(`phone.css` 끝).
3. **죽음 기록은 한 번만**(웹 화면 모두).
   - 되풀이의 원인: `web.boot`는 연결 하나에 한 번(`c.bootNoted`)만 막고, 창은 답을 받아야 `sent`를 세웠다. 휴대폰은 소켓이 자주 끊기므로(P82) 답이 오기 전에 끊기면 새 연결에서 같은 기록을 또 보내고, 백엔드는 새 연결이라 또 남긴다. 그 페이지가 만든 보고라 단계·`up`·`light`까지 같은 줄이 된다. 한 번 알린 기록을 기기에서 지우는 표시도 없었다.
   - 고침: 보고에 id(죽은 페이지의 부팅 시각, `reportId`)를 붙인다. 백엔드는 같은 `bootId`가 연결 기록에 있으면 남기지 않고 `{ dup: true }`로 답한다(기록 파일을 다시 읽어도 같다). 창은 답을 받으면 기기에 `sent`로 적고, 다음 연결과 다음 부팅은 그 기록을 다시 보내지도, 죽음으로 세지도 않는다. 같은 죽음 시각을 `crashes`에 두 번 넣지 않는다.
   - 가벼운 화면 판단을 잘못 이끌었나: 아니다. 판단은 기기의 `crashes`·`light`·`retryBoot`만 읽고, 다시 보낸 보고는 이것을 바꾸지 않는다. 연결 기록의 `light: true` 줄들은 한 페이지가 같은 보고를 다시 보낸 것이라 "다시 연 뒤에도 가벼운 화면"의 근거가 아니다. "보드로 다시 열기" 뒤 가벼운 화면은 다시 연 보드가 실제로 또 죽었을 때 정한 대로 돌아간 것이다(P84 `retryBoot`). 다만 새 부팅 기록이 저장되지 못해 같은 기록이 두 번 읽히면 같은 시각이 두 번 세어져 가벼운 화면이 될 수 있었고, 위 고침으로 막았다.

## 보고

### 한 것

1. 휴대폰(손가락, 짧은 변 430px 이하, 세로·가로 모두)은 늘 세션 목록으로 연다. 캔버스 보드, 보드 위 전체 보기, 목록 단추, 가벼운 화면 안내와 "보드로 다시 열기", 보드 단계는 휴대폰에 보이지 않는다. 태블릿·데스크톱 웹·PC 창은 그대로 보드다. 목록의 세션 화면(P74·P83)은 그대로다.
2. 목록 머리줄의 단추로 작업 관계도(미션 맵)를 연다. `mission.graph`만 받아 워크스페이스 무리마다 위 → 아래 나무로 그린다. 하위 세션 들여쓰기, 역할 이름표, 다른 무리 부모, 나무 밖 연결, P85 강조(일함·응답 필요·쉼). 줄을 탭하면 세션 화면, 돌아오면 같은 자리다. 대화와 터미널은 받지 않는다(창 시험으로 확인).
3. 죽음 기록은 id를 붙여 한 번만 남긴다. 되풀이는 답을 받기 전에 끊긴 연결이 같은 보고를 다시 보낸 것이고, 가벼운 화면 판단을 바꾸지 않았다.
4. 원인(보드가 노드마다 `session.messages`를 받아 그림)과 데스크톱 웹 보드의 양을 작업 기록에 적었다. 고치지는 않았다.

### 사람이 iPhone으로 볼 순서

1. PC를 이 빌드로 올리고 iPhone Safari(또는 홈 화면 앱)로 연다. 세션 목록이 열리고 보드로 가는 단추가 없는지 본다. 가로로 돌려도 목록이다.
2. 머리줄 오른쪽의 나무 모양 단추를 눌러 작업 관계도를 연다. 위쪽에 "작업 중 n · 응답 필요 n · 세션 n", 워크스페이스마다 부모 아래 들여 놓인 하위 세션과 역할 이름표가 보이는지 본다. 일하는 세션은 초록 테두리, 응답 필요는 주황 바탕이다.
3. 세션 하나를 눌러 세션 화면을 쓰고, "목록" 단추나 가장자리 밀기로 돌아온다. 작업 관계도의 같은 자리로 돌아오는지 본다. 한 번 더 뒤로 가면 목록이다.
4. 몇 분 써 보고 닫히지 않는지 본다. 닫혔으면 PC에서 `atrium remote log --limit 20`의 "화면이 닫힌 뒤 다시 열림" 줄이 죽을 때마다 하나씩만 생기는지, 그 줄의 화면(`list`·`session`)을 보내 준다.
