날짜: 2026-11-02

## 지시

### 목표

쉬는 세션을 잠재워 메모리를 아낀다.

사용자는 실제 판의 Memory 알약이 4.1GB인 까닭을 물었다. 지휘 세션이 2026-11-01에 읽기만 해서 잰 값은 다음과 같다.
- 판의 claude 세션 9개가 모두 쉬는 중(ready)인데도 세션마다 440~490MB를 쓴다.
- 세션 하나의 프로세스: `claude.exe` 약 310MB, 패널 셸 `powershell.exe` 87MB, aside MCP `aside.exe` 85MB와 `conhost.exe` 7MB.

사용자는 그 자리에서 제안한 "잠재우기"를 골랐다.

### 정한 것

- **잠재우기.**
  - 판이 띄운 Claude Code 세션(종류 `claude`, 판의 hook이 붙은 것, 대화 ID를 앎)을 잠재운다.
  - claude를 끝내고 그 herdr 패널(작업 공간)까지 닫는다. 셸과 MCP 서버 메모리도 돌려받는다.
  - 세션은 닫힘(J2)이 아니라 판에 남는 새 상태 "잠듦"(`sleeping`)이다. 노드, 자리, 덩어리, 그룹, 연결, 부모·자식 관계, 메모, 이름은 그대로다.
  - 셸, 다른 종류(codex 등), 판에 올린 에이전트는 잠재우지 않는다.
- **깨우기.**
  - 같은 대화 ID로 새 패널을 만들어 판의 인자로 이어 간다(J1의 `recreate_resume`와 같은 길). 갈라 열기는 하지 않는다.
  - 깨우는 때:
    - 노드를 눌러 들어갈 때
    - 명령 바·`@이름`·루프·Thread 답장으로 글을 보낼 때. 전달은 깨어 준비된 뒤에 보낸다.
    - 다른 에이전트가 `atrium child` 등 판 명령으로 그 세션을 찾을 때
    - 노드의 "깨우기"를 누를 때
  - 깨는 동안은 "깨우는 중"을 보인다. 실패하면 까닭을 남기고 잠듦으로 둔다.
- **언제 잠재우나.**
  - 설정 `sleepAfterMin`(기본 30, 0이면 저절로 잠재우지 않음, 판 설정 화면의 새 세션 기본값 옆): 이 시간 동안 쉬는 중(ready)인 세션.
  - 잠재우지 않는 세션: 일하는 중, 내 차례(묻는 중, 신뢰 대기), 전달 대기, 지금 보고 있는 노드(초점이 있거나 화면에 가까이 얼굴로 보이는 것), 돌아가는 루프의 대상, 일하는 중인 하위 세션이 있는 부모, 일하는 부모의 하위 세션.
  - 손으로도 잠재운다.
    - 노드 메뉴의 "잠재우기"
    - 트레이 메뉴의 "쉬는 세션 모두 잠재우기"
    - 아래 칩이나 위 메모리 알약 목록의 같은 동작(어디에 둘지는 화면을 보고 정해 보고에 적는다)
- **보이기.**
  - 잠든 노드는 터미널 대신 요약 얼굴이다: 흐리게, 달 같은 표시, 이름, 마지막 요청과 답 앞부분, 잠든 시각, "깨우기".
  - 상태 알약은 "잠듦"이다. 크기와 자리는 그대로라 깨면 같은 자리에서 터미널이 된다. 멀리·아이콘 얼굴에서도 잠든 것을 구분한다.
  - 메모리 알약 풀이에 잠든 세션 수와 아낀 메모리(잠들기 전 잰 값)를 더한다.
  - 내 차례 목록과 알림에는 잠든 세션이 나오지 않는다.
- **복구와의 관계.**
  - herdr나 백엔드를 다시 켤 때(J1) 잠든 세션은 되살리지 않고 잠듦으로 둔다.
  - 잠든 세션의 패널이 없는 것을 "패널이 사라짐"으로 보고 닫지 않는다. 보관·삭제(P15)는 잠든 세션에도 된다.
- **화면 글은 영어와 한국어 사전(`locales/`)에 둔다**(P16). 생김새는 지금 토큰을 쓴다(강조 초록, 주의 주황).

## 작업 기록

- 2026-11-02 상태 `sleeping`은 runtime의 `rt.sleep`으로 둔다(표 열을 더하지 않음). `deriveState`가 맨 먼저 보고, 잠든 세션은 `paneId`·`herdrWorkspaceId`를 비운다. 그래서 resync(J1), 자원 감시, 셸·폴더 확인, 구독은 따로 고치지 않아도 잠든 세션을 건너뛴다.
- 잠재우기 순서: 메모리 재기(D1과 같은 셈) → 조건 다시 보기 → `rt.sleep` 먼저 세움(전달은 기다리고, 끝나는 동안 exited로 깜빡이지 않게) → `/exit` → 작업 공간(같은 작업 공간에 다른 패널이 있으면 그 패널) 닫기 → 프로세스가 끝났는지 PID로 확인. `killing`에 넣어 `pane_closed`·`workspace_closed`를 판 밖 닫힘으로 보지 않는다.
- 깨우기는 J1 `recreate_resume`과 같은 길(새 작업 공간, 같은 herdr 이름, `--resume <대화 ID>` + 판의 인자, `registerResume`)이다. 대화 ID는 hook의 `session_id`(없으면 세션 ID). 이어 가자마자 끝나거나 90초 안에 준비되지 않으면 패널을 닫고 까닭(`rt.sleep.error`)과 함께 잠듦으로 되돌리며, 그 세션에 보낼 글은 취소한다.
- 깨우는 때: 노드 누르기(`navigateTo`의 터미널 초점), 잠든 얼굴·메뉴의 깨우기, 전달(대기열이 `sleeping`으로 기다리면 백엔드가 깨움. 명령 바, `@이름`, 루프, Thread 답장, 연결 알림 모두 이 길), 다른 에이전트의 herdr 호출(PreToolUse hook에서 대상이 잠들었으면 깨움. 그 호출은 실패하므로 판 안내에 `atrium wake <이름>` 한 줄을 더함), `atrium wake <이름>`과 잠든 자기 하위 세션 이름으로 `atrium child`.
- 보는 노드: 터미널이 붙은 노드(제어기)와 창이 알린 초점 노드(`board.viewing`, 창에 초점이 있고 가려지지 않을 때만). 창 연결이 끊기면 지운다.
- 정한 세부: 손으로 노드 하나를 잠재울 때는 보는 노드와 오류로 끝난 턴도 잠재운다(메뉴를 누르면 늘 보고 있으므로). 쉬는 세션 모두(트레이, 메모리 알약)는 저절로와 같은 조건이되 쉰 시간은 보지 않는다. 안 본 답은 잠들어도 검토 대기로 남긴다. "쉬기 시작한 때"는 마지막 활동, 턴 끝, 손댄 때, 깬 때 가운데 늦은 것.
- 손 잠재우기 자리: 노드 ⋯ 메뉴, 트레이 메뉴, 위 메모리 알약을 누르면 펼치는 목록(세션별 메모리, 잠든 세션과 아낀 메모리, "쉬는 세션 모두 잠재우기"). 아래 칩 줄은 이미 여섯 개라 넣지 않았다.
- 기존 시험 고침: P8 단위 시험 두 곳(판 안내 줄 수 5→6, 하위 세션 명령 도움말에 wake). 옛 창 시험 판 고르기에 `p21`을 더함(`p10-lib.mjs`, `p11-board.mjs`, `p12-quick`·`p15-close`의 `MT_E2E_OUT`).
- 창 시험 1·2회차에 누군가 시험 창을 손으로 만졌다(15:27 s2 끌기·크기, 15:30 s3 권한 허용, 15:30 정리). 정리가 노드 자리를 한 줄로 되돌려 이웃 노드가 터미널로 붙어 있었고, 그래서 s1이 "보는 노드"로 남았다. 3회차부터는 손대지 않은 판에서 돌았다.
- 3회차에서 찾아 고친 것: 잠든 직후 메모리 알약 목록에 30초 전 표본(깨어 있던 메모리)이 남음 → 잠든 세션은 목록의 잠든 줄로만 보이고, 잠재운 뒤 표본을 바로 다시 잰다. 중간 얼굴의 잠든 요약 글이 너무 작음 → 모든 얼굴에서 화면 기준 글자 크기, 깨우기 단추는 가까이 얼굴에서만.
- 4회차에서 찾아 고친 것: 글 보내 깨울 때 herdr가 idle을 알린 직후 보낸 글이 제출되지 않고 입력 칸에 남았고, 다음 잠재우기의 `/exit`가 그 뒤에 붙어 한 지시로 제출됐다(대화 기록에서 확인). 깨운 뒤 준비가 되어도 2.5초(`WAKE_SETTLE_MS`) 더 "깨우는 중"으로 두고 그동안 전달은 `starting`으로 기다린다. P19의 "첫 지시가 제출되지 않음"과 같은 틈으로 보인다.
- 5회차는 시험 스크립트의 기다림 조건(앞 답에도 있는 글을 봄) 때문에 멈췄다. 고친 뒤 6·7회차 22/22.

- 2026-11-02 지휘 세션: 판 터미널에 쳐 두고 보내지 않은 글(초안)이 있으면 잠재우지 않게 고쳤다. 잠재우기의 `/exit`와 Enter가 초안 뒤에 붙어 제출되기 때문이다. 키 입력(`relay.mjs`가 글을 넘김)과 제출되지 않은 전달(`unconfirmed`)로 초안을 기억하고, 제출 hook·Enter·Ctrl+C·Ctrl+U로 비운다(`draftAfterInput`, 이유 `draft`). 개발용 판에서 haiku 하나로 확인했다: 초안이 있으면 손으로도·모두 잠재우기로도 거부, Ctrl+C로 지우면 잠재움, 초안은 대화 기록에 없음(4/4). 판 밖에서 herdr 화면으로 친 글과, 백엔드를 다시 켠 뒤의 초안은 모른다.

### 남은 것과 알릴 것

- ARCH는 5절 모듈 행만 더했다. 코드 주석은 기능 번호 D4로 적었으니, 합칠 때 4절 D에 D4 행을 두면 맞는다(예산 때문에 넣지 않음). BRIEF "정한 것", README 변경 이력, PLAN은 지휘 세션 몫이다.
- 실제 판에 합치면 기본 30분이 바로 켜진다. 창을 닫아 두면 보는 노드가 없으므로 30분 쉰 판 claude는 모두 잠든다.
- 다른 에이전트가 `herdr agent prompt <잠든 이름>`을 부르면 그 호출은 실패하고(herdr에 없음) 판은 그 hook을 보고 깨운다. 에이전트가 다시 부르거나 안내대로 `atrium wake`를 먼저 해야 한다.
- 깨울 때 역할로 이은 상대에게 새 패널 알림(F2)을 보내지 않는다. herdr 이름이 그대로이고, 알림이 잠든 상대까지 깨우는 것을 피했다.
- Claude Code 안에서 `/clear`해 대화 ID가 바뀐 세션은 hook의 대화 ID로 깨우지만, herdr에 등록하는 이어 가기 명령(`resume_argv`)은 지금처럼 세션 ID 그대로다(기존 J1과 같은 한계).
- 잠재우기의 `/exit`는 입력 칸에 사람이 치다 만 글이 있으면 그 뒤에 붙는다(D2 끄기와 같은 방식). 손으로 잠재울 때만 보는 노드도 잠재우므로 그때 드러날 수 있다.
- 창 시험 중 누군가 시험 창을 만져(끌기, 권한 허용, 정리) 1·2회차가 깨졌다. 개발용 판 창을 띄워 둔 동안에는 손대지 않아야 시험이 맞는다.
- 정리: 시험 세션, 창(트레이 끔), 백엔드, herdr 서버와 세션 `atrium-dev-p21`, 시험 폴더 `C:\Workspace\mtask-p21-ws`, 시험 대화 기록 폴더를 지웠다. 삭제 시험이 휴지통으로 보낸 시험 대화 기록 몇 개는 휴지통에 남았고, `~/.claude.json`에 Claude Code가 남긴 시험 폴더 항목은 고치지 않았다. `backend/.dev/data`(시험 판 기록)는 남겼다.
