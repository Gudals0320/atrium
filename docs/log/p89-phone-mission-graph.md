- `mission.graph`만 받아 워크스페이스 무리마다 위 → 아래 나무를 줄로 그린다. 하위 세션은 들여쓰고, 역할 이름표, 나무 밖 연결, P85 강조 등급을 쓴다. 줄을 탭하면 세션 화면을 열고, 돌아오면 같은 자리다. 대화와 터미널은 받지 않는다.

### 할 것

1. **그래프 모양.** 세션은 노드 카드로, 관계는 선으로 그린다.
   - 노드 카드: 둥근 카드에 상태 점, 이름, 역할 칩, 종류 아이콘(claude·codex 등), 워크트리면 브랜치 표시
   - 선: 부모 → 하위 세션은 부드러운 곡선(화살표나 끝점)
   - 나무 밖 연결(역할 선, 알아챈 지시)은 다른 모양(점선 등)으로 구분하고, 범례를 작게 둔다
   - 무리: 워크스페이스 무리는 배경 영역이나 머리띠로 묶는다
   - 배치: 세로 화면에 맞게 위 → 아래로 내려가는 나무가 기본이다. 형제가 많아 넓어지면 줄바꿈이나 접기 등으로 화면 폭 안에 들게 한다
   - 생김새: 판의 다크 테마와 토큰(`lib/tokens.js`), 휴대폰 화면 말투에 맞춘다
2. **강조.** 일하는 세션은 P85처럼 초록 테두리와 빛으로 튀고, 응답 필요는 주황으로 따로 눈에 띄고, 쉬는·잠든·끝난 세션은 물러난다. 위쪽의 "작업 중 n · 응답 필요 n · 세션 n" 요약은 남긴다. 탭하면 그 등급만 강조하는 거르기를 둘지 근거를 들어 정한다.
3. **움직이기.** 그래프 안에서 한 손가락으로 옮기고 두 손가락으로 확대·축소한다(페이지 자체는 늘어나거나 튕기지 않게, P74). 처음에는 화면에 맞추고, "맞추기" 단추를 둔다. 노드를 탭하면 세션 화면을 열고, 돌아오면 같은 자리·배율이다. 가로 화면에서도 쓸 만해야 한다.
4. **가볍게.** iPhone Safari는 판 캔버스에서 페이지가 죽었다(P84·P86·P87). 같은 일이 생기지 않게 한다.
   - 자료는 지금처럼 `mission.graph`만 쓴다(대화·터미널 없음)
   - SVG나 DOM 크기를 적당히 두고, 큰 `filter`·`backdrop-filter`·`will-change`·끝없는 움직임을 피한다. 빛은 테두리·그림자 정도로, 움직임은 움직임 줄이기 설정을 따른다
   - 세션 50개 안팎에서도 부드러워야 한다

### 설계

- 자료는 그대로 `mission.graph`와 이미 받은 세션 요약뿐이다. 나무와 등급은 `lib/phone-mission.js`(P87)를 그대로 쓰고, 줄에 다른 무리 부모 id(`fromId`)와 연결 받는 쪽 id(`toId`)만 더했다.
- 놓기는 새 `lib/phone-graph.js`(순수 함수). 카드는 모두 150×64라 겹침 셈이 쉽다. 세로 393px에서 카드 둘이 배율 1로 들게 여백을 줄였다(무리 상자 안 2열, 폭 352).
  - 열 수는 그래프 칸 폭으로 고른다(`colsFor`: 세로 2, 가로 4). 부모 아래 하위 블록이 폭 안에 들면 나란히(row), 아니면 모두 잎일 때 두 줄 격자와 가운데 등뼈(bus), 그 밖에는 한 칸 들여 세로로 쌓고 왼쪽 등뼈(col). 무리 안의 뿌리 블록은 폭 안에서 줄을 바꾼다.
  - 나무 선은 부모 아래 가운데 → 하위 위 가운데의 3차 곡선(row) 또는 둥근 꺾임(bus·col). 나무 밖 연결과 다른 무리 부모는 점선 곡선과 끝점(같은 높이면 위로, 아니면 오른쪽으로 휜다), 역할 이름을 선 가운데에 단다.
  - 깊이 우선 줄 순서(띄운 순서)로 자리를 정하므로 상태가 바뀌어도 카드가 움직이지 않는다.
- 보기: 그래프 전체가 한 `div`(`.mt-pm-world`) 안의 DOM 카드와 SVG 한 장이고, 옮기기·확대는 그 `div`의 `transform` 하나만 바꾼다(React를 다시 그리지 않는다). 맞추기는 폭과 높이에 맞추되 글이 너무 작아지면 배율 0.6에서 멈추고 위에 붙인다. 배율 범위는 [min(0.25, 맞춘 배율), 2.5], 그래프는 늘 72px 이상 화면에 남는다. 손가락 셈은 P76의 `lib/touch-board.js`(`pinchViewport`·`panViewport`)를 쓴다.
- 돌아오기: 마지막 보기를 화면 크기 키와 함께 모듈에 둔다. 같은 크기로 돌아오면 그 보기, 돌리면(크기가 바뀌면) 다시 맞춘다.
- 요약 칩 거르기는 넣었다. 근거: 세션이 30개를 넘으면 맞춘 배율에서 일하는 카드 두셋을 찾기 어렵다. 칩을 누르면 그 등급 카드만 또렷하게 하고 그 카드들로 맞춘다(클래스와 보기만 바뀌고 다시 받거나 다시 놓지 않는다). 다시 누르면 흐림만 푼다.
- 가볍게: `filter`·`backdrop-filter`·`will-change` 없음. 일함·응답 필요의 빛은 `box-shadow` 두 겹, 상태 점의 깜빡임도 관계도 안에서는 껐다(끝없는 움직임 없음). 종류 아이콘은 같은 그림 몇 장(`<img>` 16px).
- 셸은 하위 세션이 될 수 없다(`atrium child --kind shell`은 거절). 시험 판의 셸 워커는 역할 선으로 이었다(역할 선도 나무 부모). 끝낸 셸은 판에서 빠지므로 잠듦·끝남은 큰 판 흉내에서 본다.


### 시험

- 그림 고치기: 첫 그림에서 카드 셋째 줄(묻는 글, 다른 무리 부모)이 잘렸고, 다른 무리로 가는 점선이 카드 사이를 가로질렀다. 카드 높이를 64 → 74로, 점선은 무리 상자 오른쪽 통로(세 갈래)로 돌리고 이름표를 받는 쪽 끝 가까이 세로로 달았다.
- 시험 판(atrium-dev-p89, 47897): 워크스페이스 3개, haiku 4개(lead → rev → help, lead → port는 다른 워크스페이스), 셸 6개(run은 ping 도는 중, qa·docs·lint는 역할 선으로 lead·rev 아래, sh-b는 rev의 notes 선으로 다른 워크스페이스, sh-c), lead → help 나무 밖 역할 선. lead는 권한 질문(응답 필요), rev는 ping(일함).
- 큰 판: 메모리(PC 여유 6GB)를 아끼려고 세션을 더 띄우지 않고 페이지 안에서 `mission.graph` 답에 흉내 세션 26개를 더했다(36개, 리드 하나에 하위 8, 손자 6, 셸, 역할 선, 잠듦·끝남). 그리기·옮기기·메모리만 본다.
- 손가락: Chromium은 CDP `Input.dispatchTouchEvent`(진짜 터치 두 손가락), WebKit은 여러 손가락을 보낼 길이 없어 그래프 칸에 touch 이벤트를 만들어 보냈다. 탭은 둘 다 Playwright `tap`.
- 결과(`experiments/p89/`): WebKit 26/26, Chromium 26/26. 고치기 전 그림 `*-before-*`(세로·가로·큰 판), 뒤 그림 `*-01`~`08`.

  - 한 손가락 옮기기(손가락만큼), 두 손가락 두 배 확대(가운데 점 고정), 2.5·0.25에서 멈춤, 멀리 밀어도 그래프가 화면에 남음, 맞추기 = 처음 보기, 카드 위에서 시작한 옮기기는 열지 않음
  - 응답 필요 칩 → lead만 또렷하고 가운데로(배율 1.2), 다시 누르면 모두 또렷

## 보고

### 한 것

1. 휴대폰 작업 관계도를 노드와 선으로 된 그래프로 다시 그렸다(`PhoneMission.jsx`, 새 `lib/phone-graph.js`, `phone.css`). 카드에는 상태 점, 이름, 종류 아이콘, 역할 칩, 상태, 셋째 줄(묻는 글, 다른 무리 부모, 워크트리 브랜치)이 있다. 하위 세션은 부모 아래에서 내려오는 곡선, 나무 밖 연결과 다른 무리 부모는 무리 상자 오른쪽 통로로 도는 점선과 끝점이다. 작은 범례(하위 세션·그 밖의 연결)를 둔다.
2. 무리(워크스페이스)는 머리띠가 있는 배경 상자이고 위에서 아래로 쌓인다. 머리띠를 누르면 접는다(P87 그대로). 나무는 위 → 아래이고, 형제가 많으면 두 줄 격자(잎만) 또는 한 칸 들여 세로로 쌓아 세로 화면 폭에 든다. 가로 화면은 한 줄에 카드 넷까지 나란히 놓는다.
3. 강조는 P85 등급을 따른다. 일함은 초록 테두리와 빛, 응답 필요는 주황 바탕과 빛, 오류는 빨강이고, 잠듦·끝남은 흐린 점선 카드로 물러난다. 하위 곡선도 받는 쪽 등급의 색이다. 위쪽 요약은 남겼고, "작업 중"·"응답 필요" 칩을 누르면 그 등급만 또렷하게 하고 그 카드들로 맞춘다(근거는 작업 기록).
4. 한 손가락으로 옮기고 두 손가락으로 확대·축소한다(0.25~2.5). 처음과 "맞추기" 단추는 화면에 맞춘다. 카드를 누르면 세션 화면이 열리고, 돌아오면 같은 자리·배율이다. 페이지는 늘어나거나 튀지 않는다.
5. 가볍게 그린다. 자료는 `mission.graph`만이고, 그래프는 DOM 카드와 SVG 한 장이며, 옮기기는 `transform` 하나만 바꾼다. 큰 `filter`·`backdrop-filter`·`will-change`·끝없는 움직임이 없다. 큰 판(36개)에서 WebKit 메모리가 늘지 않았다.

### 사람이 iPhone으로 볼 순서

1. PC를 이 빌드로 올리고 iPhone Safari(또는 홈 화면 앱)로 연다. 세션 목록 머리줄의 관계도 단추를 누른다.
2. 무리 상자 안에 카드가 위 → 아래로 놓이고, 부모와 하위가 곡선으로 이어지며, 다른 워크스페이스로 간 하위·역할 선이 오른쪽 점선으로 이어지는지 본다. 일하는 카드는 초록 빛, 응답 필요는 주황이다.
3. 한 손가락으로 끌고 두 손가락으로 벌리고 오므린다. 페이지 전체가 커지거나 튀지 않는지, 오른쪽 아래 "맞추기"가 처음 모습으로 돌아가는지 본다.
4. 위쪽 "응답 필요" 칩을 누른다. 그 세션만 또렷하게 가운데로 오는지 보고, 다시 눌러 푼다.
5. 카드를 눌러 세션 화면을 쓰고 뒤로 온다. 같은 자리·배율인지 본다. 가로로 돌려 다시 맞추는지 본다.
6. 몇 분 써 보고 닫히지 않는지 본다. 닫히면 PC에서 `atrium remote log --limit 20`의 "화면이 닫힌 뒤 다시 열림" 줄을 보내 준다.
