## 지시

사용자 피드백(P11 뒤 첫 피드백). 지휘 세션이 직접 고친다.

- 에이전트를 고를 때의 기본 인자를 설정해 둔다.
- 왼쪽 레일의 에이전트 단추를 누르면 대화상자 없이 바로 새 CLI가 열리고 그 창으로 들어간다.
- 모델은 띄울 때 고르지 않고 세션 안에서 바꾼다.

완료 기준: 레일의 Claude, 셸 단추가 지금 워크스페이스에 설정의 기본값으로 바로 뜨고 그 터미널로 들어가는지 개발용 판의 창 시험으로 본다. 단위 시험(백엔드, 창)과 빌드가 통과한다.

## 작업 기록

- 새 세션 대화상자는 레일, 칩 "새 세션", 영역·그룹의 "+ 세션"에서 모두 열렸다. 모델 기본값은 개발용 판만 `haiku`(Electron main의 `defaultModel`)였다.
- 백엔드 설정(`settings.mjs`)에 글(`string`)과 고르기(`choice`) 값을 더하고 새 세션 기본값 다섯을 넣었다. `session.spawn`은 받지 않은 값만 이 기본값으로 채운다. 대화상자, `mtask spawn`, 묶음 실행, `mtask child`가 넘긴 값은 그대로다. `mtask spawn`은 `--allow-herdr`가 없으면 값을 넘기지 않도록 바꿨다(전에는 늘 거짓을 넘겨 기본값이 먹지 않았다).
- 창: `quickSpawn`(SpawnDialog.jsx)이 지금 워크스페이스의 폴더로 띄우고, 노드가 올라오면 `goWhenOpen`(사이드바에서 store로 옮김)으로 그 터미널에 들어간다. 지금 워크스페이스가 없으면 대화상자를 연다. 레일 단추의 Shift+누르기와 칩 "새 세션…"은 대화상자이고, 대화상자의 처음 값도 설정의 기본값이다. 설정 화면에 "새 세션 기본값" 절을 더했다.
- 개발용 판 `multitask-dev-p12`(포트 47826, `backend/.dev/p12`)에서 `app/test/e2e/p12-quick.mjs`를 돌렸다. 시험 폴더는 새로 만든 `C:\Workspace\mtask-p12-ws\demo`, 대화 목록은 그 폴더의 대화만 읽었다. 끝난 뒤 세션, 백엔드, herdr 서버와 세션, 시험 폴더, 판 데이터를 지웠다. 첫 지시를 보내지 않아 대화 기록 파일은 생기지 않았다.

## 보고

- 왼쪽 레일의 Claude, Codex, 셸을 누르면 지금 워크스페이스에 바로 뜨고 그 노드의 터미널에 초점이 간다. Shift+누르기는 대화상자다. 칩은 "새 세션…"(대화상자)이 되었다.
- 새 세션 기본값(설정 화면, `mtask settings set`): Claude Code 모델(비우면 Claude Code 기본), 노력 수준(비우면 기본, low~max), 권한 모드(기본 `manual`), herdr 명령 자동 승인(기본 꺼짐), Codex 실행 인자(빈칸으로 나눔). 모델은 세션 안에서 `/model`로 바꾼다.
- 시험(`experiments/p12/p12-quick.json`, 스크린숏 넷): 7/7 통과. Claude 단추가 대화상자 없이 뜸, 새 노드의 터미널에 초점, 띄운 인자가 `--permission-mode acceptEdits --model haiku --effort low`(시험에서 설정한 값), 셸 단추도 같음, Shift+누르기 대화상자의 처음 값, 설정 화면의 값 보이기와 Codex 인자 바꾸기. 단위 시험은 백엔드 157(새 시험 3), 창 34, 빌드 통과.
- 계획과 다른 곳: 영역 이름표와 그룹 머리줄의 "+ 세션"은 그대로 대화상자다(그 폴더와 그룹을 미리 채워 연다).
- 알려진 문제: Codex 단추는 시험하지 않았다(새 폴더에서 Codex의 신뢰 확인을 판이 대신 누르지 않는다). 판 밖 대화를 판으로 열기와 닫힌 세션 다시 열기(J4)는 기본값을 쓰지 않고 전처럼 원래 값이나 `manual`이다. 설정 화면의 체크 상자는 한 줄 가운데에 따로 놓인다(P11부터 있던 모양).
