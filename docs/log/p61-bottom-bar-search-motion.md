## 지시

### 목표

아래 명령 바가 더 쉽게 나오고 부드럽게 올라오게 하고, ↑로 여는 찾기 창을 다시 그린다. 사용자의 말: "하단 바에 마우스 올릴 때 명령 입력줄 뜨는게 너무 범위가 좁아 좀 근처가면 알아서 나오게 해주고 명령줄 나올때 하단에서 올라오는 애니메이션 만들어줘", "방향키 위 누르면 나오는 찾기 대화창 UI가 못생겼는데 개선좀 해주고 이것도 위에서 내려오게 해줘 가볍게. 그리고 크기 좀만 더 키워".

P43이 만든 동작(평소 숨김, 초점이나 쓰다 만 글이 있으면 숨지 않음, 판 화살표 키, 찾기는 바깥을 누르면 닫힘)은 그대로 둔다.

### 할 것

1. **명령 바가 나오는 범위.** 지금은 아래 가장자리의 좁은 띠(`app/src/renderer/lib/bottom.js`의 `inBand`, `BAND_PX`·`BAND_SIDE_PX`)에 마우스가 들어와야 나온다.
   - 아래쪽에 가까이 가기만 해도 나오게 넓힌다. 높이는 명령 바와 칩 줄 높이에 여유를 더한 정도, 가로는 명령 바 폭보다 넉넉히 잡는다. 값은 써 보고 정해 작업 기록에 적는다.
   - 나온 뒤에는 더 넓은 범위를 벗어나야 숨긴다(들어가는 선과 나가는 선을 달리 둠). 숨기기는 약간 늦춰 깜빡이지 않게 한다.
   - 노드 터미널 위에서 아래로 스크롤하거나 글을 고를 때 방해되지 않는지 본다. 노드가 아래쪽에 있을 때도 써 본다.
2. **올라오는 움직임.** 명령 바와 칩 줄이 나올 때 아래에서 살짝 올라오며(위치와 투명도) 나타나고, 숨을 때는 반대로 내려간다. ↓ 키나 초점으로 나올 때도 같다.
3. **찾기 창 다시 그리기(↑).**
   - 조금 더 크게 한다: 폭과 입력칸 높이와 글자를 키운다.
   - 입력칸 앞에 찾기 아이콘을 둔다. 자리 표시 글은 짧게 한다(예: "세션, 대화, 메모 찾기"). 지금의 긴 글에 든 찾는 범위와 키 안내는 따로 보인다. 키 안내는 작은 키 모양(↑↓ 고르기, Enter 이동, Esc 닫기)으로 창 아래나 오른쪽에 둔다.
   - 결과는 종류별 표시(세션, 대화, 메모, 칸반 등), 고른 줄 강조, 맞는 글자 강조, 빈 결과 안내를 다듬는다.
   - 위에서 가볍게 내려오며(위치와 투명도) 나타나고, 닫힐 때는 반대로 움직인다.
4. Electron 창과 웹 화면 둘 다에서 같다.

### 완료 기준

1. 단위 시험을 더하고 통과한다: 넓힌 범위와 들어가는·나가는 선(`inBand`류 순수 함수), 숨김 늦추기.
2. 창 시험(개발용 판, Electron)으로 확인하고 결과를 `experiments/p61/`에 둔다.
   - 아래쪽 가까이에 마우스를 두면 명령 바가 나오고, 멀어지면 늦게 숨는다.
   - 쓰다 만 글과 초점이 있으면 숨지 않는다.
   - 올라오는 움직임과 찾기 창의 내려오는 움직임이 있다. 중간 프레임 스크린숏이나 계산된 transform으로 보인다.
   - `prefers-reduced-motion`이면 움직임이 없다.
   - 찾기 창 전후 스크린숏(두 화면 크기, 결과가 있을 때와 없을 때)을 남기고, ↑·↓·Enter·Esc와 바깥 누르기가 그대로 된다.
3. `cd backend && npm test`, `cd app && npm test`, `cd app && npm run build`가 통과한다.

### 지킬 것

- `CLAUDE.md`를 따른다. 프로세스는 직접 띄운 것만 PID로 끈다.
- 이 저장소는 공개다. 작업 기록, 시험 코드, 커밋 메시지에 사용자 경로·메일·토큰, 실제 PC·tailnet 이름, IP를 쓰지 않는다. 커밋 전·푸시 전 검사를 건너뛰지 않는다.
- 생김새는 지금 판의 색, 크기, 모양 토큰(`app/src/renderer/styles.css`)을 따른다. 바꾸기 전과 뒤 스크린숏을 1584×921과 1366×768에서 `experiments/p61/`(git 밖)에 남긴다. 움직임은 짧고 가볍게(약 150~200ms) 하고, `prefers-reduced-motion`이면 움직이지 않는다.
- 화면 글은 영어와 한국어 사전 둘 다 고친다.
- 같은 때 다른 작업자(P60(설정 창과 연결된 기기 탭))가 돈다. 맡은 일에 필요한 만큼만 고친다. `styles.css`와 두 사전은 끝에 더해 합치기 쉽게 한다.
- 자기 브랜치에만 커밋한다. 커밋 메시지에 `Co-Authored-By` 줄을 넣지 않는다. `main`을 바꾸거나 푸시하지 않는다. `node_modules`는 워크트리 안에서 받는다(`npm ci`).
- 문서는 이 작업 파일의 작업 기록 절과 보고 절만 고친다. 고쳐야 할 ARCH·testing 문장이 있으면 보고 절에 짧게 적는다.
- 끝나면 보고 절을 쓰고, 맨 마지막에 `<워크트리>/backend/.dev/p61.done`(브랜치 이름과 마지막 커밋 해시 두 줄)을 만든다.
