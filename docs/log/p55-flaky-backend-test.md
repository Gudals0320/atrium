## 지시

### 목표

가끔 실패하는 백엔드 시험을 찾아, 시간에 기대지 않게 고친다. 사용자의 말: "이거 작업 ㄱㄱ".

P49 작업자가 본 것(`docs/log/p49-remote-r3-tailscale.md` 보고 "알려진 문제와 위험"): 마지막 확인 때 `cd backend && npm test`가 한 번 1개 실패했고(이름을 남기지 못함), 그 뒤 7번 연달아 모두 통과했다. 시간에 기대는 시험이 가끔 흔들리는 것으로 보았다.

### 할 것

1. **찾기.** `cd backend && npm test`를 여러 번(예: 30번 이상, 기계 부하를 바꿔 가며. 다른 작업자가 도는 지금 상태도 부하다) 돌려, 실패한 시험의 이름과 출력을 모은다. 시험마다 따로 여러 번 돌리거나 `--test-concurrency`를 바꿔 보는 것도 쓴다. 실패가 안 나오면 시간·타이머·포트·임시 폴더·전역 상태에 기대는 시험을 코드로 찾아 의심 목록을 만든다.
2. **원인.** 찾은 시험마다 왜 흔들리는지(실제 시간 대기, 정해진 포트, 서로 같은 임시 경로, 정리되지 않은 타이머·서버, 순서 의존 등) 밝힌다.
3. **고치기.** 가짜 시계·조건 기다리기·빈 포트(0)·시험마다 따로 임시 폴더처럼 시간에 기대지 않는 방법으로 고친다. 시험의 뜻(무엇을 확인하는지)은 바꾸지 않는다. 시험이 아니라 제품 코드의 경쟁 상태(race)가 원인이면 그것을 고친다.
4. **확인.** 고친 뒤 `npm test`를 다시 여러 번(30번 이상) 돌려 모두 통과하는 것을 보이고, 몇 번 돌렸는지와 걸린 시간을 적는다. `cd app && npm test`, `cd app && npm run build`도 통과한다.

### 읽을 파일

- `CLAUDE.md`, `docs/testing.md`
- `backend/test/` 전부(특히 P47~P49, P40·P41의 시험: 서버, 프록시, 타이머, 재연결을 쓰는 것), `backend/package.json`의 test 스크립트

### 시험 환경

- 개발용 판이 필요하면 너만의 판으로 띄운다(`docs/testing.md`).
  - `ATRIUM_HERDR_SESSION=atrium-dev-p55`, `ATRIUM_PORT=47874`
  - `ATRIUM_DATA_DIR=<워크트리>/backend/.dev/data`, `ATRIUM_APP_USERDATA=<워크트리>/backend/.dev/app`
- 실제 판(`atrium`, 47800)과 다른 포트(47811~47874 가운데 네 것 말고)는 쓰지 않는다. 사용자의 기본 herdr 세션과 다른 판의 herdr 서버는 건드리지 않는다.
- 대화 목록은 시험 폴더의 대화만 읽는다(`ATRIUM_CLAUDE_PROJECTS`, `ATRIUM_CLAUDE_DESKTOP=none`). 시험 폴더는 `C:\Workspace\mtask-p55-*`처럼 새로 만든다.
- 끝나면 시험 세션, 창, 백엔드, herdr 서버와 세션(`atrium-dev-p55`만), 시험 폴더를 끄고 지운다.

### 지킬 것

- `CLAUDE.md`를 따른다. 프로세스는 직접 띄운 것만 PID로 끈다.
- 이 저장소는 공개다. 작업 기록, 시험 코드, 커밋 메시지에 사용자 경로·메일·토큰을 쓰지 않는다. 커밋 전·푸시 전 검사를 건너뛰지 않는다.
- 같은 때 다른 작업자(P54(개발용 판 CLI 오류))가 돈다. 맡은 일에 필요한 만큼만 작게 고친다.
- 자기 브랜치에만 커밋한다. 커밋 메시지에 `Co-Authored-By` 줄을 넣지 않는다. `main`을 바꾸거나 푸시하지 않는다. `node_modules`는 워크트리 안에서 받는다(`npm ci`).
- 문서는 이 작업 파일의 작업 기록 절과 보고 절만 고친다. 고쳐야 할 ARCH·testing 문장이 있으면 보고 절에 짧게 적는다.
- 끝나면 보고 절을 쓰고, 맨 마지막에 `<워크트리>/backend/.dev/p55.done`(브랜치 이름과 마지막 커밋 해시 두 줄)을 만든다.
