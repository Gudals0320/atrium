## 지시

### 목표

세션이 200개를 넘어도 쓸 수 있는 사이드바를 만들고, 여러 워크스페이스를 Atrium 안에서만 쓰는 가상 그룹으로 묶는다. 사용자의 말은 다음과 같다.
- "세션이 막 200개씩 늘어날 텐데 지금 세션에 정보량이 너무 많다. 지금이 너무 별로니 너가 잘 뜯어고쳐 봐. 자율에 맡긴다."
- "좌측 사이드바에서 가상의 그룹 설정할 수 있으면 좋겠어. 상위 디렉토리처럼. 여러 workspace를 Atrium 내에서만 이용하는 가상의 상위 디렉토리처럼 그룹으로 묶는."
- "전체 자동 정렬 했을 때 이 상위 디렉토리끼리의 workspace를 적당히 비슷한 위치에 묶이게 해 줘. 무한 캔버스에 이 상위 디렉토리를 표기할 필요는 없어. 그냥 모이도록 유도만 해."
- "좌측 사이드바 폭 조절 기능 넣어 주고."
- "안 쓰는 디렉토리 워크스페이스 삭제(안에 cli 있으면 한 번 더 물어보기. 일괄 보관/삭제 선택) 기능 넣어 줘."

### 할 것

1. **사이드바 다시 짜기(자율).** 지금 `Sidebar.jsx`를 세션 200개 이상에서 훑고 찾기 쉽게 다시 짠다.
   - 줄마다 보이는 정보를 줄인다. 이름, 상태, 꼭 필요한 한두 가지만 남기고, 나머지는 마우스를 올리거나 펼칠 때 보인다.
   - 워크스페이스·그룹 단위로 접고 펼친다. 응답 필요·오류처럼 사람이 봐야 하는 세션은 접혀 있어도 눈에 띈다.
   - 찾기·거르기(이름, 상태, 종류)와 키보드 이동을 둔다. 200개 이상에서도 느려지지 않게 한다(가상 스크롤 등).
   - 지난 대화·보관함 같은 지금 기능은 잃지 않는다. 어디로 옮겼는지 보고에 적는다.
   - 생김새는 지금 화면(tokens.css, P11 목업 계열)과 맞춘다. 정한 것과 까닭을 스크린숏과 함께 보고에 적는다.
2. **가상 그룹.**
   - 사이드바에서 그룹을 만들고, 이름을 바꾸고, 지우고, 워크스페이스를 끌어 넣고 뺀다. 그룹은 Atrium 판 데이터에만 있고 디스크 폴더와 상관없다.
   - 워크스페이스는 그룹 하나에만 속하거나 그룹이 없다. 그룹 안의 순서는 사람이 정한다.
   - 다시 켜도 남는다(판 데이터에 저장, 옛 판은 그룹 없음으로 시작).
3. **정렬 때 그룹끼리 모으기.** 판 전체 자동 정렬(`arrangeBoard`, `region-layout.mjs`)이 같은 그룹의 워크스페이스 영역을 가까이 놓는다. 캔버스에 그룹을 그리지는 않는다. 그룹이 없는 워크스페이스는 지금처럼 놓는다. 되돌리기는 지금처럼 된다.
4. **사이드바 폭 조절.** 오른쪽 가장자리를 끌어 폭을 바꾼다. 최소·최대 폭을 두고, 다시 켜도 남는다. 두 번 누르면 기본 폭으로 돌아간다.
5. **워크스페이스 지우기.**
   - 판에서 쓰지 않는 워크스페이스를 지운다(판에서 빼기). 디스크의 폴더와 대화 기록 파일은 건드리지 않는다.
   - 여러 개를 골라 한 번에 지울 수 있다(사이드바에서).
   - 안에 세션이 있으면 한 번 더 묻고, 그 세션들을 "모두 보관"(꺼서 보관함으로) 또는 "모두 삭제"(꺼서 판에서 지움) 가운데 고르게 한다. 돌고 있는 CLI 세션이 있으면 그 수를 확인 글에 보인다.
   - 지금 `workspace.close`의 `not_empty` 거부는 이 흐름으로 바꾼다. 자동으로 다시 열리지 않게 하는 지금 규칙(P10)은 지킨다.

### 완료 기준

1. 그룹 저장·옮기기, 정렬에서 그룹끼리 모으기(같은 그룹 영역 사이 거리가 다른 그룹보다 가깝다), 지우기 판단(빈 것, 세션 있음, 돌고 있는 CLI)은 순수 함수로 두고 단위 시험한다.
2. 개발용 판의 창 시험(e2e)으로 확인하고 스크린숏을 `experiments/p44/`(git 밖)에 남긴다.
   - 시험 폴더 워크스페이스 6개, 셸 세션 40개 이상(그 가운데 몇은 응답 필요처럼 보이게)으로 새 사이드바를 보인다. 200개는 단위·성능 시험으로 본다.
   - 그룹 둘을 만들고 워크스페이스를 넣은 뒤 판 전체 정리 → 같은 그룹 영역이 모인다.
   - 사이드바 폭을 바꾸고 창을 다시 읽어도 남는다.
   - 세션이 든 워크스페이스 둘을 골라 지우기 → 한 번 더 묻고 보관·삭제가 고른 대로 된다. 폴더는 디스크에 그대로다.
3. `cd backend && npm test`, `cd app && npm test`, `cd app && npm run build`가 통과한다.

## 보고

### 만든 것

**1. 사이드바 다시 짜기**(`Sidebar.jsx`, 새 `lib/sidebar-tree.js`, `sidebar.css` 끝)

- 나무: 그룹(사람이 정한 순서) → "그룹 없음"(그룹이 하나라도 있을 때만 머리줄) → 워크스페이스 → 판 세션. 하위 세션은 지금처럼 부모 아래에 들인다(`treeOrder`).
- 줄 정보
  - 세션 줄은 한 줄(28px)이다. 상태 점, 셸이면 `$`, 이름, claude·셸이 아니면 종류 꼬리표, 하위 세션이면 역할, 지난 시간만 둔다.
  - 응답 필요(waiting, trust_wait)·오류(error, exited) 줄만 두 줄(44px)이다. 꼬리표("응답 필요"/"오류")와 질문(또는 오류 글)을 보인다. 바탕도 옅은 주황(오류는 옅은 빨강)이다.
  - 나머지(종류, 상태 이름, 질문, 마지막 요청, 셸 명령, 가지 정보)는 마우스를 올리면 title로 보인다.
  - 워크스페이스·그룹 머리줄은 접힘 표시, 이름, 세는 값(응답 필요 수 주황 알약, 오류 수 빨강 알약, 작업 중 수 초록, 세션 수)이다. 접혀 있으면 사람이 봐야 하는 수만 보인다.
- 접기·펼치기: 그룹과 워크스페이스마다 접는다. 접힌 묶음 아래에도 응답 필요·오류 세션은 왼쪽 주황 줄을 단 줄로 남는다(6개까지, 넘으면 "확인이 필요한 세션 n개 더"를 누르면 펼친다). 칩 줄 오른쪽의 ⊟/⊞는 워크스페이스를 모두 접거나 편다.
- 찾기·거르기: 찾기 칸(이름, 요청, 답, 질문, 역할), 상태 칩(응답 필요, 오류, 작업 중, 대기, 절전. 판 전체 수, 0인 칩은 숨김, 여럿 고르기), 종류 고르기(종류가 둘 이상일 때). 거르는 동안에는 접힘을 무시하고 맞는 것만 보이며, 맞는 것이 없는 묶음은 뺀다. "지우기"로 모두 푼다. 거르기 값은 창 프로필에 남는다.
- 키보드: 찾기 칸에서 ↓(또는 글이 있을 때 Enter)로 목록에 들어간다. 목록에서 ↑↓, PageUp/PageDown, Home/End로 옮기고, Enter로 들어간다(세션 → 그 터미널, 워크스페이스 → 영역, 그룹 → 접기, 닫힌 세션·대화 → 판으로 열기). →는 펴고 ←는 접거나 위 머리줄로 간다. 맨 위에서 ↑, Esc는 찾기 칸으로 간다.
- 속도: 보이는 줄 위아래 6줄만 그린다(가상 스크롤). 단위 시험에서 세션 1,000개·워크스페이스 30개를 펴는 데 한 번 50ms 미만, 그리는 줄은 화면 높이만큼(50줄 미만)이다. 창 시험의 42개 판에서는 줄 48개 중 34개를 그렸다.
- 옮긴 곳
  - 닫힌 세션·판 밖 대화: 워크스페이스 안 한 줄("닫힘 n · 대화 m")로 접어 두고, 누르면 절 이름과 함께 펼친다(지금처럼 5개씩 "더 보기"). 글로 거르면 함께 찾고 저절로 펼친다. 상태·종류 칩을 고르면 숨는다(판 세션만 고른다).
  - "판으로 열기"·"보관" 단추, 묶인 곳 표시: 그 줄에 마우스를 올리거나 키보드로 고르면 오른쪽에 뜬다. 다른 곳에 묶인 줄은 지금처럼 흐리다.
  - "오래된 항목 보관": 워크스페이스 머리줄의 ⋯ 메뉴로 옮겼다. 확인 줄은 칩 줄 아래에 뜬다.
  - 보관함, missed 함: 목록 맨 아래 그대로다(가상 목록 뒤에 이어진다). 오른쪽 레일의 보관함 단추도 그대로다.
  - "리포 이름을 누르면 영역으로": 워크스페이스 이름을 누르면 영역으로 가고, 줄의 나머지를 누르면 접는다.
- 생김새: 패널 토큰(`--panel*`), 대문자 회색 절 이름(그룹 머리줄), 상태 색(`--st-*`), 내 차례 주황(`--attn`)만 썼다. 새 색은 없다. 줄 높이와 글자 크기는 P11 목업의 패널 줄(12~13px)에 맞췄다.
- 스크린숏(git 밖): `experiments/p44/p44-sidebar-01-sidebar-42.png`(셸 42개, 응답 필요 5·오류 1), `-02-folded-attn.png`(접힌 워크스페이스 아래 응답 필요), `-03-filter-need.png`(응답 필요 칩), `-04-groups-sidebar.png`(그룹 둘, 모두 접기).

**2. 가상 그룹**(새 `backend/src/ws-groups.mjs`, `Sidebar.jsx`)

- API: `group.list`, `group.create { name, workspaces?, at? }`, `group.rename { group, name }`, `group.remove { group }`, `group.order { group, index }`, `group.move { workspace, group | null, index? }`. 그룹 목록은 `workspace.updated`·`workspace.list`·`board.get`의 `groups`로 창에 온다(창 `store.js` `state.groups`).
- 이름은 1~40자, 대소문자를 무시하고 겹치지 않는다. ID는 `g1`, `g2`, …
- 사이드바: 칩 줄의 +(새 그룹을 만들고 바로 이름 칸), 그룹 머리줄 두 번 누르기 또는 ⋯ → 이름 바꾸기, ⋯ → 그룹 지우기(안의 워크스페이스는 그룹 없음으로), ⋯ → 안의 워크스페이스 모두 판에서 지우기.
- 넣고 빼기: 워크스페이스 줄을 그룹 머리줄에 끌어 놓으면 그 그룹 끝, 다른 워크스페이스 줄 위쪽 절반이면 그 앞, 아래쪽 절반이면 그 뒤(놓일 자리에 초록 줄), "그룹 없음" 머리줄이면 그룹에서 뺀다. 워크스페이스 ⋯ 메뉴의 "그룹으로 옮기기"(그룹 목록), "이 프로젝트로 새 그룹 만들기", "그룹에서 빼기"도 같다.
- 판에서 지운 워크스페이스는 그룹에서도 빠진다(다시 열면 그룹 없음).

**3. 정렬 때 그룹끼리 모으기**(`region-layout.mjs` `layoutRegions`, `canvas-ops.mjs` `arrangeBoard`)

- 같은 그룹의 영역은 그룹 안 순서대로 먼저 한 덩어리로 채우고(덩어리 안 간격 REGION_GAP), 덩어리를 영역 하나처럼 읽는 순서대로 놓는다. 그룹이 하나라도 있으면 단위 사이 간격은 REGION_GAP의 두 배다. 그룹이 없으면 P31과 같다(시험 있음).
- 캔버스에 그룹을 그리지 않는다. 되돌리기는 지금 그대로다(판 전체 되돌리기 자료는 바뀌지 않았다). 결과에 `clusters`(그룹, 영역 키, 덩어리 사각형)를 더했다.
- 창 시험: 정리 뒤 화면에서 같은 그룹 이웃까지 39px, 다른 것까지 59~69px. 스크린숏 `experiments/p44/p44-sidebar-05-arranged-groups.png`.

**4. 사이드바 폭**(`Sidebar.jsx` `ResizeHandle`)

- 오른쪽 가장자리 6px를 끈다. 최소 240px, 최대 640px, 기본 340px. 두 번 누르면 기본 폭이다. 폭은 창 프로필 localStorage(`mt.sidebar.width`)에 남는다. 스크린숏 `-06-wide.png`.

**5. 워크스페이스 지우기**(`backend.mjs` `workspaceClose`·`removeWorkspace`·`dropClosedRow`, 새 `backend/src/ws-close.mjs`, `Workspaces.jsx` `CloseWsDialog`)

- `workspace.close { workspace | workspaces: [..], confirm?, after?: 'archive' | 'delete' }`
  - 확인 전에는 `plan`(워크스페이스마다 세션 수, 돌고 있는 CLI 수, 잠든 수)을 준다. 빈 것 하나면 예전 문구(`wsClose`)다.
  - 세션이 있는데 `after`가 없으면 `not_empty`(`wsChooseAfter`)로 거부한다. 지금의 `not_empty`("먼저 끈다")를 이 흐름으로 바꿨다.
  - 모두 보관: 세션마다 `session.kill { after: 'archive' }`. 모두 삭제: 끈 뒤 닫힌 세션 행만 지운다(대화 기록 파일은 휴지통으로 보내지 않는다).
  - 끄지 못한 세션이 있으면 그 워크스페이스는 남기고 `kept`, `sessions.failed`로 알린다.
  - 지운 워크스페이스는 메모·칸반 소속을 풀고 `workspace_closed`를 남겨 저절로 다시 열지 않는다(P10).
- 돌고 있는 CLI: 셸이 아닌 세션 중 잠듦·끝남이 아닌 것, 그리고 명령이 도는 셸(`shell_running`).
- 사이드바: 칩 줄의 "선택"을 누르면 워크스페이스 줄에 체크 상자가 생기고 아래에 "n개 선택됨 · 보드에서 제거 · 취소" 막대가 뜬다. 워크스페이스 ⋯ 메뉴의 "보드에서 제거…", 영역 이름표 단추의 "제거"(`Regions.jsx`)도 같은 확인창을 연다.
- 확인창: 워크스페이스 목록(세션 수·실행 중 수), "안에 세션 n개", 실행 중 CLI가 있으면 "실행 중인 CLI n개를 종료합니다", "모두 보관"/"모두 삭제" 고르기(고르기 전에는 확인 단추가 꺼져 있다), 폴더와 대화 기록 파일은 그대로라는 안내. 스크린숏 `-07-remove-ask.png`, `-08-after-archive.png`, `-09-after-delete.png`.
- CLI: `atrium ws close <이름> --yes --after archive|delete`.

### 계획과 다른 곳

- 남의 파일을 조금 고쳤다.

  - `backend/bin/atrium.mjs`: `ws close`에 `--after`와 도움말.
- CSS는 `styles.css`가 아니라 사이드바 전용 `sidebar.css` 끝에 더했다(지우기 확인창 스타일도 거기).

- 세션 줄에서 상태 글 알약(StatePill)을 빼고 점으로 바꿨다. 상태 이름은 title에 있다.

### 알려진 문제

- "모두 보관"한 세션은 그 워크스페이스가 판에 없으면 보관함에 보이지 않는다(보관함은 열린 워크스페이스별, `recall.mjs` `compute`). 워크스페이스를 다시 열면 보인다. 확인창 글에 그렇게 적었다.
- 옛 창 시험 중 사이드바 DOM에 기대는 것(`p7-j5`, `p10-archive`, `p7-j2`, `p7-j4`, `p13-convos`, `p8-k4`, `p16-lang`, `p39-ko` 등)은 다시 돌리지 않았다. `.mt-sb-ws` 묶음, `data-action="fold"` 단추, 늘 보이던 "판으로 열기"·"보관" 단추, 화면 밖 줄이 바뀌어 고쳐야 할 수 있다. `data-sb`, `data-session`, `data-convo`, `data-action`(reopen, open-convo, archive, go-convo, go-ws, archive-old, old-confirm), `data-role`(sidebar, sidebar-filter, archive-box, missed-box) 이름은 지켰다.
- 끌어 놓기는 창 시험에서 DragEvent를 직접 보내 확인했다. 실제 마우스 끌기는 사람이 보지 않았다.
- 접힌 그룹 아래 응답 필요 줄을 누르면 그 세션으로 가지만, 그룹은 접힌 채로 둔다.
- 셸만으로는 응답 필요가 생기지 않아, 그 모양은 창 안에 흘린 가짜 상태로만 보았다.

### 살아 있는 문서에 들어갈 새 문장(지시가 보고 절에 적으라고 한 것)

- ARCH J5 → "왼쪽, 평소에 닫힘(위 왼쪽 ☰, 오른쪽 레일, `Ctrl+Shift+E`), 오른쪽 가장자리를 끌어 폭을 바꾼다. 가상 그룹 → 워크스페이스 → 판 세션의 나무를 줄 높이가 정해진 목록으로 펴서 보이는 줄만 그린다(`lib/sidebar-tree.js`). 세션 줄은 상태 점, 이름, 지난 시간이고 응답 필요·오류만 질문 한 줄을 더 보이며, 접힌 묶음 아래에도 남는다. 찾기 칸, 상태 칩, 종류 고르기, 키보드 이동이 있다. 닫힌 세션과 판 밖 대화는 워크스페이스마다 한 줄로 접혀 있다가 펼친다. 그룹은 만들기·이름·지우기와 끌어 넣기, 워크스페이스는 메뉴와 고르기 모드로 판에서 지운다. 맨 아래에 보관함과 missed 함이 있다. 열림, 폭, 접힘, 거르기는 창 프로필에 둔다."
