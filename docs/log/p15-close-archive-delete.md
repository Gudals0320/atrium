## 지시

사용자 요청. 지휘 세션이 직접 고친다.

- 열린 세션을 닫는 행위 자체가 보관이나 삭제를 뜻해야 한다. 그러지 않으면 지워도 나중에 다시 뜬다.
- 노드의 X를 누르면 보관, 삭제, 취소를 보인다.

완료 기준: 개발용 판의 창 시험으로 다음을 본다. 단위 시험과 빌드가 통과한다.
- X를 누르면 세 가지가 뜬다.
- 삭제하면 대화 기록이 휴지통으로 가고, 닫힌 목록·보관함·대화 노드에 다시 뜨지 않는다.
- 보관하면 보관함에만 있다.

## 작업 기록

- 전에는 X가 "끄기"와 "취소"였다.
  - 끈 claude는 닫힌 세션으로 남아 사이드바 닫힌 목록에 보였다.
  - 대화 기록도 남았다.
- 백엔드:
  - `session.kill`에 `after`(`archive`, `delete`)를 더했다.
  - 보관은 P10의 보관 표시를 그대로 쓴다.
  - 삭제(`recall.forgetClosed`)는 막 끈 세션의 대화 기록과 옆 폴더를 휴지통으로 보낸다.
    - 거부 규칙은 P13 missed 지우기와 같다(뿌리 밖, UUID 아님, 도는·묶인·데스크톱).
    - 판이 방금 끈 자기 세션이라 "방금 기록됨"은 묶임으로 보지 않는다.
    - 세션 파일이나 명령줄에 아직 살아 있으면 8초까지 기다린다.
    - 이어서 닫힌 세션 행, 노드 자리, 선과 선 기록, 보관 표시를 지운다(`deleteClosedSession`). 이벤트 기록은 남긴다.
    - 지우지 못하면 대화 기록이 남아 다시 뜨므로, 그때는 보관한다.
  - `mtask kill <이름> --yes --archive|--delete`도 같다.
- 창: X의 확인 줄을 보관, 삭제, 취소로 바꿨다. 결과는 알림 글로 보인다(지웠다, 보관했다, 지우지 못해 보관했다와 이유).
- 개발용 판 `multitask-dev-p15`(포트 47830, `backend/.dev/p15`)에서 `app/test/e2e/p15-close.mjs`를 돌렸다.
  - 시험 폴더: 새로 만든 `C:\Workspace\mtask-p15-ws\demo`
  - 시험 claude: haiku에 한 마디 지시
  - 끝난 뒤 백엔드, herdr 서버와 세션, 시험 폴더, 판 데이터, 이 시험의 대화 기록 폴더를 지웠다. 삭제 시험의 대화 기록은 휴지통에 있다.

## 보고

- 노드의 X: 보관, 삭제, 취소.
  - 보관: 끄고 보관함에 둔다. 보관함에서 다시 연다.
  - 삭제: 끄고 대화 기록을 휴지통으로 보낸다. 판 기록에서도 지워 다시 뜨지 않는다.
- 시험(`experiments/p15/p15-close.json`): 4/4 통과.
  - 세 단추와 문구
  - 취소
  - 삭제(대화 기록 없음, 닫힌 목록·보관함·대화 노드에 없음)
  - 보관(보관함에만 있음, 대화 기록은 남음)
- 단위 시험: 백엔드 170(P15 3개: 삭제, 도는 대화는 보관, 대화 기록 없는 세션과 열린 세션), 창 34, 빌드 통과.
- 알려진 문제:
  - 옛 창 시험(`c3-trust.mjs`, `p4-f3.mjs`, `p5-g2.mjs`)은 확인 줄의 `.mt-btn.danger`를 누른다. 이제 그것은 "삭제"라서, 그 시험들은 시험 세션의 대화 기록을 휴지통으로 보낸다. 고치지 않았고 돌리지 않았다.
  - 셸도 같은 세 단추다. 셸은 대화 기록이 없어서, 삭제하면 닫힌 행만 지운다.
