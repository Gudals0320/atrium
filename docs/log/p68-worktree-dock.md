## 지시

### 목표

같은 저장소의 서로 다른 워크트리 세션도 붙여 묶을 수 있게 한다. 사용자의 말: "worktree 막 6개씩 호출하고 그러는데 얘네들끼리는 dock 이 안되잖아? 근데 얘네들을 그래도 좀 붙이고싶은데". 사용자가 고른 방향: "워크트리끼리도 붙이기".

지금은 리드가 `atrium child --worktree`로 워커를 여럿 띄우면 워크트리마다 노란 상자(ARCH 4절 G1·H5, `backend/src/worktrees.mjs`, `store-worktrees.mjs`)가 따로 생긴다. 상자가 다른 세션끼리는 붙여 묶을 수 없다.

### 할 것

1. **붙이기 허용.** 같은 워크스페이스(같은 저장소 키)라면 워크트리가 달라도 세션끼리 붙여 묶을 수 있다. 본 저장소 세션과 워크트리 세션을 붙이는 것도 된다. 다른 워크스페이스(다른 저장소) 세션끼리는 지금처럼 붙이지 않는다.
   - 방법은 지금 붙이기와 같다: `Ctrl`+끌기, 배치 틀(여럿 고르고 1 + 2, 2 × 2 등), 덩어리 바깥 가장자리 가까이 놓기.
2. **붙인 뒤의 자리.** 붙인 세션은 노란 워크트리 상자에서 빠지고, 덩어리는 그 저장소 영역 안에 놓인다. 세션이 빠져 빈 워크트리 상자는 숨긴다(워크트리 자체는 그대로). 덩어리에서 떼면 그 세션은 자기 워크트리 상자로 돌아간다. 세션의 워크트리 정보는 바뀌지 않는다.
3. **덩어리 안의 표시.** 덩어리 안 칸마다 그 세션의 브랜치·워크트리 이름을 머리에 작게 보인다(예: `⎇ feature/dark-mode`). 칸끼리 브랜치가 다르다는 것이 한눈에 보여야 한다. 색은 노란 워크트리 표시와 맞춘다.
4. **한 번에 붙이기.** 리드가 띄운 워크트리 워커들을 한 번에 붙이는 길을 둔다. 예: 워크트리 상자 머리나 리드 노드 메뉴의 "워커 붙여 묶기"가 그 리드의 하위 세션들을 세션 수에 맞는 배치 틀로 묶는다. 같은 일을 CLI(`atrium dock …` 같은 지금의 판 명령이 있으면 그것)로도 할 수 있게 한다.
5. **정리·저장·다시 켜기.** 판 정리(`board.arrange`), 영역 정리, 워크트리 상자 자리 정하기가 이런 덩어리를 깨지 않는다. 백엔드·창·herdr를 다시 켜도 덩어리와 상자 상태가 남는다. 워크트리를 지우거나 세션을 닫으면 지금처럼 잎을 빼고 나무를 정리한다.

### 완료 기준

1. 단위 시험을 더하고 통과한다: 같은 저장소의 다른 워크트리끼리 붙이기 허용, 다른 저장소는 거부, 붙이면 상자에서 빠짐과 빈 상자 숨김, 떼면 돌아감, 정리가 덩어리를 깨지 않음, 다시 켠 뒤 남음.
2. 창 시험(개발용 판, 리드 하나가 `atrium child --worktree`로 워커 셋을 띄움, haiku)으로 확인하고 전후 스크린숏을 `experiments/p68/`에 둔다: `Ctrl`+끌기로 둘 붙이기, 셋을 골라 배치 틀, "워커 붙여 묶기", 칸마다 브랜치 표시, 떼기, 백엔드를 다시 켠 뒤 그대로.
3. `cd backend && npm test`, `cd app && npm test`, `cd app && npm run build`가 통과한다.

- 처음 상태: 백엔드 `sameWs`(세션의 워크스페이스 키)는 이미 같은 리포면 워크트리가 달라도 붙이기를 받았다. 막은 곳은 창이었다(`Canvas.jsx` `snapBlocks`·`ctrlBlocks`가 같은 "영역"끼리만 후보로 봄). 다만 붙여도 구성 노드마다 저장한 영역(`nodes.area`)대로 상자에 들어가, 상자가 덩어리 일부를 감싸는 모양이 된다.
- 설계: 영역을 정할 때 덩어리를 본다. 같은 리포의 다른 영역(본 저장소 영역, 워크트리 상자) 세션이 섞인 덩어리의 구성 노드는 리포 영역(본 저장소 쪽)에 든 것으로 센다. 저장한 `nodes.area`는 바꾸지 않으므로 다시 켜도 같은 계산이 같은 결과를 낸다. 구성 노드가 빠져나가 안이 빈 상자는 영역 자리 목록에서 뺀다(숨김). 순수 함수 둘(`dockedAreas`, `visibleAnchors`)을 `worktree-areas.mjs`에 두고 백엔드(`canvasItems`, `areaAnchors`)와 창(`areaOfId`, `anchorsOf`)이 같이 쓴다.
  - 다른 길(붙일 때 `nodes.area`를 ''로 바꾸고 뗄 때 되돌리기)은 워크트리 정보를 바꾸고, `worktrees.mjs`의 노드 옮기기와 다툴 수 있어 버렸다.
  - 한 상자 안의 세션끼리만 붙인 덩어리는 지금처럼 그 상자에 남는다(섞이지 않았으므로).

## 보고

### 만든 것

1. **영역 계산**(`backend/src/worktree-areas.mjs`, 순수, 창도 씀)
   - `dockedAreas(docks, areaOf)`: 같은 리포의 다른 영역이 섞인 덩어리의 구성 노드 → 리포 키, 구성 노드가 빠져나간 상자 키 모음.
   - `visibleAnchors(anchors, items, pulled)`: 빠져나가 안이 빈 상자를 영역 자리에서 뺀다. 워크트리 행(`worktree_areas`)은 그대로다.
   - `workersPreset(n)`: 워커 수에 맞는 고른 틀(둘 `row`, 셋 `row3`, 넷 `grid`, 다섯 `top3-bottom2`, 여섯 `grid-3x2`, 그 위 `even-rows`).
2. **백엔드**(`backend/src/canvas-ops.mjs`)
   - `canvasItems`·`areaAnchors`가 위 계산을 쓴다(`boardItems`). 정리(`blocksOf`, `arrangeBoard`), 겹침 풀기(`settleBoxes`), 빈자리, 상자 자리 정하기(`boxSlot`, `reslotBoxes`), 하위 세션 자리가 모두 이 결과를 본다. 섞인 덩어리는 본 저장소 쪽의 한 블록으로 정리되고 상자처럼 밀리지 않는다.
   - `keepBoxes`: `dock.attach`, `dock.create`, `dock.layout`, `dock.remove`(잎 하나, 덩어리 통째), 세션 닫힘(`onSessionClosed`)을 감싸 숨는 상자 자리 저장과 상자로 돌아가기를 한다. 판 이벤트 `worktree_box_hidden`, `node_moved`(cause `worktree box return`).
   - 배치 틀 자리(`presetSpot`): 고른 노드가 여러 영역에 걸치면 리포 영역에 놓고, 비게 될 상자는 피하지 않는다.
   - `dock.workers { lead, preset? }`(`dockWorkers`): 리드의 하위 세션 가운데 같은 워크스페이스에 노드가 있는 것을 띄운 차례로 묶는다. 둘보다 적으면 `bad_request`(열쇠 `dockWorkersFew`). 판 이벤트 `workers_docked`.
   - 다른 리포(워크스페이스) 세션끼리는 지금처럼 거부한다(`sameWs`).
3. **CLI**: `atrium dock workers <리드> [--preset <틀>]`(`backend/bin/atrium.mjs`).
4. **창**
   - `Canvas.jsx`: `areaOfId`·`anchorsOf`가 같은 계산을 쓴다(숨은 상자는 그리지 않는다). Ctrl+끌기(`ctrlBlocks`)와 가장자리 붙이기(`snapBlocks`)의 후보는 같은 워크스페이스 전체다. 배치 틀은 원래 워크스페이스로만 막았다. 같은 저장소 선(F4)은 저장한 영역으로 판단한다(덩어리로 빠져나간 워크트리 세션에도 긋지 않음).
   - `lib/dock-branch.js` `dockBranchOf`와 `SessionNode.jsx` 머리줄: 섞인 덩어리 칸마다 `⎇ 브랜치`(세션의 git 브랜치, 없으면 상자의 브랜치·폴더). 워크트리 칸은 노란 상자와 같은 색(`--wt-box-text`, `--wt-box-line`), 본 저장소 칸은 흐린 색. 혼자인 노드, 한 상자 안의 덩어리, 본 저장소끼리의 덩어리에는 보이지 않는다.
   - 노드 메뉴: 하위 세션이 둘 이상인 세션에 "워커를 창 그룹으로 묶기"(`data-action=dock-workers`). 영어 사전 `dockWorkers.*`, 한국어 사전 같은 절(두 사전 끝), `backend.dockWorkersFew`.
   - `styles.css` 끝에 `.mt-dock-branch`.

### 정한 것과 까닭

- **섞인 덩어리만 리포 영역으로 뺀다.** 한 상자 안 세션끼리의 덩어리는 그 상자의 것이 맞으므로 지금처럼 둔다. 상자를 덩어리 일부만 감싸게 두면 상자와 본 저장소 쪽 것이 겹치는 모양이 생긴다.
- **워크트리 정보는 저장한 그대로, 자리 판단만 바꾼다.** 덩어리와 `nodes.area`가 저장되므로 다시 켜도 계산이 같다. 별도 표나 열을 더하지 않았다.
- **빈 상자 숨김의 조건은 "빠져나가서 비었다"이다.** 세션이 아직 없는 새 워크트리 상자는 지금처럼 보인다.
- **떼면 숨기 전 자리로.** 상자가 숨을 때 그 사각형 자리를 저장해 두므로, 떼면 노드가 상자에 혼자 있던 자리로 돌아간다. 상자에 다른 세션이 남아 있었으면 그 상자의 빈자리다. Ctrl+끌기로 판 위 다른 곳에 놓아 떼도 자기 상자로 돌아간다(지시 2번 "자기 워크트리 상자로 돌아간다").
- **워커 붙여 묶기는 리드 노드 메뉴와 CLI에 둔다.** 상자 머리에도 두려 했으나 붙이고 나면 상자가 숨어 다시 누를 곳이 사라지고, 한 상자는 워커 하나의 것이라 "그 리드의 워커들"을 가리키기 어렵다. 리드는 빼고 하위 세션만 묶는다.
- **워커 틀은 고른 틀**(가로 셋, 2 × 2 등). 워커는 대등하므로 1 + 2처럼 하나를 크게 두는 틀은 쓰지 않는다. 다른 틀은 `--preset`으로 준다.

### 계획과 다른 곳

- 리드·워커가 신뢰를 받지 않은 새 시험 저장소에서 떠 신뢰 질문에서 멈춘 채로 시험했다. 신뢰는 대신 수락하지 않으므로 리드가 직접 `atrium child --worktree`를 치는 대신 리드의 세션 env로 같은 명령(`atrium child --cwd <워크트리>`)을 불렀고, 워크트리는 `git worktree add`로 claude -w와 같은 자리·브랜치 이름에 만들었다. 판 배치와 붙이기는 세션 상태와 상관없다. 실제 `claude -w` 워커로 한 번 보는 것은 사람 점검으로 남긴다.
- 워커 붙여 묶기를 워크트리 상자 머리에는 두지 않았다(위 "정한 것").

### 알려진 문제

- Ctrl+끌기로 노드 가장자리에 놓아 반으로 나눠 붙인(`at: leaf`) 뒤 떼면 노드가 반 크기로 남는다. 지금 붙이기 동작이고 이번에 바꾸지 않았다. 작은 노드는 멀리서 아이콘 얼굴이 된다.
- 반 크기로 돌아온 상자에서는 신뢰 질문 말풍선이 상자 이름표를 가린다(`p68-4-undocked`). 지금 말풍선 동작이다.
- 섞인 덩어리를 영역 이름표로 끌면 덩어리는 리포 영역과 함께 움직이지만, 숨은 상자의 저장 자리도 함께 옮겨진다(리포째 옮기기). 떼면 옮겨진 리포 영역 안의 같은 상대 자리로 돌아가므로 맞는 동작으로 본다.
