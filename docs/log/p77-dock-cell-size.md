상태: 열림
날짜: 2026-11-07

## 지시

### 목표

덩어리(붙여 묶은 세션)의 크기 막대(가로형·세로형, 16:9·4:3, 크게·보통·작게)를 덩어리 바깥이 아니라 세션 칸 하나하나에 맞춘다.

### 사용자의 말

"레이아웃 기능에서 16:9 4:3 에 대한 종횡비 측정을 가로형/세로형에 대해 dock 전체 테두리 종횡비만 따지다 보니까 사용자 경험이 좀 괴리됨. 예를 들어 (4개 dock - horizontal - 가로형 - 크게 - 16:9) 를 하면 하나하나의 세션은 위로 길어짐. 근데 이런건 내가 세로형에 원하는 건데. 세로형 가로형은 각 세션의 길게 주로를 가지고 명명해야 될거같은데"

지휘 세션이 "크기 단계는 칸마다 단독 세션 크기"와 "덩어리 전체 면적" 가운데 무엇으로 할지 물었고, 사용자는 **칸마다 단독 세션 크기**를 골랐다(2026-11-07).

### 지금(P73)

- 크기는 방향 × 비율 × 단계다(`backend/src/canvas.mjs` `SIZE_TABLE`, `stepSize`, `resolveSize`). 16:9는 1920×1080·1440×810·1040×585, 4:3은 1600×1200·1200×900·880×660, 세로형은 가로·세로를 바꾼다.
- 덩어리는 방향·비율·단계가 덩어리 바깥의 값이다(`docks.aspect`). 칸 크기는 배치 틀(분할 비율, `dock-tree.mjs`)로만 정하고, 덩어리 크기는 바깥 테두리로만 바꾼다(`dragOuter`). 그래서 H 배치 틀 넷에 가로형 16:9 크게를 고르면 바깥이 1920×1080이고 칸 하나는 480×1080으로 세로로 길다.
- 배치 틀로 새로 짠 덩어리의 칸은 `DOCK_CELL` 960×540이다.

### 할 것

1. **칸 기준 규칙.** 덩어리의 방향·비율·단계는 칸 하나의 모양과 크기다. 칸 하나는 같은 값의 단독 세션과 같은 크기다(가로형 16:9 크게면 칸마다 1920×1080). 덩어리 바깥 크기는 배치 틀에서 나온다.
   - 예: H 넷·가로형·16:9·크게 → 칸 1920×1080, 바깥 7680×1080. V 넷·세로형·4:3·보통 → 칸 900×1200, 바깥 900×4800. 2×2·가로형·16:9·보통 → 칸 1440×810, 바깥 2880×1620(바깥도 16:9).
   - 고르지 않은 배치 틀(큰 칸 하나와 작은 칸 둘 등)은 가장 작은 칸이 고른 모양과 크기가 되고, 큰 칸은 작은 칸을 합친 크기가 된다. Ctrl+끌기로 만든 분할 나무처럼 고른 격자가 아닌 나무에서 어떻게 정하는지(잎이 너무 납작해지지 않게) 근거와 함께 보고에 적는다.
2. **크기 막대.** 덩어리를 고르면 막대의 가로형·세로형·비율·단계가 칸 기준임을 보인다(제목 글·도움말). 가로형·세로형은 세션 하나의 긴 쪽 방향이다. 단독 세션의 막대는 그대로다.
3. **바깥 테두리.** 바깥 테두리로 크기를 바꾸면 지금처럼 칸이 함께 커지고 작아지며 비율·단계 단추가 꺼진다.
4. **붙이기·떼기·배치 틀 바꾸기.** 덩어리에 세션을 붙이거나 떼거나 배치 틀을 바꿀 때, 비율·단계가 켜져 있으면 칸 크기를 지키고 덩어리 바깥이 늘거나 준다. 꺼져 있으면(테두리로 바꾼 뒤) 지금처럼 한다. 덩어리가 커지면 P75의 줄 밀기(`reflowLines`)가 뒤 형제를 민다.
5. **이미 있는 판.** 뜰 때 덩어리의 자리와 크기를 바꾸지 않는다. 사람이 막대를 누를 때부터 새 규칙을 쓴다. 옛 `docks.aspect` 값은 그대로 읽힌다.

### 완료 기준

1. 단위 시험을 더하고 통과한다: 위 세 예의 칸·바깥 크기, 고르지 않은 배치 틀, 바깥 테두리 뒤 단추 꺼짐, 붙이기·떼기에서 칸 크기 유지, 이미 있는 판 그대로, 단독 세션 크기 그대로.
2. 창 시험(개발용 판, 셸 넷)으로 H 넷 가로형 16:9 크게, V 넷 세로형, 2×2, 고르지 않은 배치 틀을 찍어 `experiments/p77/`에 둔다. 고치기 전 코드로도 같은 것을 찍어 비교한다.
3. `cd backend && npm test`, `cd app && npm test`, `cd app && npm run build`가 통과한다.

### 시험 환경

- 이 작업은 `dev` 브랜치에서 시작한다. 워크트리를 연 뒤 먼저 `git fetch origin && git merge --ff-only origin/dev`를 한다(워크트리가 `main`에서 시작할 수 있다).
- 너는 사용자의 실제 판 위에서 도는 워커라 셸에 실제 판의 `ATRIUM_*`·`HERDR_*`가 있다. 시험, 개발용 판, herdr, `atrium`은 이 변수를 지운 셸(`backend/.dev/clean-env.sh`, `docs/testing.md`)로 부른다.
- 개발용 판은 너만의 판으로 띄운다(`docs/testing.md`).
  - `ATRIUM_HERDR_SESSION=atrium-dev-p77`, `ATRIUM_PORT=47897`, 창의 원격 디버깅 포트 9377
  - `ATRIUM_DATA_DIR=<워크트리>/backend/.dev/data`, `ATRIUM_APP_USERDATA=<워크트리>/backend/.dev/app`
- 실제 판(`atrium`, 47800)과 다른 판의 포트는 쓰지 않는다. 사용자의 기본 herdr 세션, 실제 판의 herdr 세션(`atrium`), 다른 판의 herdr 서버는 건드리지 않는다. 사용자의 실제 판은 열지도 캡처하지도 않는다. 스크린숏은 창 안만 찍는다(`page.screenshot`).
- 실제 판의 API(47800)와 `atrium` 명령으로 실제 판을 바꾸지 않는다. 시험의 `atrium` CLI는 늘 개발용 판 환경 변수(`ATRIUM_PORT` 등)를 주고 부른다.
- 실제 설치 폴더(`%LOCALAPPDATA%\atrium\versions`)와 실제 데이터 폴더(`%LOCALAPPDATA%\atrium`)는 읽지도 바꾸지도 않는다.
- 대화 목록은 시험 폴더의 대화만 읽는다(`ATRIUM_CLAUDE_PROJECTS`, `ATRIUM_CLAUDE_DESKTOP=none`). 시험 폴더는 `C:\Workspace\mtask-p77-*`처럼 새로 만든다.
- 세션은 `claude --model haiku`와 셸로 띄운다.
- 끝나면 시험 세션, 창, 브라우저, 백엔드, herdr 서버와 세션(`atrium-dev-p77`만), 시험 폴더를 끄고 지운다. 네가 띄운 프로세스가 남지 않았는지 포트로 확인한다.

### 지킬 것

- `CLAUDE.md`를 따른다. 프로세스는 직접 띄운 것만 PID로 끈다. 신뢰 질문은 대신 답하지 않는다.
- 이 저장소는 공개다. 작업 기록, 시험 코드, 커밋 메시지, 그림에 사용자 경로·메일·토큰, 실제 PC·tailnet 이름, IP, 실제 대화 내용을 쓰지 않는다. 커밋 전·푸시 전 검사를 건너뛰지 않는다.
- 화면 글은 영어와 한국어 사전 둘 다 고친다. 한국어 문구는 사전의 지금 말투(`docs/log/korean-copy-review.md`)를 따른다.
- 같은 때 P78 작업자(워크트리 워커 줄, 판 `atrium-dev-p78`, 47898·9378)가 `tree-line.mjs`·`worktrees.mjs`·`branch.mjs`를 고친다. 지휘 세션은 `atrium-dev-p75`(47896·9376)로 합친 코드를 시험한다. 그 포트와 세션은 쓰지 않는다. 맡은 일에 필요한 만큼만 고치고, `styles.css`와 두 사전은 끝에 더해 합치기 쉽게 한다.
- 자기 브랜치에만 커밋한다. 커밋 메시지에 `Co-Authored-By` 줄을 넣지 않는다. `main`이나 `dev`를 바꾸거나 푸시하지 않는다. `node_modules`는 워크트리 안에서 받는다(`npm ci`, 창은 그 뒤 `node node_modules/electron/install.js`).
- 문서는 이 작업 파일의 작업 기록 절과 보고 절만 고친다. 고쳐야 할 ARCH·BRIEF·testing·README 문장은 보고 절에 짧게 적는다. 살아 있는 문서 예산이 거의 찼으니(70,000자 중 69,997자) 문장은 바꾸는 문장보다 길지 않게 적는다.
- 끝나면 보고 절을 쓰고, 맨 마지막에 `<워크트리>/backend/.dev/p77.done`(브랜치 이름, 마지막 커밋 해시, 시험 수 세 줄)을 만든다.
