## 지시

### 목표

덩어리(붙여 묶은 세션)의 크기 막대(가로형·세로형, 16:9·4:3, 크게·보통·작게)를 덩어리 바깥이 아니라 세션 칸 하나하나에 맞춘다.

### 사용자의 말

"레이아웃 기능에서 16:9 4:3 에 대한 종횡비 측정을 가로형/세로형에 대해 dock 전체 테두리 종횡비만 따지다 보니까 사용자 경험이 좀 괴리됨. 예를 들어 (4개 dock - horizontal - 가로형 - 크게 - 16:9) 를 하면 하나하나의 세션은 위로 길어짐. 근데 이런건 내가 세로형에 원하는 건데. 세로형 가로형은 각 세션의 길게 주로를 가지고 명명해야 될거같은데"

지휘 세션이 "크기 단계는 칸마다 단독 세션 크기"와 "덩어리 전체 면적" 가운데 무엇으로 할지 물었고, 사용자는 **칸마다 단독 세션 크기**를 골랐다(2026-11-07).

### 지금(P73)

- 크기는 방향 × 비율 × 단계다(`backend/src/canvas.mjs` `SIZE_TABLE`, `stepSize`, `resolveSize`). 16:9는 1920×1080·1440×810·1040×585, 4:3은 1600×1200·1200×900·880×660, 세로형은 가로·세로를 바꾼다.
- 덩어리는 방향·비율·단계가 덩어리 바깥의 값이다(`docks.aspect`). 칸 크기는 배치 틀(분할 비율, `dock-tree.mjs`)로만 정하고, 덩어리 크기는 바깥 테두리로만 바꾼다(`dragOuter`). 그래서 H 배치 틀 넷에 가로형 16:9 크게를 고르면 바깥이 1920×1080이고 칸 하나는 480×1080으로 세로로 길다.
- 배치 틀로 새로 짠 덩어리의 칸은 `DOCK_CELL` 960×540이다.

### 할 것

1. **칸 기준 규칙.** 덩어리의 방향·비율·단계는 칸 하나의 모양과 크기다. 칸 하나는 같은 값의 단독 세션과 같은 크기다(가로형 16:9 크게면 칸마다 1920×1080). 덩어리 바깥 크기는 배치 틀에서 나온다.
   - 예: H 넷·가로형·16:9·크게 → 칸 1920×1080, 바깥 7680×1080. V 넷·세로형·4:3·보통 → 칸 900×1200, 바깥 900×4800. 2×2·가로형·16:9·보통 → 칸 1440×810, 바깥 2880×1620(바깥도 16:9).
   - 고르지 않은 배치 틀(큰 칸 하나와 작은 칸 둘 등)은 가장 작은 칸이 고른 모양과 크기가 되고, 큰 칸은 작은 칸을 합친 크기가 된다. Ctrl+끌기로 만든 분할 나무처럼 고른 격자가 아닌 나무에서 어떻게 정하는지(잎이 너무 납작해지지 않게) 근거와 함께 보고에 적는다.
2. **크기 막대.** 덩어리를 고르면 막대의 가로형·세로형·비율·단계가 칸 기준임을 보인다(제목 글·도움말). 가로형·세로형은 세션 하나의 긴 쪽 방향이다. 단독 세션의 막대는 그대로다.
3. **바깥 테두리.** 바깥 테두리로 크기를 바꾸면 지금처럼 칸이 함께 커지고 작아지며 비율·단계 단추가 꺼진다.
4. **붙이기·떼기·배치 틀 바꾸기.** 덩어리에 세션을 붙이거나 떼거나 배치 틀을 바꿀 때, 비율·단계가 켜져 있으면 칸 크기를 지키고 덩어리 바깥이 늘거나 준다. 꺼져 있으면(테두리로 바꾼 뒤) 지금처럼 한다. 덩어리가 커지면 P75의 줄 밀기(`reflowLines`)가 뒤 형제를 민다.
5. **이미 있는 판.** 뜰 때 덩어리의 자리와 크기를 바꾸지 않는다. 사람이 막대를 누를 때부터 새 규칙을 쓴다. 옛 `docks.aspect` 값은 그대로 읽힌다.

### 완료 기준

1. 단위 시험을 더하고 통과한다: 위 세 예의 칸·바깥 크기, 고르지 않은 배치 틀, 바깥 테두리 뒤 단추 꺼짐, 붙이기·떼기에서 칸 크기 유지, 이미 있는 판 그대로, 단독 세션 크기 그대로.
2. 창 시험(개발용 판, 셸 넷)으로 H 넷 가로형 16:9 크게, V 넷 세로형, 2×2, 고르지 않은 배치 틀을 찍어 `experiments/p77/`에 둔다. 고치기 전 코드로도 같은 것을 찍어 비교한다.
3. `cd backend && npm test`, `cd app && npm test`, `cd app && npm run build`가 통과한다.

## 보고

### 만든 것

- 규칙: 덩어리의 가로형·세로형, 16:9·4:3, 크게·보통·작게는 칸 하나의 것이고 칸 하나는 같은 값의 단독 세션과 같은 크기다. 바깥은 배치 틀에서 나온다.

  | 덩어리 | 칸 | 바깥 |
  |---|---|---|
  | H 넷 · 가로형 16:9 크게 | 1920×1080 | 7680×1080 |
  | V 넷 · 세로형 4:3 보통 | 900×1200 | 900×4800 |
  | 2 × 2 · 가로형 16:9 보통 | 1440×810 | 2880×1620 |
  | 1 + 3 · 가로형 16:9 보통 | 작은 칸 1440×810, 큰 칸 4320×2430(3 × 3) | 5760×2430 |

- 고르지 않은 나무: 모든 잎이 고른 모양을 지키므로 납작한 잎이 없다. 1 + 2·위 하나 아래 둘·1 + 4·1 + 5는 큰 칸이 작은 칸 2 × 2, 1 + 3은 3 × 3이다. 왼쪽 둘·오른쪽 셋(`cols-2-3`)처럼 높이를 맞추면 정수배가 안 되는 틀은 모양을 지키고 큰 칸이 1.5배다. Ctrl+끌기로 반씩 번갈아 나눈 나무는 큰 칸이 피보나치 수만큼 커진다(잎 다섯이면 한 변 5·3·2·1·1배, 반씩 나눈 넓이로는 8배인 것이 25배). 잎의 모양을 지키는 것을 넓이 비보다 앞에 두었다. 근거: 사용자가 말한 가로형·세로형은 세션 하나의 긴 쪽이라, 큰 칸만 다른 모양이 되면 같은 괴리가 다시 생긴다.
- 크기 막대: 덩어리를 고르면 "칸마다"(넓은 창에서만) 글과 칸 기준 도움말. 불은 가장 작은 칸의 방향·비율·단계. 단독 세션의 막대는 그대로.
- 바깥 테두리: 전처럼 칸이 함께 커지고 비율·단계 불이 꺼진다. 그 뒤 붙이기·떼기·틀 바꾸기는 전과 같다.
- 이미 있는 판: 뜰 때 바꾸지 않는다. 옛 `docks.aspect`는 칸 비율로 읽는다. P73 바깥 기준으로 짠 H 넷(칸 480×1080)은 불이 꺼지고 세로형으로 보이며, 막대를 누르면 새 규칙이 된다. 2 × 2는 칸도 16:9라 불이 그대로다.

### 계획과 다른 곳

- 혼자인 두 노드를 붙일 때 대상에 비율 불이 있으면 덩어리도 칸 기준으로 시작한다(지시에 없음).
- "칸마다" 글은 막대가 넉넉할 때(줄임 0~2단계)만 보인다. 1584 너비 창에서는 줄임 3단계라 도움말로만 보인다.
- 큰 칸이 작은 칸을 모은 크기가 되지 못하는 틀(`cols-2-3`, `top3-bottom2`, `big2-small3`)은 모양을 지키고 1.5배가 된다. 크게·보통 둘 짜리 `main2-left`·`main2-top`은 칸 기준이면 H·V와 같아진다(두 칸 높이·너비가 같아야 하므로).

### 알려진 문제

- 칸 기준 덩어리는 크다(H 넷 크게는 7680 너비, 1 + 3 크게는 7680×3240). 줄 밀기(`reflowLines`)는 같은 줄의 뒤 형제만 아래로 밀고, 옆 노드는 밀지 않는다(P73과 같다).
- 깊은 Ctrl+끌기 나무에서 칸 기준을 고르면 큰 칸이 매우 커진다(위 피보나치).
- `presetSize`는 비율이 꺼진 새 덩어리(시험의 `cellW`·`cellH`)에만 쓰인다.
