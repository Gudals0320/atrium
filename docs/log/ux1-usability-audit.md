## 지시

### 이 파일의 쓰임

사용자가 이 계획("사용성 자율 검증", "ux1")을 언급하면, 지휘 세션이 이 지시대로 작업자 하나를 띄워 **한 번** 돌린다. 그 전에는 돌리지 않는다.
- 돌리기 전 조건: P41·P42·P43이 `main`에 합쳐져 푸시되어 있고, 돌고 있는 작업자 워크트리가 없다.
- **한 번만 한다.** 반복 작업, 예약 작업, CI, git 훅, 스킬로 만들지 않는다(사용자 지시). 다음에 다시 하려면 사용자가 새로 정한다.

### 목표

사용자가 매일 하는 일을 막거나 느리게 만드는 문제를 재현 가능한 증거와 함께 찾아, 그대로 작업 지시가 될 수 있는 GitHub 이슈로 올린다. 많이 찾는 것이 목표가 아니다. 찾고 보고만 하고 고치지 않는다.

사용자와 정한 것(2026-11-05):
1. 범위는 전부 넓게(S1~S9) 본다.
2. 이슈는 검토 없이 바로 올린다. 다음 작업자가 다시 검증한다.
3. 스크린숏은 공개 저장소의 증거 전용 브랜치에 올리고 이슈에서 링크한다.
4. 라벨은 새로 만든다.
5. 지금 돌고 있는 워크트리 작업이 끝난 뒤에 한다.
6. 한 번만 한다. 반복 작업이나 CI로 등록하지 않는다.

### 기준(세 겹)

1. **BRIEF 4절 사용성 원칙**을 확인할 문장으로 쓴다.
   - U1: 상태가 바뀌어도 노드는 움직이지 않고 색과 표시만 바뀐다. 새 노드는 빈자리에 놓이고 다른 노드를 가리지 않는다.
   - U2: 응답 필요는 노드를 옮기지 않고 가리킨다. `N`으로 그 자리로 간다.
   - U3: 응답 필요는 모든 프로젝트를 가로질러 보인다.
   - U4: 연 세션은 모두 캔버스에 보인다. 줄여 보아도 무엇을 묻고 무엇을 요청받았는지 읽히고, 누르면 그 세션으로 간다.
   - U5: 오래 손대지 않은 세션으로 돌아오면 브리핑(마지막 요청, 한 일, 지금 필요한 것)이 있다.
   - U6: 확인할 결과(검토 대기)를 따로 센다.
   - U7: 정리가 또 하나의 일이 되지 않는다(쉬는 세션은 흐리게, 닫은 세션은 보관, 자동 정렬).
   - U8: 마지막 Enter는 사람이 누른다. 종료, 재시작, 시키지 않은 단계는 확인을 받는다.
2. **일반 기준 일곱**
   - H1 발견성: 문서 없이 찾을 수 있는가.
   - H2 피드백: 모든 동작에 결과나 오류가 보이는가.
   - H3 오류 회복과 되돌리기.
   - H4 일관성: 용어, 단축키, 한국어·영어.
   - H5 가림·넘침·잘림.
   - H6 키보드만으로 가는 길.
   - H7 체감 속도.
3. **기능 정확성:** ARCH 4절 기능(A~K)이 적힌 대로 동작하는지 시나리오 안에서 본다.

### 방법

- **격리:** 새 개발용 판과 새 시험 폴더(`C:\Workspace\mtask-ux1-*`)를 쓴다.
  - 대화 목록은 시험 폴더의 대화만 읽는다(`ATRIUM_CLAUDE_PROJECTS`). 데스크톱 앱은 가짜 폴더나 `none`을 쓴다.
  - 실제 판, 실제 대화, 데스크톱 앱 데이터는 쓰지 않는다.
- **에이전트:** claude는 `--model haiku`로 하고 턴은 짧게 한다. deepseek flash는 사용자의 게이트웨이가 떠 있을 때만 한 턴 쓴다.
- **두 가지 방식**
  - **각본:** Playwright로 창을 조작하는 시나리오 스크립트(`app/test/e2e/ux1-*.mjs`)다. 저장소에 남긴다.
  - **탐색:** 목표만 갖고 화면(스크린숏, 접근성 트리)을 보며 해 본다. 찾는 데 몇 번 헤맸는지와 막힌 곳을 적는다.
- **자동 측정:** 겹침·넘침·잘림(P39 측정 방법), 창 콘솔 오류, 백엔드 로그의 오류·경고, 동작에서 화면 반영까지의 시간, 화면 프레임 간격, 세션 20개일 때의 메모리.
- 결과물은 `experiments/ux1/`(git 밖)에 모은다.

### 거르기

- **증거 필수:** 재현 단계와 스크린숏이나 측정값이 있어야 한다. 처음부터 다시 해서 두 번 재현되지 않으면 버린다.
- **심각도**
  - S1: 일을 막거나 데이터를 잃는다.
  - S2: 자주 마주치는 큰 불편이나 틀린 동작이다.
  - S3: 다듬기다.
- **이미 아는 것은 뺀다:** 열린 GitHub 이슈, PLAN의 열린 결정, P36~P43 작업 파일의 "알려진 문제"·"남은 것". 이미 있는 이슈와 겹치면 새 증거가 있을 때만 그 이슈에 댓글을 단다.
- 시나리오에서 실제로 겪은 것만 올린다. 일부러 만든 극단 조건에서만 나는 것은 S3로 내리고 그렇게 적는다.
- **상한:** S1·S2는 이슈 하나에 하나씩, 최대 8개다. 넘으면 심각도와 자주 겪는 정도로 자르고, 나머지는 보고 절에만 적는다. S3는 "UX polish (ux1)" 이슈 하나에 체크리스트로 묶는다.

### 이슈

- 저장소 `Gudals0320/atrium`에 `gh`로 올린다. 검토 없이 바로 올린다(사용자 지시).
- **글:** 영어로, 인사말이나 감사 없이 필요한 말만 쓴다. 제목은 증상 한 줄이다.
- **몸글 순서:** Summary, Steps to reproduce, Expected, Actual, Evidence(스크린숏 링크, 측정값), Environment(커밋, Windows, herdr 버전, 창 크기·배율·언어), Severity, Area, Principle(U·H 번호), Suggested direction.
- **라벨:** 처음에 없는 것만 만든다.
  - `ux`
  - `severity:S1`, `severity:S2`, `severity:S3`
  - `area:canvas`, `area:terminal`, `area:workers`, `area:sessions`, `area:chrome`, `area:i18n`, `area:recovery`
  - 기존 `bug`, `enhancement`, `accessibility`도 맞으면 단다.
- **공개 안전**
  - 이슈 글을 파일로 쓰고 `node scripts/check-public.mjs --message <파일>`로 검사한 뒤 올린다.
  - 스크린숏은 Atrium 창만 찍는다. 시험 데이터만 보이고, 사용자 경로, 실제 대화, 다른 앱 창은 보이지 않게 한다.
- **증거 브랜치**
  - `ux-evidence`는 `main`과 이력을 잇지 않는 orphan 브랜치다.
  - 파일은 `ux1/<영역>-<n>.png`로 두고, 한 장에 300KB 이하로 줄인다.
  - 푸시하면 공개 검사 훅이 돈다.
  - 이슈의 이미지 주소는 `https://raw.githubusercontent.com/Gudals0320/atrium/ux-evidence/ux1/<파일>`이다.
- 올린 뒤 이슈 번호와 링크를 이 파일 보고 절의 표에 적는다.

### 하지 않을 것

- 고치지 않는다. 코드는 시나리오 스크립트와 측정 도구만 더한다.
- 반복 작업, 예약, CI, git 훅, 스킬로 만들지 않는다.
- 실제 판(`atrium`, 47800), 사용자 세션, 기본 herdr 세션은 건드리지 않는다. 신뢰 대화상자를 대신 수락하지 않는다. opencodex 설정은 고치지 않는다.
- `main`은 바꾸거나 푸시하지 않는다. 푸시는 `ux-evidence` 브랜치만 한다.

### 완료 기준

1. S1~S9를 모두 돌렸다. 시나리오마다 통과한 것, 발견한 것, 보지 못한 것을 보고 절 표에 적었다.
2. 거른 이슈가 라벨과 증거 링크를 달고 올라갔다. 보고 절에 이슈 표(번호, 제목, 심각도, 영역, 원칙)가 있다.
3. 시나리오 스크립트가 작업자 브랜치에 커밋되어 있다. `cd app && npm test`와 `cd app && npm run build`가 통과한다.

### 지킬 것

- `CLAUDE.md`를 따른다. 프로세스는 직접 띄운 것만 PID로 끈다.
- 이 저장소는 공개다. 작업 기록, 시험 코드, 커밋 메시지, 이슈 글, 스크린숏에 사용자 경로·메일·토큰을 넣지 않는다. 커밋 전·푸시 전 검사를 건너뛰지 않는다.
- 자기 브랜치에만 커밋한다. 커밋 메시지에 `Co-Authored-By` 줄을 넣지 않는다. `node_modules`는 워크트리 안에서 받는다(`npm ci`).
- 문서는 이 작업 파일의 작업 기록 절과 보고 절만 고친다.
- 끝나면 보고 절을 쓰고, 맨 마지막에 `<워크트리>/backend/.dev/ux1.done`(브랜치 이름과 마지막 커밋 해시 두 줄)을 만든다.

### 지휘 세션이 할 일(돌릴 때)

1. 조건을 확인한다: P41~P43 합침, 돌고 있는 워크트리 없음, `main` 푸시.
2. 비어 있는 다음 포트를 정해 "시험 환경"에 적고, 커밋하고 푸시한다(`claude -w`는 `origin/main`에서 워크트리를 만든다).
3. `claude --model claude-opus-5-5 --effort high -w ux1 '<이 파일을 읽고 지시대로 하라>'`로 띄우고, `ux1.done`을 기다린다.
4. 끝나면 올라간 이슈를 확인하고, 시나리오 스크립트 브랜치를 합치고, 이 파일을 닫는다.
