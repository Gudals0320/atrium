## 지시

### 목표

휴대폰(터치)에서 보드 화면(캔버스)을 쓸 수 있게 한다. 지금은 세션을 누르고 끌면 화면이 튕기는 등 쓸 수 없다.

### 사용자의 말

"핸드폰에서 기본화면이 그냥 세션 목록이네? 뭐 나쁘진 않은거같은데.. 근데 우측상단 canvas 나가서 세션 누르고 드래그하면 튕기는 등 아직 사용 불가능"

사용자는 iPhone Safari(또는 홈 화면 앱)로 원격 판에 붙는다. P74가 만든 휴대폰 화면(세션 목록)은 괜찮다고 했다. 문제는 목록 머리줄 오른쪽 위 단추(`data-action="phone-board"`, "보드 화면으로 보기")로 간 보드 화면이다. 휴대폰을 가로로 돌렸을 때와 태블릿도 같은 보드 화면을 쓴다.

### 할 것

1. **먼저 재현하고 원인을 찾는다.** Playwright 휴대폰 흉내(iPhone 크기, `isMobile`, `hasTouch`)와 CDP 터치 이벤트(`Input.dispatchTouchEvent`, 한 손가락 끌기, 두 손가락 벌리기)로 보드 화면에서 세션을 누르고 끌어 본다. "튕김"이 무엇인지 적는다. 예: 노드 끌기와 판 옮기기가 다투는 것, 눌러서 확대(P73)가 끌기 도중에 끼어드는 것, 터미널(xterm)이 터치를 먹는 것, 페이지가 스크롤·확대되는 것(iOS 고무줄), 노드를 누르면 휴대폰 화면 밖 터미널 초점이 잡히는 것.
2. **터치 규칙.** 터치로 쓰는 보드 화면은 다음처럼 움직이게 한다. 마우스 보드(PC 창, 노트북 브라우저)는 바꾸지 않는다.
   - 한 손가락 끌기: 어디서 시작해도(노드 위, 터미널 위 포함) 판을 옮긴다.
   - 두 손가락 벌리기·오므리기: 확대·축소. 페이지 자체는 확대되거나 스크롤되지 않는다(`touch-action`, `overscroll-behavior`, viewport).
   - 노드를 짧게 누르기(탭): 그 세션을 휴대폰 세션 화면(P74의 전체 화면 터미널과 입력 줄)으로 연다. 돌아오면 보드 화면의 같은 자리로 온다. 가로 보드 화면처럼 휴대폰 세션 화면이 없는 폭이면 지금처럼 그 노드로 확대한다.
   - 노드를 길게 누른 뒤 끌기: 노드(덩어리면 덩어리)를 옮긴다. 길게 누름이 잡히면 짧게 진동하거나 테두리로 알린다. 실수로 옮겨지지 않게 길게 누름 시간은 0.5초 안팎으로 한다.
   - 눌러서 확대(P73)는 터치에서 끈다(탭이 위 규칙을 따른다).
   - 터치 보드 화면에서는 터미널에 글을 치지 않는다(입력은 휴대폰 세션 화면에서 한다). 터미널 글이 터치를 가로채지 않게 한다.
3. **휴대폰 보드 화면의 크롬.** 좁은 폭에서 위·아래 알약과 레일이 판을 가리면 줄이거나 접는다. "휴대폰 화면"으로 돌아가는 단추는 늘 보인다. 바꾼 것을 보고에 적는다.

### 완료 기준

1. 단위 시험을 더하고 통과한다: 터치 판단, 탭·길게 누름·끌기 가르기, 길게 누름 시간, 마우스 보드가 그대로인 것.
2. 창 시험(개발용 판의 원격 웹 화면, 휴대폰 흉내, P74의 `app/test/e2e/p74-mobile.mjs`와 가짜 Tailscale을 본떠서)으로 다음을 확인하고 전후 스크린숏을 `experiments/p76/`에 둔다.
   - 고치기 전 코드에서 튕김을 재현한 그림이나 수치.
   - 고친 뒤: 노드 위 한 손가락 끌기는 판만 옮기고 노드 자리는 그대로다. 두 손가락으로 확대·축소하고 페이지 스크롤과 확대는 0이다. 탭하면 휴대폰 세션 화면이 열리고 돌아오면 같은 자리다. 길게 눌러 끌면 노드가 옮겨진다(판 기록의 자리가 바뀜).
   - 노트북 크기 마우스 보드에서 지금처럼 노드를 끌고 판을 옮길 수 있다.
3. `cd backend && npm test`, `cd app && npm test`, `cd app && npm run build`가 통과한다.

## 작업 기록

- 시작: `git fetch origin && git merge --ff-only origin/dev`(9fbf98a). 워크트리 안에서 `npm ci`(백엔드, 창)와 Electron 받기. 물려받은 판 변수를 지우는 `backend/.dev/clean-env.sh`와, 지운 뒤 이 판의 값(atrium-dev-p76, 47897, `backend/.dev/data`, `backend/.dev/app`)만 넣는 `backend/.dev/p76.sh`를 만들어 모든 시험, 빌드, CLI, herdr 명령을 그것으로 부른다(git 밖).
- 2026-11-06 바뀐 지시(사용자의 말: "세션별 보기 말고 폰에서도 무한캔버스 기본으로 가자. 대신 클릭하면 확대를 전체보기로 확 보여주고 타이핑 수 있게 하고 ctrl c 같은 특수키들 하단에만 만들어주는거야. 타자 키 올라오면 알아서 화면도 올라가게"). 할 것 2의 탭 규칙을 바꾸고 다음을 더한다.
  1. 휴대폰의 기본 원격 화면은 P74 세션 목록이 아니라 무한 캔버스(보드 화면)다. 세션 목록은 작은 단추 하나로 갈 수 있게 남긴다.
  2. 노드를 탭하면 그 세션이 휴대폰 화면 전체(아래 키 줄 위)를 채우게 확대하고(전체 보기), 그 자리에서 그 세션에 입력한다. P74의 따로 된 세션 화면은 열지 않는다. 전체 보기에서 나오는 길은 바깥 탭, 뒤로 가기 동작, 두 손가락 오므리기다.
  3. 특수 키(Esc, Ctrl+C, 화살표, Tab, Shift+Tab, Enter, `/`)는 화면 아래 줄에만 둔다. 전체 보기에서 세션 위에 다른 떠 있는 단추를 두지 않는다.
  4. 화면 키보드가 올라오면 화면이 저절로 올라가 세션의 아래 줄과 키 줄이 키보드 위에 보인다(visualViewport).
  5. iPhone의 한글 IME(조합)로 입력할 수 있어야 한다. 터미널에 바로 치거나 키 줄에 붙은 얇은 입력 줄을 쓴다. 되는 쪽을 고르고 이유를 보고에 쓴다.
  - 한 손가락 끌기(판 옮기기), 두 손가락 확대·축소, 길게 눌러 옮기기는 그대로 둔다. 휴대폰 흉내에서 새 흐름(기본 캔버스, 탭해 전체 보기, 키보드를 올린 채 입력, 키 줄, 전체 보기 나오기)을 시험한다.
- 재현(고치기 전 코드, `P76_STAGE=before`): 390×844 휴대폰 흉내, 노드(1440×810)를 배율 0.55 가까이 얼굴로 두고 CDP 터치를 보냈다. 첫 실행은 머리줄 가운데가 화면 밖(x 416)이라 아무것도 일어나지 않았고, 화면 안 자리로 고쳐 다시 쟀다.
  - 머리줄 한 손가락 끌기(−80, +160px): 판은 0, 노드가 판 좌표로 (−133, +265) 옮겨지고 판 기록에 남았다. 판을 옮기려던 손가락이 노드를 끌고 간다.
  - 터미널 위 끌기: 판 0, 노드 0. 터미널 칸(`nodrag nowheel nopan`)이 손가락을 먹는다.
  - 터미널 위 두 손가락 벌리기·오므리기: 배율 0.55 그대로(같은 까닭). 페이지 확대·스크롤은 흉내에서 0.
  - 짧게 누르기: 화면이 확 옮겨지고(배율 0.55 → 0.264, 판 (+34, +134)) 터미널 초점(`xterm-helper-textarea`)이 잡혔다. iPhone에서는 여기서 화면 키보드가 올라온다. 고른 노드 막대(크기 단추 줄)가 위를 덮는다.
  - 눌러서 확대된 뒤 터미널 위 끌기: 판 0, 터미널 초점 그대로. 그림 `experiments/p76/before-*.png`, 수치 `before` 결과 파일.
  - 튕김 = 손가락이 판 대신 노드를 끌고 가고, 터미널 위에서는 아무것도 안 되며, 누르면 화면이 튀고 키보드가 올라오는 것.
- 설계 결정:
  - 판의 터치는 `.mt-canvas`가 캡처 단계에서 모두 받아(`preventDefault`, `stopPropagation`) React Flow(d3-zoom·d3-drag)와 xterm에 넘기지 않는다. 마우스 흉내 이벤트·click·초점도 함께 막히므로 탭은 직접 가른다(단추는 `click()`, 입력칸은 `focus()`, 메모·영역·빈 판은 그 자리에 click을 보낸다).
  - 길게 눌러 옮기기는 마우스 끌기의 `onNodeDragStart`·`onNodesChange`·`onNodeDragStop`을 그대로 불러, 덩어리째 옮기기·붙이기·겹침 되돌리기·저장이 마우스와 같다.
  - 전체 보기는 캔버스를 확대하지 않고 판 위에 덮어 그린다. 노드(가로로 긴 1440×810)를 세로 화면에 맞추면 화면의 3분의 1만 채우고 글자가 7px쯤이 되기 때문이다. 대신 노드의 화면 자리에서 화면 전체로 커지는 움직임(170ms)을 넣었다. 판의 뷰포트는 건드리지 않아 나오면 같은 자리다.
  - 한 창이 한 패널을 두 번 붙이지 않게, 전체 보기 세션은 판의 제어기 목록에서 빼고 200ms 뒤에 전체 보기가 붙인다.
  - 키보드가 올라오면 터미널 높이(패널 줄 수)는 그대로 두고 위쪽을 가린다(패널 크기가 바뀌어 Claude Code가 다시 그리는 것을 피한다). 처음에는 늘 아래 끝을 맞췄는데 새 셸은 프롬프트가 맨 위라 보이지 않았다(그림 `after-09`의 첫판). 글이 있는 마지막 줄(커서 줄 포함)이 입력 줄 바로 위에 오도록 올리는 양을 정했다(`kbShift`).
  - 키 줄 열 개가 한 줄에 들어가지 않아(Enter가 화면 밖) 키를 고르게 나누고 글자 크기 A−·A+는 위 띠로 옮겼다.
- 시험을 돌리며 고친 것: 판이 손가락보다 8px 덜 따라옴(끌기 판단 순간 시작점을 다시 잡았다 → 처음 누른 자리 기준), 시험의 끄는 방향이 옆 노드 가장자리에 닿아 붙음(마우스와 같은 붙이기 규칙, 시험 방향을 바꿈), 가로 탭 시험이 "이미 보고 있으면 움직이지 않는다"(P26)에 걸림(시작 배율을 0.15로), 위 크롬 두 덩어리가 겹침(위 왼쪽을 숨기고 위 오른쪽을 왼쪽부터 한 줄로).

### 터치 규칙(`lib/touch-board.js`, `Canvas.jsx`)

- 판(`.mt-canvas`)이 손가락 이벤트를 캡처 단계에서 모두 받고 React Flow·터미널에 넘기지 않는다. 마우스는 이 길로 오지 않아 PC 창과 노트북 브라우저는 그대로다. 터치 화면 PC 창에서 손가락을 쓰면 같은 규칙을 따른다.
- 한 손가락: 누른 자리에서 8px 넘게 움직이면 판 옮기기(노드·터미널 위에서 시작해도). 0.5초 움직이지 않으면 길게 누름(테두리, 진동을 지원하면 짧게 진동). 그 뒤 끌면 노드를 옮긴다(덩어리 안 노드면 덩어리째, 붙이기·겹침 되돌리기·저장은 마우스와 같다). 0.5초 전에 떼면 탭.
- 두 손가락: 두 손가락 가운데를 축으로 확대·축소(0.05~2)하고 가운데가 움직인 만큼 판도 옮긴다. 한 손가락을 떼면 남은 손가락으로 이어서 옮긴다.
- 탭: 노드 안 단추·입력칸이면 그것을 누른다(닫기, ⋯, 승인 카드 단추 등). 세션 노드면 휴대폰 세로는 전체 보기, 가로·태블릿은 그 노드로 확대(화면만, 터미널 초점 없음). 메모·칸반·대화 노드, 영역 이름표, 빈 판은 그 자리를 누른 것으로 넘긴다. 눌러서 확대(P73)는 터치에서 쓰지 않는다.
- 손가락 기기에서는 판의 터미널 입력칸에 `inputmode="none"`을 두고, 터치가 시작되면 터미널 초점을 푼다. 화면 키보드가 판에서 올라오지 않는다.
- 페이지: 터치 보드에서는 `body`를 고정하고 `overscroll-behavior: none`, `touch-action: none`, 캔버스 밖 크롬 위의 두 손가락 `touchmove`와 iOS `gesturestart`를 막는다(iOS Safari는 viewport의 확대 막기를 무시한다).

### 전체 보기(`PhoneFull.jsx`, `full-view.js`)

- 휴대폰 세로에서 세션 노드를 탭하면 판 위에 덮어 그린다. 노드 자리에서 화면 전체로 커지는 움직임(170ms). 판의 뷰포트는 그대로라 나오면 같은 자리다. 기록 한 칸을 더해 뒤로 가기(가장자리 밀기, Android 뒤로 단추)로 나온다.
- 위 띠(세션 바깥): 상태 점, 이름, 상태, "탭하면 보드로", 글자 크기 A−·A+. 띠를 탭하면 나온다. 두 손가락 오므리기(거리가 70% 아래)로도 나온다.
- 터미널: 화면 폭 전체, 휴대폰 글자 크기(P74와 같은 값과 저장 키), DOM 렌더러. 이 휴대폰이 패널 크기를 가져간다(P47 초점). 손가락으로 끌면 스크롤(휠), 탭하면 입력 줄에 초점(키보드). 터미널 자체는 손가락·키보드를 받지 않는다. 잠든 세션은 깨우기 단추, 끝난 세션은 안내.
- 아래: 얇은 입력 줄과 키 줄 하나(Esc, ^C, Tab, ⇧Tab, ↑, ↓, ←, →, /, ⏎, 한 줄에 다 들어간다). 키는 입력 줄 초점을 빼앗지 않아 키보드가 내려가지 않는다. ⏎는 입력 줄에 글이 있으면 그 글을 보내고, 비었으면 Enter. 화살표는 터미널의 응용 커서 모드를 따른다.
- 키보드: 보이는 높이(visualViewport)에 전체 보기를 맞춰 입력 줄과 키 줄이 키보드 바로 위에 온다. 터미널 높이(패널 줄 수)는 그대로 두고 위쪽을 가린다. 글이 있는 마지막 줄(커서 줄 포함)이 입력 줄 바로 위에 보이도록 올린다(Claude Code처럼 아래까지 그린 화면은 아래 줄, 새 셸처럼 위쪽에만 있으면 위쪽 그대로). 출력이 오면 250ms마다 다시 잰다.
- 승인 카드는 전체 보기에 두지 않았다(세션 위 떠 있는 것을 두지 않는다는 지시). Claude Code의 승인 화면은 터미널 안에 있으므로 ↑↓⏎, Esc로 답한다. 판의 노드에는 지금처럼 승인 카드가 있다.

### 한글 입력: 입력 줄을 고른 이유

얇은 입력 줄(보통 `textarea`)에 쓰고 Enter에 터미널로 친다. 터미널에 바로 치는 길은 고르지 않았다.
- 입력 줄은 브라우저의 보통 입력칸이라 조합을 브라우저와 OS 키보드가 끝까지 맡는다. 판은 확정된 글만 읽는다. iOS 한글 키보드는 조합 이벤트 대신 글을 지우고 다시 넣는 식으로 고칠 때가 있는데, 그 과정도 입력칸 안에서만 일어난다.
- 터미널에 바로 치면 xterm의 숨은 입력칸과 조합 도우미를 거친다. P74에서 피한 한글 IME와 xterm의 충돌(겹친 글자, 빠진 받침)이 그대로 남고, 조합 중간 글자(ㅎ, 하)를 터미널에 보냈다가 지우는 식이 되어 셸과 Claude Code 입력 상자에 깜빡임과 어긋남이 생긴다.
- 보내기: 글을 터미널 입력으로 치고 150ms 뒤 Enter(백엔드가 `/exit` 등을 보낼 때와 같은 간격). 여러 줄이면 괄호 붙여넣기로 감싼다. 조합을 확정하는 Enter(`isComposing`, keyCode 229)와 Shift+Enter는 보내지 않는다. 에이전트에게도 전달 대기열(`session.send`)이 아니라 터미널에 바로 친다. 대기열은 승인·질문을 기다리는 동안 보내지 않아 "1"이나 "y" 같은 답을 칠 수 없기 때문이다.

### 휴대폰 보드 화면의 크롬(바꾼 것)

- 위 왼쪽(사이드바 단추, 프로젝트 탭, 검색)은 숨기고, 위 오른쪽 알약은 0.82배로 줄여 왼쪽부터 한 줄로 둔다. 그중 메모리 알약과 변경 기록 단추는 숨긴다(내 차례, 검토, 문제, 연결, 설정은 남는다).
- 오른쪽 레일, 고른 노드 막대, 배율 알약(두 손가락으로 확대), 왕복 지연 글은 숨긴다. 왼쪽 레일(런처, 메모·칸반, 전체 보기)은 0.72배.
- 오른쪽 위에 세션 목록 단추(40px, 늘 보인다). 목록 화면(P74)의 머리줄 보드 단추로 돌아온다. P74의 "휴대폰 화면" 알약은 없앴다.
- 시험 화면에서 크롬이 가리는 넓이는 판의 8%.

### 계획과 다른 곳

- 탭의 전체 보기는 캔버스 배율을 바꾸는 확대가 아니라 판 위에 덮어 그린 화면이다(이유는 작업 기록). 노드 자리에서 커지는 움직임으로 확대처럼 보이게 했다.
- "두 손가락으로 나오기"는 오므리기(손가락을 모음)로 했다.
- 글자 크기 A−·A+를 키 줄에서 위 띠로 옮겼다(키 줄은 특수 키만).
- P74 창 시험 `p74-mobile.mjs`를 고쳤다. 짝 맺은 뒤 보드 화면이 뜨므로 목록 단추를 거쳐 목록으로 가고, 9절의 "휴대폰 화면" 알약 대신 목록 단추를 누른다.

### 알려진 문제와 사용자가 iPhone에서 볼 것

- 실제 iPhone Safari·홈 화면 앱에서는 보지 못했다(Chromium 휴대폰 흉내, CDP 터치·IME, 가짜 visualViewport). 볼 것: (1) 노드·터미널 위 한 손가락 끌기가 판만 옮기는지, 페이지가 고무줄로 튀지 않는지, (2) 두 손가락으로 판만 확대되고 페이지는 확대되지 않는지, (3) 0.5초 길게 눌러 테두리가 켜지고 끌면 노드가 옮겨지는지(iOS는 진동이 없다), (4) 탭하면 전체 보기가 열리고 위 띠 탭·가장자리 밀기·오므리기로 나오는지, (5) 터미널을 탭하면 입력 줄에 키보드가 올라오고 입력 줄·키 줄과 터미널 아래 줄이 키보드 위에 보이는지, (6) 한글로 "안녕하세요"를 쳐 Enter로 보냈을 때 터미널에 그대로 들어가는지, (7) 키 줄을 눌러도 키보드가 내려가지 않는지.
- Android Chrome은 `interactive-widget=resizes-content`라 키보드가 창 높이를 줄인다. 그때는 키보드를 알아채지 못해 터미널 줄 수가 줄어든다(패널 크기가 바뀐다). 흉내로는 보지 못했다.
- 전체 보기를 열면 그 패널 크기가 휴대폰 폭(50칸쯤)으로 바뀐다(P74 세션 화면과 같다). PC가 같은 패널을 보면 P47처럼 비율로 줄여 그리고, PC에서 입력하면 PC 크기로 돌아온다.
- 터치로는 영역 이름표를 끌어 영역째 옮기지 못하고, 덩어리에서 한 노드만 끌어내기(마우스의 Alt·Ctrl 끌기)도 없다. 판 위 승인 카드 안의 긴 내용은 손가락으로 스크롤되지 않고 판이 옮겨진다.
- 메모·칸반을 탭할 때는 그 자리에 click을 보낸다. 메모 편집 같은 노드 안 동작은 이번 시험에서 보지 않았다.

### 고쳐야 할 문서 문장(제안)

- ARCH 원격 절의 P74 줄을 고쳐: "웹 화면은 휴대폰에서도 보드 화면이 기본이다. 터치는 판이 받아 한 손가락 끌기는 판 옮기기, 두 손가락은 확대·축소, 길게 누른 뒤 끌기는 노드 옮기기, 탭은 휴대폰 세로면 전체 보기(`PhoneFull.jsx`: 세션 하나, 입력 줄, 특수 키 줄), 그 밖이면 그 노드로 확대한다(`lib/touch-board.js`). 세션 목록(`Phone.jsx`)은 보드 화면의 목록 단추로 간다."
- BRIEF 원격 행(P74 줄)에: "휴대폰도 기본은 보드 화면이고, 노드를 탭하면 그 세션 하나를 화면 가득 보고 입력 줄과 특수 키 줄로 입력한다(2026-11-06, P76)."
- testing.md 원격 창 시험 줄에: "휴대폰 터치 시험(`p76-touch.mjs`)은 CDP `Input.dispatchTouchEvent`(id로 두 손가락), 한글 조합은 `Input.imeSetComposition`과 `Input.insertText`, 가상 키보드는 `visualViewport`를 바꿀 수 있는 가짜로 흉내 낸다. 끄는 방향이 옆 노드 가장자리에 닿으면 붙이기가 일어나니 빈 쪽으로 끈다. P74 시험은 `MT_E2E_HERDR_SESSION`·`MT_E2E_PORT`·`MT_E2E_SIM_PORT`·`MT_E2E_SIM2_PORT`·`P74_PROJ`로 다른 판에서 돌린다."
- README(원격 접속 절)에: "휴대폰에서는 보드를 손가락으로 옮기고(두 손가락으로 확대), 세션을 탭하면 화면 가득 보고 아래 입력 줄과 특수 키(Esc, Ctrl+C, 화살표 등)로 입력한다. 세션 목록은 오른쪽 위 단추."
