## 지시

### 목표

세션 크기, 덩어리(dock)의 종횡비와 배치, 고른 노드 막대, 눌러서 확대를 사용자가 말한 대로 바꾼다.

### 할 것

1. **크기 단계를 종횡비에서 만든다.** 크기는 방향(가로·세로) × 종횡비(16:9·4:3) × 단계(크게·보통·작게)로 정한다. 세로는 가로를 돌린 것이다(16:9 세로 = 9:16, 4:3 세로 = 3:4). 단계마다 가로와 세로가 함께 커지고 작아진다.
   - 시작 값(배율 1의 노드 크기, 시험해 보고 고친다): 16:9 가로 크게 1920×1080, 보통 1440×810, 작게 1040×585. 4:3 가로 크게 1600×1200, 보통 1200×900, 작게 880×660. 세로는 가로·세로를 바꾼 값.
   - 작게도 터미널이 읽히는지(14px 글자로 세로형 55칸 이상) 확인한다. 고친 값과 까닭을 보고에 적는다.
   - 지금 쓰는 `SIZE_STEPS`(`backend/src/canvas.mjs`)의 다른 쓰임(정리 `arrange`, 노드 메뉴)도 새 값에 맞춘다.
2. **새 세션 크기.** 새로 띄운 세션(레일, 대화상자, `atrium child`, 대화 다시 열기)은 16:9 가로 보통으로 놓는다. 이미 판에 있는 노드는 사람이 바꾸기 전까지 크기를 바꾸지 않는다.
3. **종횡비 토글.** 고른 노드 막대에 16:9·4:3 단추 둘을 둔다. 하나를 누르면 그 비율이 되고 다른 하나는 꺼진다.
   - 덩어리는 덩어리 바깥 사각형의 비율이다(칸 하나하나의 비율이 아니다). 칸은 배치 틀의 비율대로 나눈다.
   - 비율을 바꿀 때는 지금 크기 단계(넓이)를 지킨다. 사람이 테두리를 끌어 크기를 바꾸면 두 단추 모두 꺼진다(자유 비율). 그 뒤 단추를 누르면 다시 그 비율로 맞춘다.
   - 노드(덩어리)마다 고른 비율을 판 기록에 남겨 다시 켜도 단추 불이 맞게 한다.
4. **덩어리 안 크기 조절 빼기.** 덩어리 안 분할선 끌기를 없앤다. 칸 크기는 배치 틀로만 정한다. 덩어리 크기 조절은 덩어리 바깥 테두리 끌기로만 하고, 칸은 비율대로 함께 커진다.
   - 이미 손으로 비율을 바꾼 덩어리는 그 비율을 그대로 두고, 배치 틀을 고르면 틀의 비율로 바뀐다.
5. **배치 틀 H·V.** 세션 수와 상관없이 모두 가로로 한 줄(H)과 모두 세로로 한 줄(V)인 배치 틀을 더한다. 칸이 많아 그림이 어려우면 `H`·`V` 글자 단추로 보인다.
6. **고른 노드 막대를 혼자인 세션에도.** 세션 하나를 고르면 막대에 가로/세로, 크게/보통/작게, 16:9/4:3을 보인다(배치 틀은 없음). 덩어리를 고르면 지금처럼 배치 틀도 보인다. 막대가 좁을 때 접히는 규칙(`selbar.js`)을 새 단추에 맞춘다.
7. **눌러서 확대.** 세션을 누르고 가만히 있으면 잠시 뒤 그 세션으로 확대한다. 이때 세션이 화면을 지금보다 더 꽉 채우게 한다. 위·아래 고정 크롬(알약 줄, 아래 칩 줄)은 가리지 않는 선에서 둘레 여백을 줄인다. 바꾼 여백 값을 보고에 적는다.

### 완료 기준

1. 단위 시험을 더하고 통과한다: 크기 표(방향 × 비율 × 단계), 비율 바꾸기의 넓이 지키기, 테두리 끌기 뒤 비율 꺼짐, 덩어리 비율과 칸 나누기, H·V 틀, 혼자인 노드의 막대 항목, 확대 여백.
2. 창 시험(개발용 판, 셸과 haiku 세션)으로 다음을 찍어 `experiments/p73/`에 둔다.
   - 새 세션의 크기.
   - 혼자인 세션 막대로 가로·세로 × 16:9·4:3 × 크게·보통·작게.
   - 넷짜리 덩어리의 16:9↔4:3, 테두리 끌기 뒤 단추 꺼짐, H·V 틀.
   - 덩어리 안 분할선이 끌리지 않는 것.
   - 눌러서 확대 전후.
3. `cd backend && npm test`, `cd app && npm test`, `cd app && npm run build`가 통과한다.

### 시험 환경

- 이 작업은 `dev` 브랜치에서 시작한다. 워크트리를 연 뒤 먼저 `git fetch origin && git merge --ff-only origin/dev`를 한다(워크트리가 `main`에서 시작할 수 있다).
- 개발용 판은 너만의 판으로 띄운다(`docs/testing.md`).
  - `ATRIUM_HERDR_SESSION=atrium-dev-p73`, `ATRIUM_PORT=47893`, 창의 원격 디버깅 포트 9373
  - `ATRIUM_DATA_DIR=<워크트리>/backend/.dev/data`, `ATRIUM_APP_USERDATA=<워크트리>/backend/.dev/app`
- 실제 판(`atrium`, 47800)과 다른 판의 포트는 쓰지 않는다. 사용자의 기본 herdr 세션, 실제 판의 herdr 세션(`atrium`), 다른 판의 herdr 서버는 건드리지 않는다. 사용자의 실제 판은 열지도 캡처하지도 않는다.
- 너는 사용자의 실제 판 위에서 도는 워커다. 실제 판의 API(47800)와 `atrium` 명령으로 실제 판을 바꾸지 않는다. 시험의 `atrium` CLI는 늘 개발용 판 환경 변수(`ATRIUM_PORT` 등)를 주고 부른다.
- 실제 설치 폴더(`%LOCALAPPDATA%\atrium\versions`)와 실제 데이터 폴더(`%LOCALAPPDATA%\atrium`)는 읽지도 바꾸지도 않는다.
- 대화 목록은 시험 폴더의 대화만 읽는다(`ATRIUM_CLAUDE_PROJECTS`, `ATRIUM_CLAUDE_DESKTOP=none`). 시험 폴더는 `C:\Workspace\mtask-p73-*`처럼 새로 만든다.
- 세션은 `claude --model haiku`와 셸로 띄운다.
- 끝나면 시험 세션, 창, 브라우저, 백엔드, herdr 서버와 세션(`atrium-dev-p73`만), 시험 폴더를 끄고 지운다. 네가 띄운 프로세스가 남지 않았는지 포트로 확인한다.

### 지킬 것

- `CLAUDE.md`를 따른다. 프로세스는 직접 띄운 것만 PID로 끈다.
- 이 저장소는 공개다. 작업 기록, 시험 코드, 커밋 메시지, 그림에 사용자 경로·메일·토큰, 실제 PC·tailnet 이름, IP, 실제 대화 내용을 쓰지 않는다. 커밋 전·푸시 전 검사를 건너뛰지 않는다.
- 화면 글은 영어와 한국어 사전 둘 다 고친다. 한국어 문구는 사전의 지금 말투(`docs/log/korean-copy-review.md`)를 따른다.
- 같은 때 다른 작업자(P71(작은 고침), P72(기본 호출자와 Codex 모델), P74(휴대폰 화면과 웹앱))가 돈다. 맡은 일에 필요한 만큼만 고치고, `styles.css`와 두 사전은 끝에 더해 합치기 쉽게 한다.
- 자기 브랜치에만 커밋한다. 커밋 메시지에 `Co-Authored-By` 줄을 넣지 않는다. `main`이나 `dev`를 바꾸거나 푸시하지 않는다. `node_modules`는 워크트리 안에서 받는다(`npm ci`, 창은 그 뒤 `node node_modules/electron/install.js`).
- 문서는 이 작업 파일의 작업 기록 절과 보고 절만 고친다. 고쳐야 할 ARCH·BRIEF·testing·README 문장은 보고 절에 짧게 적는다.
- 끝나면 보고 절을 쓰고, 맨 마지막에 `<워크트리>/backend/.dev/p73.done`(브랜치 이름과 마지막 커밋 해시 두 줄)을 만든다.
