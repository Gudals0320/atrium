## 지시

### 목표

터미널 노드에서 글을 고르고 복사하는 것을 웹 페이지처럼 되게 한다. P38은 배율 아래 칸 어긋남은 고쳤다. 대신 복사·휠·화면 바뀜 뒤에 선택을 지우는 쪽을 골랐고, 사용자는 그것이 답이 아니라고 했다. 사용자의 말은 다음과 같다.
- "복사가 안 되는데, 아직."
- "드래그하고 스크롤하면 선택이 풀려. 이는 제대로 된 해결책이 아니다."
- "드래그해서 창 하단으로 끌면 cli 창이 알아서 밑으로 내려가고."
- "드래그하고 스크롤하면 드래그한 부분도 같이 이동하고."
- "드래그 끌고 있는 상태로 스크롤하면 내 선택 범위도 밑으로 쭉쭉 내려가야지. 웹처럼."

지금의 사정은 다음과 같다(P38 보고, ARCH 7.2, E4).
- 터미널 노드의 화면은 herdr가 자기 화면 모델을 다시 그린 프레임이고, xterm의 scrollback은 0이다.
- 휠은 SGR 마우스 시퀀스로 바뀌어 Claude Code 전체 화면 렌더러가 스스로 대화를 스크롤한다. 그래서 xterm은 글이 위아래로 움직였다는 것을 모르고, 선택은 칸에 붙어 있다.
- P38은 그 때문에 선택을 지운다(`clearsSelection`: 복사, 붙여넣기, 휠, 고른 자리의 글이 바뀜).
- Claude Code가 일하는 동안에는 상태 줄과 스피너가 계속 바뀐다. 그래서 고른 곳이 그 줄에 걸리면 복사하기 전에 지워질 수 있다. "복사가 안 된다"의 원인일 가능성이 크다.
- 셸 노드(PowerShell)는 SGR 휠을 무시해서, 휠로 지난 출력을 올려 볼 수도 없다.

### 할 것

1. **재현.** 개발용 판에서 claude 노드(일하는 중과 쉬는 중)와 셸 노드로 다음을 재현하고 원인을 작업 기록에 적는다.
   - "복사가 안 된다"
   - 끌고 스크롤하면 선택이 풀린다
   - 가장자리로 끌어도 스크롤되지 않는다
2. **길 고르기(실험).** 화면 밖으로 나간 글까지 고르고 복사하려면, 화면 프레임 말고 글의 기록이 필요하다. 아래 길들을 짧게 실험해 고르고, 결과를 `docs/experiments/E12.md`(실험 문서 규칙)에 쓴다. 다른 길이 낫다면 그것을 쓴다.
   - herdr가 패널 글을 기록(scrollback)과 함께 줄 수 있는가: 소켓 API, `pane`/`agent read`의 source(`recent`, `recent-unwrapped` 등), 제어기 프레임. Claude Code 전체 화면 렌더러에서도 위로 간 대화 글이 들어 있는가. 셸은 어떤가.
   - **복사 모드 겹치기:** 고르기를 시작하거나 고른 채로 휠·가장자리 끌기를 하면, 노드 위에 그 패널 글(herdr에서 읽은 기록)을 보통 DOM 글로 깐다. 그 위에서는 브라우저가 고르기·스크롤·가장자리 자동 스크롤을 그대로 한다. 지금 보이던 화면과 같은 자리에서 이어지게 맞춘다.
   - **xterm에 기록 넣기:** 프레임 대신, 또는 프레임과 함께 기록 줄을 xterm 버퍼에 넣어 xterm 자체 선택(scrollback 포함)을 쓴다. 전체 화면 렌더러와 어떻게 맞출지 본다.
   - Claude Code 노드만이라면 대화 기록(JSONL)으로 글을 얻는 길도 있다. 다만 터미널에 보인 글과 같은지 본다.
3. **만들 동작.** 웹 페이지처럼 한다.
   - 고른 채로 휠을 굴리면 선택은 글에 붙어 함께 움직이고 풀리지 않는다.
   - 끄는 중에 노드 아래(위) 가장자리 가까이 가거나 넘으면 저절로 스크롤되고 선택이 늘어난다. 빠르기는 가장자리와의 거리에 따른다.
   - 끄는 중에 휠을 굴리면 선택 범위가 스크롤을 따라 늘어난다.
   - Ctrl+C(Ctrl+Shift+C, 오른쪽 메뉴가 있으면 그것도)는 화면 밖으로 나간 부분까지 고른 글 전체를 복사한다. 줄 끝 빈칸은 지금처럼 뺀다.
   - Claude Code가 일하는 중이어도 고른 글이 지워지지 않고 복사된다.
   - 고르기를 끝내는 법은 웹과 같다: 다른 곳을 누르거나, 글을 치거나, Esc. 끝나면 지금 화면(살아 있는 터미널)으로 자연스럽게 돌아온다.
   - P38에서 지킨 것(배율 보정, 고르는 동안 판 고정, 두세 번 누르기, 괄호 붙여넣기, 선택 없을 때 Ctrl+C는 ^C, 휠 → SGR)은 그대로 둔다.
   - P38의 "지우기" 규칙은 새 동작에 맞게 고치거나 없앤다.
4. **셸 노드.** 셸 노드도 고르기를 시작하면 같은 방법으로 지난 출력을 올려 고를 수 있으면 좋다. 길에 따라 되지 않으면 까닭을 보고에 적는다.

## 작업 기록

2026-11-05, P42 작업자 세션(워크트리 `p42`, 브랜치 `worktree-p42`).

- 판: `atrium-dev-p42`, 47860, `backend/.dev`(git 밖 `experiments/p42/tools/env.cjs`). 시험 폴더는 새로 만든 `C:\Workspace\mtask-p42-dir`(git init 안 함, `atrium trust`로 신뢰 대화상자 없음 확인). 셸은 PowerShell이다.
- **재현.** 고치기 전 코드로 셸 노드(1~120줄)와 claude 노드(haiku, 1~150)를 띄우고 git 밖 `experiments/p42/tools/repro.mjs`로 봤다(`repro-before.json`, `repro-working.json`).
  - "복사가 안 된다": 쉬는 중에 고른 두 줄은 복사됐다. 일하는 중에 고른 두 줄은 4번 가운데 1번, 0.4초 안에 선택이 지워져 Ctrl+C가 클립보드를 바꾸지 못했다.
    - 원인 하나: P38의 "고른 자리의 글이 바뀌면 지운다"(`clearsSelection('frame')`). 일하는 동안 스피너 줄이 바뀌고, 턴이 끝나면 화면이 통째로 다시 그려진다. 고른 범위가 그 줄에 걸리거나 그 순간이 겹치면 지워진다.
    - 원인 둘: 선택이 남아도 복사는 화면에 보이는 칸만 된다(xterm scrollback 0).
  - 끌고 스크롤하면 풀린다: 고른 뒤 휠, 끄는 중 휠 모두 휠을 보내는 순간 지워졌다(`clearsSelection('wheel')`). 셸도 같다. 셸은 PowerShell이 SGR 휠을 무시해 화면도 그대로였다.
  - 가장자리로 끌어도 스크롤되지 않는다: claude는 화면이 그대로이고, 선택은 화면 끝 줄을 넘어 "Jump to bottom (ctrl+End) ↓" 줄, 구분선, 입력칸까지 들어갔다. 셸도 위로 끌어도 그대로였다. 끄는 동안 xterm이 스크롤하려 해도 scrollback이 0이라 움직일 곳이 없다.
- **실험(E12).** `docs/experiments/E12.md`에 적었다. herdr `pane.read recent`는 셸 기록을 다 주지만, 판 제어기가 붙은 claude 패널에는 화면만 준다. Claude Code는 SGR 휠 한 번에 2~3줄을 고르지 않게 스크롤한다. 대화 기록(JSONL)은 화면 글과 다르다. 일하는 동안에는 답을 그리지 않고 스피너 줄만 바뀐다.
  - 고른 길: claude 등은 프레임을 이어 붙인 문서에 선택을 붙인다. 셸은 herdr 기록을 xterm scrollback에 넣고 판 안에서 스크롤한다. 복사 모드 겹치기(DOM)는 claude 기록 출처가 없어 버렸다.
- **만든 방법.**
  - 선택은 xterm 자체 선택 대신 `term-selection.js`(`TermSelection`)가 든다. 마우스는 터미널 안에서 캡처 단계로 받아 xterm으로 넘기지 않는다. 노드 활성과 초점은 대신 한다. 선택은 문서 줄과 칸 경계로 들고, 보이는 부분만 `term.select()`로 그린다. 판(Canvas)과 시험이 쓰는 `hasSelection`·`getSelection`은 이 선택으로 답하게 덮었다.
  - claude 등(live): 고르는 중일 때만 프레임마다 화면 칸을 읽어 `TermDoc.update`에 넣는다. `findShift`는 앞 화면에 있던 줄 가운데 같은 거리만큼 옮겨 간 줄을 세어 움직인 줄 수를 찾는다. 제자리 줄(질문 머리줄, 입력칸, 상태 줄)은 영역에서 뺀다.
  - 가장자리 자동 스크롤: 끄는 점이 노드 위·아래 가장자리 한 줄 안에 들어가면 줄/초 빠르기를 정하고(`edgeSpeed`), 40ms마다 claude에는 SGR 휠, 셸에는 `scrollLines`를 보낸다. 끝은 마우스 밑 칸(밖이면 영역 끝 줄)으로 다시 잡는다.
  - 셸(buffer): scrollback 5000. 그림자 터미널(scrollback 0)에 프레임을 먼저 써서 화면이 위로 d줄 밀렸으면, 실제 xterm에서 영역을 d줄 올려 밀려난 줄을 scrollback으로 보낸다. 첫 프레임 앞에는 `terminal.history`(새 API, herdr `recent` ANSI)로 받은 지난 출력 가운데 화면 위의 줄을 넣는다.
- **하면서 알아낸 것.**
  - 셸에서 영역을 올린 뒤 herdr 차이분 프레임을 그대로 쓰면 글이 깨졌다("9", "20"처럼 바뀐 칸만 남음). 프레임은 herdr 앞 화면에서 바뀐 칸만 쓰기 때문이다. 올린 뒤 그림자 화면을 칸 그대로(색 포함) 다시 쓰고 프레임을 쓴다(`serializeScreen`).
  - 빠른 출력(150줄)은 한 프레임에 지나가 밀려난 줄이 화면에 한 번도 보이지 않는다. 움직임으로 설명되지 않게 많이 바뀌면(`bigChange`) 출력이 0.5초 멈춘 뒤 herdr 기록으로 판 안 기록을 다시 맞춘다. 고르는 중이거나 위로 올려 보는 중이면 미룬다.
  - 배율 0.75의 첫 시험에서 자동 스크롤이 Claude Code를 맨 위로 올려 버렸다. 노드 밖의 점을 그대로 쓰면 SGR 휠이 상태 줄 칸에서 나간다. 휠은 스크롤 영역 안의 칸에서 보내게 고쳤다(그 뒤 재현되지 않음).
  - 위로 스크롤한 Claude Code는 영역 끝 줄에 "Jump to bottom" 안내를 겹쳐 그린다. 그 줄이 문서에 들어가 복사 끝 줄에 붙었다. 글이 움직였는데 같은 칸에 그대로 남은 오른쪽 끝 글을 지운다(`maskOverlay`, 영역 끝 두 줄만).
  - 처음 `findShift` 조건(움직인 줄이 바뀐 줄의 절반 이상)은 새로 드러난 줄이 많으면 움직임을 놓쳤다. 앞 화면에 있던 줄만 세게 고쳤다.
  - 이 Claude Code는 일하는 동안 답을 그리지 않는다. 그래서 "일하는 중" 시험은 고른 범위에 스피너 줄을 넣어 고른 자리의 글이 계속 바뀌는 때를 본다.
  - 창 시험에서 줄 글은 `translateToString(true)`이어도 끝 빈칸이 남는다(herdr가 빈칸으로 채움). 시험은 `trimEnd`로 견준다.
- **시험.** 창 단위 117/117(새 `p42-lib` 17개, `p38-lib` 7개 가운데 1개 고침), 백엔드 335/335, 빌드 됨. 창 시험 `p42-select` 28/28, `p38-select`(P42 판에서, 새 동작에 맞게 고친 3단계 포함) 61/61.

## 보고

### 만든 것

1. **웹 같은 글 고르기**(`app/src/renderer/term-selection.js`, 계산은 `lib/term-select.js`)
   - 고른 채로 휠을 굴리면 선택이 글에 붙어 함께 움직이고 풀리지 않는다.
   - 끄는 중 노드 위·아래 가장자리 한 줄 안에 들어가거나 넘어가면 저절로 스크롤되고 선택이 늘어난다. 빠르기는 넘어간 거리(줄 수)에 따른다: 가장자리에서 6줄/초, 한 줄 넘을 때마다 18줄/초 더, 90줄/초까지.
   - 끄는 중 휠을 굴리면 선택이 스크롤을 따라 늘어난다.
   - Ctrl+C·Ctrl+Shift+C는 화면 밖으로 나간 부분까지 고른 글 전체를 복사한다. 줄 끝 빈칸은 지금처럼 뺀다. 복사하면 지금처럼 선택을 지운다(다음 Ctrl+C가 ^C).
   - Claude Code가 일하는 중이어도 고른 글이 지워지지 않는다. 고른 범위에 스피너 줄이 있으면 복사할 때의 글이 들어간다.
   - 끝내기: 터미널 밖 누르기, 글 입력, Esc(고른 글이 있을 때 Esc는 선택만 끝내고 앱에 보내지 않는다. 없으면 지금처럼 Claude Code 끊기). 셸은 Esc로 끝내면 판 안 기록 맨 아래(지금 화면)로 돌아온다. Shift+누르기는 선택을 늘린다.
   - 두 번 누르기(낱말), 세 번 누르기(줄)는 직접 한다. 낱말 구분 글자는 xterm 기본값과 같다.
2. **claude 등(live)**: 프레임을 이어 붙인 문서(`TermDoc`, `findShift`, `maskOverlay`). 휠과 자동 스크롤은 지금처럼 SGR로 보낸다. 자동 스크롤의 휠은 스크롤 영역 안의 칸에서 보낸다.
3. **셸(buffer)**: 판 안 기록(xterm scrollback 5000).
   - 노드가 붙을 때 첫 프레임 앞에 herdr 기록(지난 출력)을 넣는다.
   - 새 출력으로 밀려난 줄은 프레임마다 scrollback으로 보낸다.
   - 한 프레임에 지나간 빠른 출력, `cls`, 크기 바뀜 뒤에는 출력이 멈추면 herdr 기록으로 다시 맞춘다.
   - 휠은 판 안에서 스크롤한다(SGR을 보내지 않는다).
4. **백엔드 API** `terminal.history { session, lines? }`: herdr `pane.read recent`(ANSI, 기본 3000줄, 10000줄까지).
5. **P38 규칙 고침**(`lib/term-input.js`): `clearsSelection`은 복사, 붙여넣기, 입력, Esc, 밖 누르기, 크기 바뀜에서만 지운다(휠·프레임은 지우지 않는다). `keyAction`에 `clear-selection`(Esc), 자동 스크롤용 `sgrWheel`을 더했다.
6. P38에서 지킨 것(배율 보정은 화면 사각형 비율로, 고르는 동안 판 고정, 두세 번 누르기, 괄호 붙여넣기, 선택 없을 때 Ctrl+C는 ^C, claude 휠 → SGR, 끄는 동안 포인터 모양)은 그대로이고 `p38-select` 61/61로 확인했다.

### 계획과 다른 곳

- 고른 길은 지시의 "복사 모드 겹치기"가 아니다. claude는 프레임 이어 붙이기, 셸은 xterm에 기록 넣기다(E12 3절).
- 고친 자리: `TerminalView.jsx`, `lib/term-input.js`, 새 `lib/term-select.js`·`term-selection.js`, `locales` 끝(`termSelect.copyFail`), `backend/src/backend.mjs`(API 한 줄), 시험 파일. `Canvas.jsx`, `styles.css`와 P41·P43의 파일은 고치지 않았다. `Canvas.jsx`는 `term.hasSelection()`을 그대로 부르고, 그 답을 새 선택으로 덮었다.
- 셸의 휠이 SGR 대신 판 안 스크롤이 됐다(지시 4).
- 복사 뒤 선택을 지우는 P38 규칙은 남겼다. 웹은 복사 뒤에도 선택이 남지만, 터미널에서는 다음 Ctrl+C가 ^C여야 해서다.
- 오른쪽 메뉴는 터미널에 없어서 더하지 않았다.
- 시험과 문제 찾기를 위해 `term._mtSel.trace`(문서가 움직인 줄 수, 자동 스크롤 휠 최근 200개)를 둔다.

### 알려진 문제

- Claude Code가 화면을 통째로 다시 그리면(노드 크기 바뀜, 대화 다시 그리기) 문서가 이어지지 않는다. 크기가 바뀌면 선택을 지운다. 그 밖에는 선택이 같은 문서 줄에 남는다.
- claude 노드에서 선택을 처음 시작할 때는 스크롤 영역을 모른다. 글이 한 번 움직이기 전까지는 입력칸·상태 줄까지 끌어 고를 수 있다. 글이 움직이면 영역을 알아내 그 안으로 묶는다.
- "Jump to bottom" 안내 지우기는 글이 한 번 움직인 뒤에 된다. 영역 끝 두 줄의 오른쪽 끝 글이 열 칸 넘게 앞 화면과 같은 칸에 남으면 안내로 본다. 표처럼 줄마다 같은 끝 글이 있으면 그 줄 끝이 빈칸으로 복사될 수 있다.
- 셸 노드는 휠을 판 안에서만 쓴다. 셸 노드 안에서 띄운 전체 화면 앱(less, vim, 셸에서 띄운 claude)에는 휠이 가지 않는다. 앱이 도는지 herdr가 알려 주지 않아 가리지 않았다.
- 셸 판 안 기록은 5000줄이다. 넘어 잘리면 고른 줄이 그만큼 어긋난다.
- 셸의 `cls` 뒤에도 출력이 멈춰 다시 맞추기 전(0.5초)에는 옛 기록이 보인다.
- 선택 칸 계산은 더 이상 xterm 내부를 쓰지 않는다(화면 사각형 ÷ 칸 수). P38의 `fixMouseScale`은 마우스 보고와 링크용으로 남아 있다.
