날짜: 2026-11-05

## 지시

### 목표

터미널 노드에서 글을 고르고 복사하는 것을 웹 페이지처럼 되게 한다. P38은 배율 아래 칸 어긋남은 고쳤다. 대신 복사·휠·화면 바뀜 뒤에 선택을 지우는 쪽을 골랐고, 사용자는 그것이 답이 아니라고 했다. 사용자의 말은 다음과 같다.
- "복사가 안 되는데, 아직."
- "드래그하고 스크롤하면 선택이 풀려. 이는 제대로 된 해결책이 아니다."
- "드래그해서 창 하단으로 끌면 cli 창이 알아서 밑으로 내려가고."
- "드래그하고 스크롤하면 드래그한 부분도 같이 이동하고."
- "드래그 끌고 있는 상태로 스크롤하면 내 선택 범위도 밑으로 쭉쭉 내려가야지. 웹처럼."

지금의 사정은 다음과 같다(P38 보고, ARCH 7.2, E4).
- 터미널 노드의 화면은 herdr가 자기 화면 모델을 다시 그린 프레임이고, xterm의 scrollback은 0이다.
- 휠은 SGR 마우스 시퀀스로 바뀌어 Claude Code 전체 화면 렌더러가 스스로 대화를 스크롤한다. 그래서 xterm은 글이 위아래로 움직였다는 것을 모르고, 선택은 칸에 붙어 있다.
- P38은 그 때문에 선택을 지운다(`clearsSelection`: 복사, 붙여넣기, 휠, 고른 자리의 글이 바뀜).
- Claude Code가 일하는 동안에는 상태 줄과 스피너가 계속 바뀐다. 그래서 고른 곳이 그 줄에 걸리면 복사하기 전에 지워질 수 있다. "복사가 안 된다"의 원인일 가능성이 크다.
- 셸 노드(PowerShell)는 SGR 휠을 무시해서, 휠로 지난 출력을 올려 볼 수도 없다.

### 할 것

1. **재현.** 개발용 판에서 claude 노드(일하는 중과 쉬는 중)와 셸 노드로 다음을 재현하고 원인을 작업 기록에 적는다.
   - "복사가 안 된다"
   - 끌고 스크롤하면 선택이 풀린다
   - 가장자리로 끌어도 스크롤되지 않는다
2. **길 고르기(실험).** 화면 밖으로 나간 글까지 고르고 복사하려면, 화면 프레임 말고 글의 기록이 필요하다. 아래 길들을 짧게 실험해 고르고, 결과를 `docs/experiments/E12.md`(실험 문서 규칙)에 쓴다. 다른 길이 낫다면 그것을 쓴다.
   - herdr가 패널 글을 기록(scrollback)과 함께 줄 수 있는가: 소켓 API, `pane`/`agent read`의 source(`recent`, `recent-unwrapped` 등), 제어기 프레임. Claude Code 전체 화면 렌더러에서도 위로 간 대화 글이 들어 있는가. 셸은 어떤가.
   - **복사 모드 겹치기:** 고르기를 시작하거나 고른 채로 휠·가장자리 끌기를 하면, 노드 위에 그 패널 글(herdr에서 읽은 기록)을 보통 DOM 글로 깐다. 그 위에서는 브라우저가 고르기·스크롤·가장자리 자동 스크롤을 그대로 한다. 지금 보이던 화면과 같은 자리에서 이어지게 맞춘다.
   - **xterm에 기록 넣기:** 프레임 대신, 또는 프레임과 함께 기록 줄을 xterm 버퍼에 넣어 xterm 자체 선택(scrollback 포함)을 쓴다. 전체 화면 렌더러와 어떻게 맞출지 본다.
   - Claude Code 노드만이라면 대화 기록(JSONL)으로 글을 얻는 길도 있다. 다만 터미널에 보인 글과 같은지 본다.
3. **만들 동작.** 웹 페이지처럼 한다.
   - 고른 채로 휠을 굴리면 선택은 글에 붙어 함께 움직이고 풀리지 않는다.
   - 끄는 중에 노드 아래(위) 가장자리 가까이 가거나 넘으면 저절로 스크롤되고 선택이 늘어난다. 빠르기는 가장자리와의 거리에 따른다.
   - 끄는 중에 휠을 굴리면 선택 범위가 스크롤을 따라 늘어난다.
   - Ctrl+C(Ctrl+Shift+C, 오른쪽 메뉴가 있으면 그것도)는 화면 밖으로 나간 부분까지 고른 글 전체를 복사한다. 줄 끝 빈칸은 지금처럼 뺀다.
   - Claude Code가 일하는 중이어도 고른 글이 지워지지 않고 복사된다.
   - 고르기를 끝내는 법은 웹과 같다: 다른 곳을 누르거나, 글을 치거나, Esc. 끝나면 지금 화면(살아 있는 터미널)으로 자연스럽게 돌아온다.
   - P38에서 지킨 것(배율 보정, 고르는 동안 판 고정, 두세 번 누르기, 괄호 붙여넣기, 선택 없을 때 Ctrl+C는 ^C, 휠 → SGR)은 그대로 둔다.
   - P38의 "지우기" 규칙은 새 동작에 맞게 고치거나 없앤다.
4. **셸 노드.** 셸 노드도 고르기를 시작하면 같은 방법으로 지난 출력을 올려 고를 수 있으면 좋다. 길에 따라 되지 않으면 까닭을 보고에 적는다.

### 완료 기준

1. 순수 함수(줄 맞추기, 가장자리 자동 스크롤 빠르기, 선택 범위 계산, 복사 글 만들기)는 단위 시험한다.
2. 개발용 판의 창 시험(e2e)으로 확인하고 결과를 `experiments/p42/`(git 밖)에 남긴다.
   - claude 노드(`--model haiku`)에 120줄이 넘는 답을 내게 한다. 배율 0.75와 1에서 각각 다음을 본다.
     - 끌어서 노드 아래 가장자리 밖으로 가져가면 자동 스크롤되며 화면 밖 줄까지 골라지고, 복사한 글이 기대한 여러 줄과 같다.
     - 고른 뒤 휠을 굴려도 선택이 풀리지 않고 글과 함께 움직이며, 그 뒤 복사가 된다.
     - 끄는 중 휠을 굴리면 선택이 늘어난다.
   - claude 노드가 일하는 중(스피너가 도는 중)에 고른 글을 복사할 수 있다.
   - 셸 노드에서도 같은 시험을 하고 결과(되거나, 안 되는 까닭)를 적는다.
   - 시험이 시스템 클립보드를 쓰면 시험 앞의 글로 되돌린다.
3. `cd backend && npm test`, `cd app && npm test`, `cd app && npm run build`가 통과한다. P38 시험(`p38-lib`, `e2e/p38-select`) 가운데 바뀐 동작과 어긋나는 것은 새 동작에 맞게 고친다.

### 지킬 것

- `CLAUDE.md`를 따른다. 프로세스는 직접 띄운 것만 PID로 끈다.
- 이 저장소는 공개다. 작업 기록, 시험 코드, 커밋 메시지에 사용자 경로·메일·토큰을 쓰지 않는다. 커밋 전·푸시 전 검사를 건너뛰지 않는다.
- 같은 때 두 작업자가 돈다.
  - P41(말로 한 모델 고르기)은 `branch.mjs`, `bin/atrium*.mjs`, `launchers.mjs`, `deepseek.mjs`, 백엔드 spawn 계획을 고친다.
  - P43(아래 바 자동 숨김과 방향키)은 `Chrome.jsx`, `CommandBar.jsx`, `Search.jsx`, `main.jsx`의 키 처리, `styles.css`를 고친다.
  - 너는 그 파일을 되도록 건드리지 않는다. `styles.css`는 끝에 더한다. 화면 글은 `locales/en.js`·`ko.js` 끝에 더하고, 한국어는 P39 말투(합니다체)와 용어를 따른다.
- 자기 브랜치에만 커밋한다. 커밋 메시지에 `Co-Authored-By` 줄을 넣지 않는다. `main`을 바꾸거나 푸시하지 않는다. `node_modules`는 워크트리 안에서 받는다(`npm ci`).
- 문서는 이 작업 파일의 작업 기록 절과 보고 절, 그리고 새 실험 문서 `docs/experiments/E12.md`만 쓴다. 고쳐야 할 ARCH 7.2 문장은 보고 절에 적는다.
- 끝나면 보고 절을 쓰고, 맨 마지막에 `<워크트리>/backend/.dev/p42.done`(브랜치 이름과 마지막 커밋 해시 두 줄)을 만든다.
