## 지시

### 목표

잠재우기(P21, ARCH 4절 D4)를 세션 단위에서 리포(워크스페이스) 단위로 바꾼다. 사용자의 말은 다음과 같다.
- 30분 잠재우기는 세션 단위가 아니라 같은 디렉토리(리포)를 단 단위로 나눈다.
- 30분 동안 그 리포에 아무 일이 없으면 그 리포의 모든 작업자를 잠재운다.
- 지금의 세션별 잠재우기는 삭제한다.
- 잠든 리포의 노드 하나를 누르거나 글을 보내면 리포 전체를 깨운다.

### 정한 것

- **리포 단위 저절로 잠재우기.**
  - 워크스페이스 하나에 설정 `sleepAfterMin`(기본 30분, 0이면 끔) 동안 아무 일이 없으면, 그 워크스페이스의 잠재울 수 있는 세션을 모두 잠재운다.
  - 잠재울 수 있는 세션은 지금처럼 판이 띄운 Claude Code다(DeepSeek처럼 Claude Code로 띄우는 것 포함). 셸과 다른 종류는 그대로 둔다.
  - "아무 일"은 그 워크스페이스의 어떤 세션이든 다음 가운데 하나에 해당하는 것이다.
    - 일하는 중, 내 차례, 신뢰 대기, 시작 중
    - 전달 대기, 돌아가는 루프
    - 사람이 보거나 입력하거나 보냄(손댄 시각)
    - 보내지 않은 초안(P21)
    - 화면에서 그 워크스페이스의 노드를 보고 있음(초점이나 가까이 얼굴)
    - 하위 세션이 다른 워크스페이스에서 일하는 부모
  - 마지막 일이 끝난 뒤 정한 시간이 지나야 잠재운다.
- **세션별 잠재우기 빼기.**
  - 세션 하나만 저절로 잠드는 규칙을 뺀다.
  - 노드 메뉴의 "잠재우기"를 뺀다. 노드의 "깨우기"는 리포 깨우기로 바꾼다.
  - API·CLI(`session.sleep`, `session.sleepIdle`, `atrium wake`)는 리포 단위(`workspace.sleep`, `workspace.wake`, 쉬는 리포 모두)로 바꾼다. 옛 이름은 지우거나 리포 동작으로 넘긴다.
- **손으로.**
  - 영역 이름표 메뉴에 "이 리포 잠재우기·깨우기"를 둔다.
  - 트레이 메뉴와 위 메모리 알약 목록의 동작은 "쉬는 리포 모두 잠재우기"다.
- **깨우기.**
  - 잠든 리포의 노드 하나를 누르거나, 그 리포의 세션 하나에 글을 보내면(명령 바, `@이름`, 루프, Thread 답장, 다른 에이전트의 herdr 호출), 그 리포에서 잠든 세션을 모두 깨운다. 글은 그 세션이 준비된 뒤에 보낸다.
  - 한꺼번에 깨울 때 부담이 크면 차례로 띄워도 된다(고른 방식을 보고에 적는다).
- **보이기.**
  - 영역 이름표에 "잠듦" 표시와 아낀 메모리를 보인다. 잠든 노드 얼굴은 P21 그대로다.
  - 메모리 알약 목록은 리포별로 묶는다.
  - 설정의 풀이 글을 리포 단위에 맞게 고친다.
- 복구 때 건너뛰기, 보관·삭제, 초안 막기는 P21 그대로 지킨다.

## 작업 기록

- 2026-11-02 판정을 둘로 나눴다. `sleepTarget`(세션 하나가 잠재울 대상인가: 판이 띄운 claude, 대화 기록, 쉬는 중·오류로 끝난 턴)과 `sessionActivity`(그 세션이 리포를 깨워 두는 일). 리포 판정 `repoSleepPlan`은 리포 세션 모두의 일을 먼저 보고(있으면 까닭과 세션 이름), 대상이 없으면 `asleep`·`nothing`, 저절로일 때만 쉰 시간을 본다. 셋 다 순수 함수다.
- "마지막 일이 끝난 뒤"는 리포마다 `busyAt`(일이 보인 마지막 때)으로 센다. tick(3초~30초)과 `sleep.status`가 판정할 때, 초점이 바뀔 때(`board.viewing`), 창 연결이 끊길 때 적는다. 쉬기 시작한 때는 `max(busyAt, 리포 세션들의 idleSince)`. 메모리에만 두므로 백엔드를 다시 켜면 세션의 활동 시각만 남는다.
- 정한 세부:
  - 셸은 잠재우지 않고, 리포를 깨워 두지도 않는다. 셸의 `shell_running`(개발 서버 등)은 일로 보지 않고, 셸의 쉬기 시작한 때는 사람이 손댄 때뿐이다. 셸에 친 글도 초안으로 보지 않는다(`/exit`와 상관없음). 다른 종류(codex 등)의 일하는 중·내 차례는 일이다.
  - P21의 "일하는 부모의 하위 세션"(`parent_busy`)도 남겼다. 다른 리포의 부모가 일하면 하위 세션의 리포를 잠재우지 않는다(부모의 herdr 호출이 잠든 이름에서 한 번 실패하는 일을 줄임).
  - 손으로 "이 리포 잠재우기"(hand)는 보는 노드와 쉰 시간을 보지 않는다. 그 밖의 일(일하는 중, 내 차례, 초안, 전달 대기, 루프, 부모·자식)이 있으면 리포 전체를 거부하고 까닭과 세션 이름을 알린다(`repoSleepRefused`). 일부만 잠재우지 않는다.
  - 쉬는 리포 모두(bulk, 트레이·메모리 알약)는 저절로와 같은 조건이되 쉰 시간은 보지 않는다.
  - 리포를 잠재울 때 세션마다 차례로 잠재우고, 세션마다 판정을 다시 본다. 도중에 일이 들어오면 남은 세션은 그대로 둔다(잠깐 일부만 잠든 리포가 생길 수 있다. 다음 tick에 다시 본다).
- 깨우기: `wakeRepo(key, first)`가 부른 세션을 먼저, 나머지를 1.5초(`WAKE_STAGGER_MS`) 간격으로 띄운다. 기다리는 세션도 처음부터 "깨우는 중"으로 보이고 전달은 기다린다. claude 여럿이 한꺼번에 뜨는 부담(시작 때 CPU와 MCP 서버)을 나누되, 다음 세션은 앞 세션이 준비되기를 기다리지 않는다. 노드 누르기·`session.wake`·`atrium wake`는 그 세션이 준비될 때까지 기다리고, 이름표 메뉴의 깨우기는 기다리지 않는다(API `workspace.wake`는 `wait`로 고른다).
- 깨우는 길: 대기열 `sleeping` → `wakeFor`(명령 바, `@이름`, 루프, Thread 답장, 연결 알림 모두), PreToolUse hook의 herdr 호출 대상, `atrium wake`·잠든 하위 세션 이름의 `atrium child`, 노드 누르기와 잠든 얼굴의 깨우기, 노드 메뉴 "이 리포 깨우기", 이름표 메뉴 "깨우기".
- API: `workspace.sleep`(리포 키·이름·폴더 또는 `session`), `workspace.wake`, `workspace.sleepIdle`, `session.wake`(그 세션의 리포), `sleep.status`(리포마다 까닭, 일이 있는 세션, 쉰 시간, 잠든 수, 아낀 메모리). `session.sleep`과 `session.sleepIdle`은 지웠다. 사람의 CLI에 `atrium sleep [<리포>]`, `atrium wake <리포|이름>`, `atrium sleep-status`를 더했다.
- 창: 노드 메뉴의 잠재우기를 빼고 잠든 노드에 "이 리포 깨우기"만 둔다. 영역 이름표에 잠듦 표시(모두 잠들면 "잠듦 · 아낀 메모리", 일부면 "n개 잠듦 · …", 테두리 점선)와 이름표 단추 줄(⌄)의 잠재우기·깨우기. 메모리 알약 목록은 리포마다 이름·깨어 있는 메모리·잠든 수와 아낀 메모리 아래에 세션 줄. 트레이와 목록 단추는 "쉬는 리포 모두 잠재우기". 순수 함수는 `renderer/lib/repo-sleep.js`(`repoSleep`, `memByRepo`).
- 단위 시험: P21 판정 시험 둘과 초안·부모자식·보는 노드 시험을 리포 판정으로 바꿨다. `backend/test/p24.test.mjs`(리포 둘의 가짜 판: 쉰 리포만 통째로, 보기를 그만둔 뒤부터 센다, 부른 세션 먼저 깨우기, 손으로·모두·깨우기)와 창 시험 하나(이름표 잠듦, 리포별 묶음, 글)를 더했다. 백엔드 224, 창 47 통과.
- 시험 판 값: `experiments/p24/tools/env.cjs`(atrium-dev-p24, 47842). 시험 폴더 `C:\Workspace\mtask-p24-ws\ra`, `rb`(p24-repo), `r1`~`r3`(리포 단위로 고친 p21-sleep).
- 창 시험 1회차(10/21)에서 찾아 고친 것: 노드가 넷뿐이면 "모두 보기"도 가까이 얼굴이라 터미널이 붙어 리포가 늘 "보는 중"이었다(시험의 눈 돌리기를 아주 멀리 보기로 바꿈). 또 백엔드는 터미널이 붙은 노드만 보는 노드로 알아서, 한 세션이 잠들어 제어기 자리가 비면 화면에 있던 이웃이 붙어 리포가 반만 잠들었다. 창이 `board.viewing`에 가까이 얼굴로 보이는 노드 모두(제어기 상한 밖, 잠든 노드 포함, `closeIds`)를 함께 보내게 고쳤다.

## 보고

### 만든 것

- 백엔드 `sleep.mjs`: 리포 단위 판정(`repoSleepPlan`, `sleepTarget`, `sessionActivity`, 리포마다 `busyAt`), 리포 잠재우기(`sleepRepo`, 세션마다 차례로), 리포 깨우기(`wakeRepo`·`wakeFor`, 부른 세션 먼저, 나머지 1.5초 간격), API `workspace.sleep`·`workspace.wake`·`workspace.sleepIdle`·`session.wake`(리포)·`sleep.status`(리포마다). `session.sleep`·`session.sleepIdle`과 세션별 판정 `sleepBlock`은 지웠다. 대기열·herdr hook·`atrium wake`·`atrium child`는 `wakeFor`로 리포째 깨운다(`backend.mjs`, `branch.mjs`). 판 안내 한 줄, `atrium-child` 도움말, 설정 풀이를 리포 단위로. 사람의 CLI `atrium sleep [<리포>]`, `atrium wake <리포|이름>`, `atrium sleep-status`.
- 창: 노드 메뉴의 잠재우기 뺌, 잠든 노드 메뉴는 "이 리포 깨우기". 영역 이름표의 잠듦 표시(모두 잠들면 "잠듦 · 아낀 메모리"와 점선 테두리, 일부면 "n개 잠듦 · …")와 단추 줄(⌄)의 잠재우기·깨우기. 메모리 알약 목록을 리포별로 묶음. 트레이·목록 단추 "쉬는 리포 모두 잠재우기". 설정 "쉬는 리포 잠재우기(분)"와 풀이. 보는 노드 알리기에 가까이 얼굴 노드 모두. 글은 `locales/en.js`·`ko.js`(`sleep.*`, `regions.asleep*`·`sleep`·`wake*`, `backend.repoSleepRefused`·`sleepWhy_asleep`·`sleepWhy_nothing`).
- 깨우기 방식: 차례로 띄우기를 골랐다. 부른 세션을 먼저 띄우고 나머지는 1.5초 간격으로 띄우되 앞 세션이 준비되기를 기다리지 않는다. 기다리는 세션도 처음부터 "깨우는 중"이고 전달은 기다린다.

### 남은 것과 알릴 것

- Claude Code는 쉰 지 약 1분 뒤 idle 알림 hook을 한 번 보낸다. 쉬기 시작한 때를 마지막 hook으로 세므로 `sleepAfterMin`이 1분이면 실제로는 약 2분 뒤에 잠든다(시험에서 rb 125초). 기본 30분에서는 상관없다.
- 리포를 잠재우는 도중에 일이 들어오면 남은 세션은 깨어 있어 잠깐 일부만 잠든 리포가 생긴다. 이름표는 "n개 잠듦"으로 보이고, 깨어 있는 노드를 눌러도 나머지를 깨우지는 않는다(잠든 노드를 누르거나 이름표 메뉴로 깨운다). 다음 tick에 다시 판정한다.
- 손으로 "이 리포 잠재우기"는 리포에 일하는 세션이 하나라도 있으면 아무것도 잠재우지 않는다(일부만 잠재우지 않음).
- `busyAt`은 메모리에만 있어 백엔드를 다시 켜면 세션 활동 시각(hook, 턴 끝, 손댄 때, 깬 때)만으로 센다.
- 셸이 돌리는 명령(개발 서버 등)은 리포를 깨워 두지 않는다. 사람이 그 셸 노드를 보거나 치면 깨워 둔다.
- 옛 `experiments/p21/tools`(atrium-dev-p21)로는 고친 `p21-sleep.mjs`를 돌릴 수 없다(리포마다 시험 폴더가 필요해 `MT_E2E_OUT=p24`만 받는다).
- 정리: 시험 세션, 창, 백엔드, herdr 서버와 세션 `atrium-dev-p24`, 시험 폴더 `C:\Workspace\mtask-p24-ws`, 시험 대화 기록 폴더를 지웠다. 시험 판 설정의 트레이는 끄고 정리했다. 삭제 시험이 휴지통으로 보낸 시험 대화 기록 하나는 휴지통에 남았고, `~/.claude.json`에 Claude Code가 남긴 시험 폴더 항목은 고치지 않았다. `backend/.dev/data`(시험 판 기록)는 남겼다. 떠 있는 Electron 세 개는 본 저장소 앱의 것이라 건드리지 않았다.
