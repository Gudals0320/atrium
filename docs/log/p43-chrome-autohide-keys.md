## 지시

### 목표

아래쪽 명령 바와 칩이 터미널을 가리지 않게 평소에는 숨기고, 방향키로 명령 바·찾기 바·도구 모드를 바로 부르게 한다. 사용자의 말은 다음과 같다.
- "하단에 명령 바랑 버튼들(새 세션, 자동 정렬, 작업 관계도, 변경 내역, 전체 보기) 이것들 상시 뜨니까 밑에 있는 cli 창들을 가리잖아. 마우스를 하단에 가져가면 자동으로 뜨게 해 줘."
- "방향키 아래 누르면 이 가려져 있던 명령줄이 커서 위치와 상관없이 뜨고, 바로 명령 바 입력 대기 상태로 바뀐다(마우스로 클릭한 것처럼)."
- "방향키 왼쪽 누르면 좌측 도구 바에서 select/link 모드 전환하고."
- "방향키 위 누르면 Ctrl+F처럼 찾기 바 나오게 하기. 이 찾기 바는 밑에 있는데 상단으로 옮겨. 그리고 똑같이 방향키 위 누르면 마우스로 클릭한 것처럼 입력 대기로 바꾸고."
- "찾기 바에서 나가려면 지금은 esc 누르는 게 강제인데, 그냥 찾기 바 외부 클릭 한 번 하면 자연스럽게 사라지도록 하자."

### 할 것

1. **아래 바 자동 숨김.**
   - 명령 바(`CommandBar.jsx`)와 아래 칩(`Chrome.jsx`의 새 세션, 자동 정렬, 작업 관계도, 변경 내역, 전체 보기)을 평소에는 숨긴다.
   - 마우스가 창 아래 가장자리 띠에 오면 부드럽게 나타나고, 벗어나면 잠시 뒤 숨는다.
   - 숨지 않는 때: 명령 바에 포커스가 있을 때, 입력칸에 쓰다 만 글이 있을 때, 그 위 펼침(후보 목록, Thread 등)이 열려 있을 때, 칩 메뉴를 쓰는 중일 때.
   - 숨은 동안에도 아래에 있다는 것을 알 수 있게 아주 얇은 표시를 남긴다(모양은 네가 정한다). 숨은 동안 그 자리의 터미널은 가려지지 않고 눌린다.
   - 띠 높이, 나타나고 숨는 시간은 네가 정하고 보고에 적는다.
2. **방향키.** 판에 키보드 포커스가 있을 때만 받는다. 터미널 노드나 입력칸, 대화상자에 포커스가 있으면 방향키는 지금처럼 그쪽(셸 기록, Claude Code 입력, 목록 고르기)으로 간다. 판에 포커스가 있다는 것의 뜻(빈 캔버스를 누른 뒤 등)은 네가 정하고 보고에 적는다.
   - **아래:** 숨은 명령 바를 띄우고 입력칸에 포커스를 준다. 마우스로 누른 것과 같고, 마우스 위치와 상관없다.
   - **왼쪽:** 왼쪽 도구 모음의 고르기(select)와 잇기(link) 모드를 서로 바꾼다. 화면의 도구 단추 표시도 같이 바뀐다.
   - **위:** 찾기 바를 연다(Ctrl+F와 같다). 입력칸에 포커스를 준다.
   - **오른쪽:** 정하지 않았다. 아무것도 하지 않는다.
   - 지금 방향키를 쓰는 판 동작이 있으면 충돌을 보고에 적고, 사용자가 말한 위 동작을 우선한다.
3. **찾기 바.**
   - 화면 아래에서 위(가운데 위쪽, 위 크롬과 겹치지 않게)로 옮긴다. 결과 목록은 아래로 펼친다.
   - 찾기 바 바깥을 한 번 누르면 닫힌다. 그 누르기는 판에 그대로 전달된다(노드를 눌렀으면 노드도 골라진다). Esc도 그대로 닫는다.
4. **도움말.** 새 키(아래·왼쪽·위)를 툴팁이나 단축키 안내가 있는 곳에 적는다. 화면 글은 `locales/en.js`·`ko.js` 끝에 더하고, 한국어는 P39 말투(합니다체)와 용어를 따른다.

### 완료 기준

1. 숨김 판단(포커스, 쓰다 만 글, 펼침, 마우스 띠)과 방향키 판단(포커스가 어디 있을 때 받는가)은 순수 함수로 두고 단위 시험한다.
2. 개발용 판의 창 시험(e2e)으로 확인하고 스크린숏을 `experiments/p43/`(git 밖)에 남긴다.
   - 처음에는 아래 바가 숨어 있고, 아래쪽 터미널 노드의 마지막 줄이 가려지지 않으며 눌린다.
   - 마우스를 아래 띠로 가져가면 나타나고, 벗어나면 숨는다. 글을 쓰다 만 상태에서는 숨지 않는다.
   - 빈 캔버스를 누른 뒤 아래 키를 누르면 명령 바가 나타나고 입력칸에 포커스가 있다(바로 글을 칠 수 있다).
   - 왼쪽 키로 고르기·잇기가 바뀐다.
   - 위 키로 위쪽 찾기 바가 열리고 바로 칠 수 있다. 바깥을 누르면 닫힌다.
   - 터미널 노드에 포커스가 있을 때 방향키는 터미널로 간다(셸에 위 키 → 이전 명령이 나온다).
3. `cd backend && npm test`, `cd app && npm test`, `cd app && npm run build`가 통과한다. 이 작업으로 깨지는 옛 창 시험(아래 칩을 바로 누르는 것 등)은 새 동작에 맞게 고친다.

### 지킬 것

- `CLAUDE.md`를 따른다. 프로세스는 직접 띄운 것만 PID로 끈다.
- 이 저장소는 공개다. 작업 기록, 시험 코드, 커밋 메시지에 사용자 경로·메일·토큰을 쓰지 않는다. 커밋 전·푸시 전 검사를 건너뛰지 않는다.
- 같은 때 두 작업자가 돈다.
  - P41(말로 한 모델 고르기)은 백엔드 `branch.mjs`, `bin/atrium*.mjs`, `launchers.mjs`를 고친다.
  - P42(터미널 선택을 웹처럼)는 `TerminalView.jsx`, `lib/term-input.js`, 터미널 쪽 `Canvas.jsx`를 고친다.
  - 너는 그 파일을 되도록 건드리지 않는다. `Canvas.jsx`를 고쳐야 하면 키·포커스 처리만 한다. `styles.css`는 끝에 더한다. 화면 글은 `locales` 끝에 더한다.
- 자기 브랜치에만 커밋한다. 커밋 메시지에 `Co-Authored-By` 줄을 넣지 않는다. `main`을 바꾸거나 푸시하지 않는다. `node_modules`는 워크트리 안에서 받는다(`npm ci`).
- 문서는 이 작업 파일의 작업 기록 절과 보고 절만 고친다. 고쳐야 할 ARCH 행(7.1 크롬, 단축키, H8 명령 바, J5 찾기)은 보고 절에 새 문장으로 적는다.
- 끝나면 보고 절을 쓰고, 맨 마지막에 `<워크트리>/backend/.dev/p43.done`(브랜치 이름과 마지막 커밋 해시 두 줄)을 만든다.
