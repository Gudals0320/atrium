## 지시

### 목표

아래쪽 명령 바와 칩이 터미널을 가리지 않게 평소에는 숨기고, 방향키로 명령 바·찾기 바·도구 모드를 바로 부르게 한다. 사용자의 말은 다음과 같다.
- "하단에 명령 바랑 버튼들(새 세션, 자동 정렬, 작업 관계도, 변경 내역, 전체 보기) 이것들 상시 뜨니까 밑에 있는 cli 창들을 가리잖아. 마우스를 하단에 가져가면 자동으로 뜨게 해 줘."
- "방향키 아래 누르면 이 가려져 있던 명령줄이 커서 위치와 상관없이 뜨고, 바로 명령 바 입력 대기 상태로 바뀐다(마우스로 클릭한 것처럼)."
- "방향키 왼쪽 누르면 좌측 도구 바에서 select/link 모드 전환하고."
- "방향키 위 누르면 Ctrl+F처럼 찾기 바 나오게 하기. 이 찾기 바는 밑에 있는데 상단으로 옮겨. 그리고 똑같이 방향키 위 누르면 마우스로 클릭한 것처럼 입력 대기로 바꾸고."
- "찾기 바에서 나가려면 지금은 esc 누르는 게 강제인데, 그냥 찾기 바 외부 클릭 한 번 하면 자연스럽게 사라지도록 하자."

### 할 것

1. **아래 바 자동 숨김.**
   - 명령 바(`CommandBar.jsx`)와 아래 칩(`Chrome.jsx`의 새 세션, 자동 정렬, 작업 관계도, 변경 내역, 전체 보기)을 평소에는 숨긴다.
   - 마우스가 창 아래 가장자리 띠에 오면 부드럽게 나타나고, 벗어나면 잠시 뒤 숨는다.
   - 숨지 않는 때: 명령 바에 포커스가 있을 때, 입력칸에 쓰다 만 글이 있을 때, 그 위 펼침(후보 목록, Thread 등)이 열려 있을 때, 칩 메뉴를 쓰는 중일 때.
   - 숨은 동안에도 아래에 있다는 것을 알 수 있게 아주 얇은 표시를 남긴다(모양은 네가 정한다). 숨은 동안 그 자리의 터미널은 가려지지 않고 눌린다.
   - 띠 높이, 나타나고 숨는 시간은 네가 정하고 보고에 적는다.
2. **방향키.** 판에 키보드 포커스가 있을 때만 받는다. 터미널 노드나 입력칸, 대화상자에 포커스가 있으면 방향키는 지금처럼 그쪽(셸 기록, Claude Code 입력, 목록 고르기)으로 간다. 판에 포커스가 있다는 것의 뜻(빈 캔버스를 누른 뒤 등)은 네가 정하고 보고에 적는다.
   - **아래:** 숨은 명령 바를 띄우고 입력칸에 포커스를 준다. 마우스로 누른 것과 같고, 마우스 위치와 상관없다.
   - **왼쪽:** 왼쪽 도구 모음의 고르기(select)와 잇기(link) 모드를 서로 바꾼다. 화면의 도구 단추 표시도 같이 바뀐다.
   - **위:** 찾기 바를 연다(Ctrl+F와 같다). 입력칸에 포커스를 준다.
   - **오른쪽:** 정하지 않았다. 아무것도 하지 않는다.
   - 지금 방향키를 쓰는 판 동작이 있으면 충돌을 보고에 적고, 사용자가 말한 위 동작을 우선한다.
3. **찾기 바.**
   - 화면 아래에서 위(가운데 위쪽, 위 크롬과 겹치지 않게)로 옮긴다. 결과 목록은 아래로 펼친다.
   - 찾기 바 바깥을 한 번 누르면 닫힌다. 그 누르기는 판에 그대로 전달된다(노드를 눌렀으면 노드도 골라진다). Esc도 그대로 닫는다.
4. **도움말.** 새 키(아래·왼쪽·위)를 툴팁이나 단축키 안내가 있는 곳에 적는다. 화면 글은 `locales/en.js`·`ko.js` 끝에 더하고, 한국어는 P39 말투(합니다체)와 용어를 따른다.

## 보고

### 만든 것

- **아래 바 자동 숨김**(`lib/bottom.js`, `CommandBar.jsx` `useAutoHide`, `Chrome.jsx` `ChipRow`, `styles.css` 끝).
  - 명령 바와 칩 줄은 처음에 숨는다. 숨은 동안 둘 다 마우스를 받지 않아 그 자리의 터미널이 눌린다.
  - 마우스가 띠에 오면 나타난다. 띠는 판 아래 끝에서 28px 높이, 가로는 명령 바 폭의 양옆 48px까지다(왼쪽 레일과 오른쪽 아래 줌 알약 쪽은 띄우지 않는다).
  - 띠에 90ms 머물면 나타난다. 초점이 들어올 때(Ctrl+K, 아래 키, Tab)는 바로 나타난다. 띠와 보이는 바·칩 위를 벗어나 650ms가 지나면 숨는다. 바와 칩 사이의 빈틈은 이 시간 안에 지나므로 숨지 않는다. 나타나고 숨는 움직임은 0.16~0.18초 동안 18px 아래로 내려가며 흐려진다(움직임 줄이기 설정이면 바로).
  - 숨지 않는 때: 명령 바 안에 초점, 입력칸에 쓰다 만 글(빈칸만이면 없는 것으로 본다), 대상 후보 목록이나 Thread가 열림, 칩 줄 안에 초점, 시험 고정.
  - 숨은 동안의 표시: 아래 가운데, 바닥에서 7px 위에 72×4px 둥근 줄(`--chrome-text-3`, 불투명 0.28). 마우스를 받지 않는다.
  - 전달 칩(보낸 글의 전달 상태)은 숨은 동안에도 보이되 바닥 쪽으로 내려 앉는다. 숨은 동안 그 칩에 마우스를 올려도 바는 띄우지 않는다.
- **방향키**(`lib/keys.js` `boardArrowKey`, `main.jsx`). 판에 초점이 있을 때 아래 = 명령 바를 띄우고 입력칸에 초점, 위 = 찾기 바 열기(이미 열려 있으면 입력칸 글 고르기), 왼쪽 = 고르기·잇기 바꾸기(레일 단추 표시도 바뀐다), 오른쪽 = 받기만 하고 아무것도 하지 않는다.
  - 판에 초점이 있다의 뜻: 초점이 문서 몸통(빈 캔버스나 영역을 누른 뒤, 머리줄을 누른 뒤, 찾기 바를 닫은 뒤)이거나, 판 칸(`.mt-stage`) 안에서 글을 받지 않는 곳(노드 테두리, 떠 있는 단추, 칩)이다.
  - 받지 않는 때: 입력칸·터미널·메모 편집, 대화상자·노드 메뉴·알약 펼침 목록·찾기 바·사이드바 안, 대화상자·미션 맵·출력 보기가 열림, 노드 본문을 눌러 들어가 터미널이 붙기를 기다리는 동안(H4, 친 키는 터미널로 간다), Shift·Ctrl·Alt를 누른 채, 한글 조합 중, 누르고 있어 되풀이되는 키.
- **찾기 바**(`Search.jsx`, `styles.css` 끝). 위 가운데, 위 알약 줄 아래(top 60px)에 뜨고 결과는 아래로 펼친다. 바깥을 누르면 닫는다(`pointerdown`을 잡는 단계에서 보고 막지 않는다. 노드를 Ctrl+누르면 그 노드도 골라진다). Esc도 닫는다.
- **도움말**(사전 끝 `boardKeys`). 고르기·잇기 단추의 툴팁에 ← 키, 위 찾기 단추의 툴팁에 ↑ 키와 바깥 누르기·Esc로 닫기, 명령 바 입력칸의 툴팁에 Ctrl+K·↓ 키와 아래 가장자리로 띄우기를 적었다.
- **시험 고리**: `window.__mt.pinBottom(true|false)`. 창 시험이 아래 바를 늘 보이게 고정한다. 고정은 sessionStorage에 두어 창을 다시 읽어도 남고, 창을 닫으면 사라진다.

### 방향키 충돌

- React Flow: 노드 테두리에 초점이 있고 그 노드가 골라져 있으면 방향키로 노드를 옮겼다. 이제 조합 키 없는 네 방향키는 판이 먼저 받으므로 이 이동은 일어나지 않는다. Shift+방향키는 판이 받지 않으므로 React Flow 동작 그대로다(확인하지 않았다).
- 명령 바의 위·아래(보낸 글 기록, 대상 후보 고르기)와 찾기 바의 위·아래(결과 고르기)는 입력칸 안이라 그대로다.
- 노드에 들어간 직후 터미널이 붙기 전 8초 동안 모으는 키(H4)는 방향키도 그대로 터미널로 모은다.

### 계획과 다른 곳

- 지시에 없던 `store.js`를 고쳤다(`bottomShown`, `bottomPin`과 그 설정 함수).
- 왼쪽 키로 고르기로 돌아갈 때 노드 고름은 풀지 않는다. 고르기 단추를 마우스로 누르면 지금처럼 고름을 푼다.
- 위 찾기 단추를 찾기 바가 열린 채 누르면, 바깥 누르기로 닫힌 뒤 같은 누르기로 다시 열린다. 결과는 열린 채이고 입력칸 글이 골라진다.
