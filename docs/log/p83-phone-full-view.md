## 지시

### 목표

휴대폰(iPhone Safari) 화면의 다섯 가지를 고친다. 전체 보기(`PhoneFull.jsx`)는 위 띠가 흐리고, 글자를 가장 작게 해도 크고, 나가는 길을 모르면 못 나가고, 아래에 빈 띠가 남는다. 보드 화면은 아래 명령 줄을 열 수 없다.

### 사용자의 말(2026-11-07, `v0.1.4-dev.2`, iOS Safari)

"핸드폰에서 봤을 때 상단 부분에 뭔가 흐릿한데..ios 기능인가? 터미널 제목이 너무 상단에 붙어있어서 그런지 좀 흐리다. 그리고 글자 줄이고 키우는 옵션이 잇긴 한데 최대한 줄여도 좀 나한테 큼. 작아지는게 더 좋은거같음. 그리고 화면 나가기 할때 zoom out 하면 되던데 (특정 세션 클릭하면 해당 세션으로 줌 되는거) 뭔가 그걸 모르면 우야노? 나가기 버튼같은게 있으면 좋겠다. 그리고 아이폰에서 봤을 때 하단이 안채워져있는건데 이건 뭐임?"

사용자의 화면 그림은 git 밖 `C:\Workspace\multitask\experiments\p83\user-ios-full.png`에 있다(세로 iPhone, Safari, 전체 보기). 실제 대화 내용이 보이므로 그림을 옮기거나 저장소에 넣지 않고, 작업 기록에는 모양만 적는다. 그림에서 보이는 것:

- 위 띠(점, 세션 이름, "준비 완료", "탭하면 보드로", A−, A+)가 상태 표시줄 바로 아래에 붙어 있고, 띠 전체가 흐리게 번져 보인다.
- 터미널 글자가 커서 Claude Code가 "Resize your terminal to at least 110 columns to show the diff"를 띄운다.
- 키 줄 아래에 페이지 색 띠(약 45pt)가 있고, 그 아래 화면 맨 끝(약 70pt)은 더 검은 띠로 비어 있다.

### 할 것

1. **위 띠 흐림.** 원인을 찾아 적는다. 후보: iOS Safari가 상태 표시줄 아래(위 가장자리)에 그리는 흐림·색 띠, 판 CSS의 `backdrop-filter`·투명도·글자 색, `viewport-fit`과 `env(safe-area-inset-top)` 처리. 판 탓이면 고치고, Safari 탓이면 띠를 안전 영역 아래로 충분히 내리거나 위 가장자리 색을 맞춰 흐림 띠에 걸리지 않게 한다. 띠의 글이 또렷해야 한다.
2. **더 작은 글자.** 휴대폰 전체 보기의 A−로 지금 가장 작은 값(`lib/scale.js` 70%)보다 더 작게 줄일 수 있게 한다. 세로 iPhone(390pt 폭 안팎)에서 Claude Code가 110칸 안팎을 받을 수 있는 크기까지를 목표로, 읽을 수 있는 가장 작은 값을 재어 정한다. PC 창의 터미널 글자 배율(70~150%)은 바꾸지 않는다. 저장된 값과 새 하한이 맞지 않으면 안전하게 맞춘다.
3. **나가기 단추.** 전체 보기 위 띠에 보드로 돌아가는 단추를 눈에 띄게 둔다(예: 왼쪽 "← 보드"). 지금의 위 띠 누르기, 뒤로 쓸기, 오므리기는 그대로 둔다. "탭하면 보드로" 글은 단추가 생기면 줄이거나 뺀다. 두 사전, 지금 말투. 휴대폰 목록 화면이나 다른 웹 화면에서도 같은 길이 필요하면 보고에 적는다.
4. **아래 빈 띠.** 키 줄 아래가 비는 원인을 찾아 적는다. 후보: `innerHeight`·`visualViewport`·`100vh`/`dvh` 높이 차이, 홈 표시줄 안전 영역(`env(safe-area-inset-bottom)`)과 `mt-kb-open` 처리, `html`·`body` 배경, Safari 아래 도구 막대가 접힐 때의 높이. 화면이 아래 끝까지 판 색으로 차고, 키 줄은 홈 표시줄 바로 위에 붙고, 남는 높이는 터미널이 갖게 한다. 키보드가 올라올 때(P74·P76)의 동작은 그대로 지킨다.

5. **휴대폰의 아래 명령 줄.** 사용자의 말(같은 날): "그리고 모바일 환경에서는 커서가 따로 없어서 하단 명령줄이 절대 안켜짐. 이건 그냥 고정해놓던지 알아서 해봐". 아래 명령 바(P43 자동 숨김)는 마우스가 아래 띠에 머물 때 나타나므로 손가락 포인터에서는 열 길이 없다. 손가락 포인터(`pointer: coarse`)나 휴대폰 보드 화면에서는 명령 바를 늘 보이게 두거나, 아래의 얇은 표시를 탭하면 열리게 하는 것 중 하나를 근거를 들어 고른다(보드를 가리는 높이, 키보드가 올라올 때 입력칸이 가려지지 않는지, 터치 규칙과 부딪히지 않는지를 잰다). 마우스가 있는 PC·노트북의 자동 숨김은 그대로 둔다.

## 작업 기록

- 시작: `git fetch origin && git merge --ff-only origin/dev`(ae5046d). 워크트리 안에서 `npm ci`(백엔드, 창)와 Electron 받기. 물려받은 판 변수를 지우는 `backend/.dev/clean-env.sh`와 이 판 값(atrium-dev-p83, 47897, `backend/.dev/data`·`app`)만 넣는 `backend/.dev/p83-board.mjs`를 만들어 시험, CLI, herdr를 그것으로 불렀다(저장소 밖).
- 사용자 그림(모양만): 세로 iPhone, 1179×2556(3배, 393×852pt). 브라우저 막대가 없어 홈 화면 웹 앱(standalone)으로 본다. 위 띠는 상태 표시줄(위 안전 영역 약 59pt) 바로 아래 63~95pt, 글자 칸은 약 5.9pt(9.8px, 배율 70%)로 약 64칸. 키 줄 아래에 키 줄 색 띠 약 40pt(아래 안전 영역 34 + 6), 그 아래 검은 띠 약 59pt.
- 원인 1, 아래 빈 띠: 검은 띠 높이가 위 안전 영역과 같다. iOS 홈 화면 앱(`black-translucent`, `viewport-fit=cover`)은 `innerHeight`·`visualViewport.height`·`100vh`를 화면보다 상태 표시줄만큼 짧게 줄 때가 있다(WebKit 버그 236445, 같은 증상의 공개 사례 여럿). 전체 보기는 `visualViewport.height`(793)로 높이를 정하므로 852까지 59pt가 남고, 그 자리에 판 바탕색(#070705)이 보였다. iOS의 높이를 그대로 믿은 판 탓과 iOS 탓이 겹친 것이다.
- 원인 2, 위 띠 흐림: 판 CSS에는 위 띠를 덮는 `backdrop-filter`·투명도가 없다(`backdrop-filter`는 미션 맵 하나). 위 띠는 불투명 `--chrome-bg`다. 흐림은 띠 전체(글과 단추)에 고르게 걸리고 그 아래 터미널 글은 또렷하다. iOS 26이 상태 표시줄 아래 위 가장자리에 그리는 흐림(스크롤 가장자리 효과, 범위가 안전 영역보다 조금 넓다)으로 본다. 이 흐림은 iOS가 그리므로 Chromium 흉내로는 재현되지 않는다. 그래서 띠의 글을 안전 영역보다 14px 더 내렸다(전 4px).
- 원인 3, 명령 바: P43 자동 숨김은 `pointermove`의 마우스 자리로만 연다. 손가락은 누른 채 움직일 때만 `pointermove`가 오고(`buttons`), 숨은 동안 누른 채 움직임으로는 띄우지 않는다. 또 휴대폰 보드에서 바 폭이 `calc(100% - 340px)` = 52px였다(`before-01-board.png`).
- 고른 것, 명령 바: "늘 보이기" 대신 "아래 손잡이 단추를 탭하면 연다". 늘 보이면 바(60) + 아래 여백(약 28) + 칩 줄이 852 화면의 110pt 남짓(13%)을 가린다. 손잡이는 34pt 알약 하나다. 탭하면 입력칸에 초점을 줘 키보드가 바로 올라오므로 한 번에 쓸 수 있다. 판의 터치 규칙(P76)은 캔버스 요소의 캡처 단계라 캔버스 밖 손잡이와 부딪히지 않는다. 키보드가 올라오면 바를 보이는 높이 안으로 올리고(가려지지 않는다), 판을 탭하면 초점을 풀어 바가 숨는다(문서 캡처 단계의 수동 `touchstart`로 초점만 푼다. 판은 손가락을 그대로 받는다).
- 고친 것:
  - 글자: `lib/scale.js clampPhoneScale`(40~150%, 5% 단위, 없음·이상한 값은 기본 80%, 범위 밖은 끝 값). `termFontSize`가 맞추기 함수를 받고, `TerminalView`는 `fontScale`(휴대폰 화면만 준다)이 있을 때만 휴대폰 맞추기를 쓴다. PC 창 배율(`clampScale` 70~150%)은 그대로. `Phone.jsx readPhoneScale`·A−/A+와 `PhoneFull.jsx`가 같은 맞추기를 쓴다. A−는 40%에서, A+는 150%에서 막힌다.
  - 하한 40%(5.6px): JetBrains Mono 글자 폭은 0.6em이라 칸 3.36px. iPhone 393pt 폭에서 에이전트 387px/3.36 = 115칸, 셸(스크롤 막대 14px) 111칸. 375pt 폭(작은 iPhone)은 109칸 안팎. 45%(6.3px)는 102칸이라 모자란다. 3배 화면에서 5.6px는 장치 픽셀 17 높이라 그림에서 읽을 수 있었다(`after-10-full-smallest-zoom.png`).
  - 높이: `lib/phone.js screenBox`. 홈 화면 앱이고, 키보드가 닫혔고(보이는 높이가 창 높이보다 120 넘게 작지 않고 밀림 없음), 화면 높이(세로면 `screen`의 긴 변)보다 모자란 만큼이 100px 안이면 화면 높이를 쓴다. 브라우저 탭과 키보드가 열린 때는 지금 그대로(`viewportBox`). `Phone.jsx useScreenFix`가 `html.mt-tall`과 `--mt-screen-h`로 `html`·`body`·`#root`를 늘리고(보드 화면도), 목록 화면과 전체 보기는 `screenNow()`로 높이를 정한다. 전체 보기가 덮지 못한 자리는 키 줄 색(`html.mt-full-on`). 키 줄 아래 여백은 `max(6px, 안전 영역 − 12px)`(34pt면 22pt)로 줄였다. 키보드가 올라올 때(P74·P76)의 처리는 바꾸지 않았다.

  - 사전: 두 사전 끝에 `phoneExit`(button 보드/Board, label 보드로 돌아가기, cmdOpen 명령 입력 열기, cmdShort 명령/Command). CSS는 `phone.css` 끝에 더했다(`styles.css`는 고치지 않음).

## 보고

### 한 것

1. 위 띠 흐림: 판 CSS 탓이 아니다(덮는 흐림·투명도 없음). iOS 26이 상태 표시줄 아래에 그리는 가장자리 흐림으로 보고, 띠의 글과 단추를 안전 영역보다 14px 더 내렸다. 흉내로는 재현되지 않아 iPhone에서 확인해야 한다.
2. 글자: 휴대폰 화면(목록의 세션 화면, 전체 보기)의 A−를 40%(5.6px)까지 내렸다. iPhone 393pt에서 에이전트 115칸, 셸 111칸(계산). PC 창 배율은 70~150% 그대로. 저장값은 40~150%로 맞추고 이상하면 기본 80%.
3. 나가기: 전체 보기 위 띠 왼쪽에 "‹ 보드" 단추. 띠 누르기, 뒤로 쓸기, 오므리기도 그대로. "탭하면 보드로" 글은 뺐다. 휴대폰 목록 화면은 이미 보드 단추와 "‹ 목록" 단추가 있어 더하지 않았다.
4. 아래 빈 띠: iOS 홈 화면 앱이 창 높이를 상태 표시줄만큼 짧게 주는 것이 원인이다. 홈 화면 앱에서는 화면 높이를 써서 보드, 목록, 전체 보기가 아래 끝까지 찬다. 남는 높이는 터미널이 갖고, 키 줄은 홈 표시줄 바로 위에 온다.
5. 명령 바: 손가락 화면에서는 아래 가운데 "명령" 손잡이를 탭하면 열리고 키보드가 올라온다. 바는 키보드 위로 올라가고, 판을 탭하면 닫힌다. 휴대폰 보드에서는 바가 화면 폭이다(전에는 52px). 마우스 PC는 그대로.

### 사람이 iPhone으로 확인할 순서

1. PC를 이 빌드로 업데이트하고, 그림과 같은 홈 화면 앱으로 연다.
2. 세션 하나를 탭해 전체 보기를 연다. 위 띠의 "‹ 보드", 이름, 상태가 또렷한지 본다. 아직 흐리면 흐린 범위가 띠의 어디까지인지(단추 위쪽만, 전부) 알려 준다(더 내릴 양을 정한다).
3. 화면 맨 아래까지 판 색으로 차고 검은 띠가 없는지, 키 줄이 홈 표시줄 바로 위인지 본다. 아래가 여전히 비면 그 높이를 알려 준다.
4. A−를 끝까지 눌러 읽을 수 있는지, Claude Code 세션에서 "Resize your terminal to at least 110 columns" 줄이 사라지는지 본다. 너무 작으면 A+로 한두 단계 올린다.
5. 입력칸을 눌러 키보드를 올리고 내린다. 키 줄과 입력 줄이 키보드 위에 남고, 내리면 다시 아래 끝까지 차는지 본다.
6. "‹ 보드"로 보드에 돌아온다.
7. 보드 아래 가운데 "명령" 손잡이를 탭한다. 바가 화면 폭으로 열리고 키보드 위에 보이는지, `@이름 글`을 보내면 전달이 나오는지, 판을 탭하면 닫히는지 본다.
8. 홈 화면 앱이 아닌 Safari 탭으로도 2~7을 한 번 본다. 이때는 높이 보정이 꺼지고 Safari 도구 막대가 아래 끝을 차지한다.

### 남은 것

- 위 띠 흐림과 아래 빈 띠는 iOS가 그리고 정하는 것이라 흉내로 재현되지 않았다. 원인은 그림의 수치와 공개 사례로 정했고, iPhone에서 확인해야 닫힌다.
