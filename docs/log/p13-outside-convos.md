## 지시

### 목표

판을 켜면 이 PC에서 터미널(CLI)로 한 Claude Code 대화가 리포별로 캔버스에 모두 보이게 한다. 사용자의 말은 다음과 같다.
- 데스크톱 앱 홈은 "CLI 세션 121개"를 보이는데, 판에는 셋만 보인다.
- 그 대화들이 잡고 있는 작업 폴더(리포)대로 워크스페이스를 나누고, 앱을 켜면 다 보였으면 한다.
- 리포로 묶이고, 대화끼리의 하위 세션 관계도 선으로 이어졌으면 한다.
- 지워진 시험 폴더와 개발용 판 폴더의 대화는 보관이 아니라 처음부터 지울 것이다. 이런 대화는 "missed"로 따로 빼고, 앱 안에서 한꺼번에 지우는 기능을 넣는다.

지휘 세션이 2026-10-31에 기록을 읽어 본 결과는 다음과 같다.
- CLI 출처 대화는 133개이고, 최근 3일 안이 119개다.
- 대부분은 이 앱을 만들며 띄운 시험 세션이다.
  - 폴더가 지워진 `C:\Workspace\mtask-p*-*`
  - 저장소의 `backend/.dev/proj`(34개)와 `experiments/proj`(11개)
  - 임시 폴더
  - 지워진 `.claude/worktrees/p*`
- 폴더가 남아 있고 시험 폴더가 아닌 최근 14일 대화는 6개 폴더, 19개다.
- 실제 판이 셋만 보이는 까닭은 둘이다.
  - 판 밖 대화가 사이드바 목록에만 있다.
  - 실제 판 백엔드가 P10(리포 스스로 찾기)보다 먼저 떠서 옛 코드로 돈다.

이미 있는 것을 바탕으로 만든다.
- 대화 색인 `convo_index`, 묶임 판정(`~/.claude/sessions/<pid>.json`, claude 명령줄, 데스크톱 목록), 보관 표시, 리포 스스로 찾기, 판으로 열기, 자리 찾기는 `backend/src/recall.mjs`, `convos.mjs`, `archive.mjs`에 있다.
- 셸 명령 나누기는 `links.mjs`에 있다.

### 정한 것

- **판에 올리는 대화.** CLI 출처(`entrypoint` `cli`)이고, 사람 요청이 하나 이상이며, 폴더가 남아 있고, 아래 missed 폴더가 아니며, 보관되지 않았고(기간과 손 보관은 P10 규칙 그대로), 판 세션에 묶이지 않은 대화.
  - 데스크톱 앱 대화는 지금처럼 보이지도 지우지도 않는다(BRIEF "데스크톱 앱").
- **대화 노드.** 읽기 전용 카드이고, 터미널이 아니다.
  - 보이는 것: 종류 아이콘, 제목(대화 제목이나 첫 요청), 마지막 요청과 답 앞부분, 마지막 활동 시각, 브랜치·워크트리, 하위 에이전트 수, 묶임 표시("터미널 · pid n에서 도는 중").
  - 동작: "판으로 열기"(지금의 판 밖 대화 이어 가기, 노드가 그 자리에서 세션 노드가 된다), 보관.
  - 다른 곳에서 도는 대화는 열지 않는다.
  - 줌 얼굴(가까이, 멀리, 아이콘)은 세션 노드와 같은 규칙으로 맞춘다.
  - 생김새는 P11 토큰과 콘솔 부품을 쓴다(`app/design/board-mock/`).
- **리포로 나누고 묶기.**
  - 대화마다 리포(폴더) 워크스페이스 영역이 판을 켤 때와 색인이 바뀔 때 저절로 열린다(리포 스스로 찾기를 노드까지 넓힌다). 사람이 닫은 워크스페이스는 지금처럼 다시 열지 않는다.
  - 영역 안의 순서: 판 세션이 먼저, 대화 노드는 그 아래나 옆에 최근 순으로 작은 카드 격자로 놓는다.
  - 자리는 다른 노드처럼 저장해 사람이 옮길 수 있다.
  - 같은 리포의 워크트리 대화는 그 리포 영역 안에 워크트리마다 묶어 보인다.
  - 영역 하나에 노드가 너무 많으면(예: 40개 넘게) 최근 것만 올리고 나머지는 사이드바에 둔다. 상한은 정해서 보고에 적는다.
- **대화끼리의 관계.** 기록만으로 알 수 있는 것을 선과 수로 보인다.
  1. 판 기록에 이미 있는 부모(가지 펼치기)는 그대로 쓴다.
  2. 띄움.
     - 한 대화의 셸 도구 호출 명령 글에서 새 claude를 띄운 줄을 찾는다.
       - 도구: Bash, PowerShell, 터미널 MCP의 run_in_terminal 등
       - 명령: `claude … -w <이름>`·`--worktree`, `herdr agent start`, `mtask child`·`mtask spawn`
     - 그 뒤 짧은 시간(정해서 적는다) 안에 시작한 다른 대화가 다음 중 하나에 맞으면, 그 대화를 하위로 보고 띄움 선(주황 실선)을 긋는다.
       - 워크트리 이름이나 폴더
       - 명령 속 첫 지시 글
     - 부모가 판에 없으면(데스크톱 앱 대화 등) 노드에 "띄운 곳"만 글로 적는다.
  3. 하위 에이전트(`<대화 ID>/subagents/*.jsonl`)는 따로 노드로 만들지 않는다. 부모 노드에 수를 적고, 누르면 목록(설명, 시각)을 보인다.
  - 관계 찾기를 위해 색인 파서를 넓혀야 하면 `CONVO_PARSER` 판을 올린다. 바뀐 파일만 다시 읽는 지금 방식은 지킨다.
- **missed.** 사용자가 부른 이름 그대로 분류 이름은 `missed`다. 화면 글은 "missed(지울 대화)"다.
  - 들어가는 것: CLI·SDK 출처 대화 가운데 다음 하나에 맞는 것.
    - 폴더가 없어졌다.
    - 이 앱의 시험 폴더다: 판 코드 저장소의 `backend/.dev`와 `experiments` 아래, OS 임시 폴더 아래, 이름이 `mtask-`로 시작하는 시험 폴더.
  - 보관(오래돼서 접어 둔 것)과 다른 분류다.
  - 지금 도는 대화, 판 세션에 묶인 대화, 데스크톱 앱 대화는 missed가 되지 않는다.
  - missed는 캔버스와 사이드바 기본 목록에 올리지 않는다.
- **한꺼번에 지우기.**
  - 사이드바에 보관함처럼 missed 함을 둔다.
    - 폴더별로 묶어 수, 크기, 마지막 활동을 보인다.
    - "모두 지우기", 폴더 하나 지우기, 하나 지우기가 있다.
    - 확인창에 지울 대화 수, 크기, 폴더 목록을 보인다.
  - 지우기는 바로 지우지 않고 Windows 휴지통으로 보낸다(Electron `shell.trashItem`이나 PowerShell VisualBasic `FileSystem`).
  - 지우는 것은 대화 기록 `<대화 ID>.jsonl`과 옆의 `<대화 ID>/` 폴더뿐이다. 비게 된 프로젝트 폴더는 지워도 된다.
  - 다음은 거부한다.
    - 대화 기록 폴더 뿌리(`MTASK_CLAUDE_PROJECTS`) 밖의 경로
    - 이름이 UUID가 아닌 파일
    - 지우는 순간 도는 대화, 묶인 대화, 데스크톱 대화
  - 지운 뒤 색인에서 뺀다. `mtask`에도 missed 보기와 지우기(`--yes`)를 둔다.

### 완료 기준

1. 고정 자료 판에서 다음을 확인하고 스크린숏을 남긴다.
   - 판을 켜면 고정 자료 대화가 리포마다 열린 영역에 대화 노드로 보인다.
   - 워크트리 묶음, 띄움 선, 하위 에이전트 수, 도는 중 표시, "판으로 열기"를 확인한다.
2. missed 함과 한꺼번에 지우기를 확인한다.
   - missed 함에 지워진 폴더와 시험 폴더의 고정 자료 대화가 보인다.
   - 모두 지우기와 폴더 지우기로 고정 자료 복사본이 휴지통으로 가고 목록과 색인에서 빠진다.
   - 거부 경우는 단위 시험으로 본다.
3. 실제 기록 읽기 보고를 남긴다.
   - 실제 `~/.claude/projects`를 읽기만 하는 스크립트로 분류별 수를 낸다(판에 올림, 보관, missed, 도는 중, 데스크톱 건너뜀).
   - 지휘 세션이 센 값(올림 6개 폴더 19개 안팎)과 견준다.
   - 이 스크립트는 판을 띄우지 않고 아무것도 지우지 않는다. 결과에는 수만 적고 제목, 요청 글, 경로는 적지 않는다.
4. 단위 시험을 더하고, 기존 단위 시험(백엔드 157, 창 34)이 통과한다.
   - 단위 시험 대상: 분류, 관계 찾기, 지우기 거부, 영역 안 자리.
   - 사이드바 목록과 리포 스스로 찾기를 쓰는 기존 창 시험(`p10-discover.mjs`, `p10-archive.mjs` 등)이 깨지면 고쳐 다시 돌린다.
5. 노드가 많은 판(고정 자료로 대화 60개 이상, 영역 5개 이상)에서 켜기와 줌이 느려지지 않는지 잰다.

### 2026-10-31 작업자 세션(워크트리 p13, 브랜치 worktree-p13)

**시작 상태.** 기준 커밋 86e1d99. `npm install` 뒤 백엔드 157, 창 34 단위 시험 통과. Electron 바이너리는 `node node_modules/electron/install.js`로 받았다.

**기록을 읽어 본 것(읽기만).**
- 지휘 세션이 이 작업자를 띄운 줄은 `mcp__terminal__run_in_terminal`의 `input.command`(`claude --model … -w p13 '<지시>'`)와 `input.cwd`다. 셸 도구 이름은 Bash·PowerShell만이 아니므로, `input.command`가 글인 도구 호출을 모두 셸 명령으로 본다.
- 하위 에이전트 폴더 `<대화 ID>/subagents/`에는 `agent-<id>.jsonl`과 `agent-<id>.meta.json`(`description`, `agentType`)이 있다. 수는 `.jsonl` 수, 목록은 meta의 설명과 파일 시각으로 낸다.

**설계(처음 계획).**
1. 파서(`convos.mjs`, `CONVO_PARSER` 3): 머리·꼬리 요약에 더해, 바뀐 파일은 셸 도구 호출만 골라 띄움 명령을 찾는다. 대화 기록은 덧붙기만 하므로 읽은 바이트 위치(`spawn_off`)를 색인에 두고 다음에는 늘어난 부분만 읽는다. 첫 훑기 비용을 줄이려고 띄움 읽기는 마지막 활동이 30일 안인 파일만 한다(그보다 오래된 부모는 화면에 오를 자식도 없다).
   - 띄움 명령: `claude … -w|--worktree <이름>`(셸 글 안의 글, `herdr pane run`, `herdr agent start -- claude …`도 풀어 본다), `herdr agent start <이름>`(뒤의 `herdr agent prompt <이름> "…"`를 첫 지시로 붙인다), `mtask child|spawn`(`--worktree`, `--cwd`, `--prompt`, 이름).
   - 자식 쪽 열쇠: 시작 시각(머리 첫 줄), cwd, 첫 지시 앞 40자의 해시. 글을 판 기록에 옮기지 않도록 해시만 둔다.

### 만든 것

1. **대화 노드.** 판 밖 CLI 대화를 리포 영역 안의 읽기 전용 카드로 올린다(`app/src/renderer/ConvoNode.jsx`).

   - 얼굴은 세션 노드와 같은 너비 기준(`lib/faces.js`, 이력 16px)이다. 터미널이 없으므로 가까이·중간은 같은 카드 얼굴이고, 140~200px는 멀리(제목, 시각), 140px 아래는 아이콘이다.
   - 카드 320×184, 한 줄 5장, 판 세션(그룹, 메모, 칸반) 아래 56px부터 최근 순 격자. 본 저장소 대화가 먼저이고 워크트리마다 줄을 새로 시작하며, 창이 워크트리 배경(주황 점선, `⎇ 이름 · 워크트리 대화 n`)을 그린다.
   - **상한은 영역마다 40개**(`CONVO_CAP`)다. 넘는 것은 사이드바 판 밖 대화 목록에만 있다. 사이드바 줄의 제목을 누르면 캔버스의 그 노드로 간다(`onCanvas`).
   - 자리는 표 `convo_nodes`에 둔다. 머리를 끌어 옮기면 `convo.move`로 저장하고, 영역 이름표를 끌면 함께 움직인다. 새 대화가 와도 놓인 카드는 그대로다. 보관하거나 판 세션이 되면 숨기고 자리는 남긴다.

   - "판으로 열기"는 P7의 판 밖 대화 이어 가기(`convo.open`)다. 카드 자리에 보통 크기 세션 노드가 들어가면 그 자리, 안 되면 작게, 그것도 안 되면 카드 바로 옆 빈자리에 놓는다.

   - 하위 에이전트(`<대화 ID>/subagents/agent-*.jsonl`)는 노드로 만들지 않는다. 수는 색인에, 목록은 `convo.subagents`(meta의 설명과 종류, 파일 시각)로 부를 때 읽는다.

   - 지우기: "모두 지우기", "폴더 지우기", 하나 "지우기"가 모두 확인창(수, 크기, 폴더 목록)을 거친다. 백엔드가 `<대화 ID>.jsonl`과 옆 `<대화 ID>/` 폴더를 PowerShell `Microsoft.VisualBasic.FileIO.FileSystem`으로 휴지통에 보내고, 비게 된 프로젝트 폴더(뿌리 바로 아래)를 지우고, 색인과 대화 노드에서 뺀다.

5. **API·mtask.** `convo.nodes`, `convo.move { convo, x, y }`, `convo.subagents { convo }`, `convo.classify`, `missed.list`, `missed.delete { all | folder | convos, confirm }`(확인 없이는 `needsConfirm`과 수·크기·폴더), `board.get`의 `convoNodes`·`convoEdges`, 이벤트 `convo.nodes`, `recall.list`·`recall.updated`의 `missed` 수. mtask `convo-nodes`, `classify`, `missed`, `missed rm (--all | --folder 폴더 | 대화 ID…) [--yes]`.

### 계획과 다른 곳

1. 워크트리 고정 자료는 git이 아닌 폴더의 `.claude/worktrees/<이름>`이다(지시: git init 하지 않음). 그래서 워크트리 블록 이름을 폴더 워크스페이스에서도 이 경로로 정한다. git 리포 워크스페이스의 워크트리는 단위 시험으로 봤다.
2. 도는 중 표시는 고정 자료 세션 파일 폴더(`MTASK_CLAUDE_SESSIONS`)에 직접 띄운 잠자는 node 프로세스의 pid를 적어 시험했다. 실제 claude의 세션 파일 판정은 P7·P10에서 본 것을 그대로 쓴다.
3. 시험 판에서 missed 접두어 규칙을 `MTASK_TEST_PREFIX=mtask-p13-x`로 바꿨다(고정 자료 폴더가 `mtask-p13-*`라서). 판 코드 저장소 규칙은 이 워크트리의 `backend/.dev/proj-p13`으로 시험했다.
4. 워크트리 이름이 있는 띄움은 그 워크트리 폴더의 대화만 자식으로 본다(첫 지시가 같아도 다른 폴더면 아니다). 단서의 세기는 워크트리 > 첫 지시 > 폴더다.
5. 카드 격자는 자기 영역 안의 것만 피하고, 다른 영역과의 겹침은 영역째로 민다(`settleRegions`). 그래서 대화가 많은 리포가 처음 열릴 때 다른 영역이 오른쪽·아래로 밀린다.
6. 사이드바의 데스크톱 묶임 줄은 P7처럼 "데스크톱 앱" 표시로 남겼다(지시의 "지금처럼"). 캔버스에는 올리지 않는다.
7. 지우기 직전의 묶임 판정은 출처 추측("출처가 cli가 아니면 묶여 있을 수 있음")을 빼고 세션 파일, 명령줄, 데스크톱 목록, 30초 안에 쓰였는지만 본다. 그러지 않으면 끝난 SDK 대화를 지울 수 없다.
8. 성능 기준을 재려고 창에 `window.__mt.setConvoNodes`(시험용)를 더했다.

### 알려진 문제

1. **실제 판은 다시 띄워야 P13이 된다.** 첫 훑기에서 `CONVO_PARSER`가 바뀌어 색인을 다시 만들고, 띄움 줄을 30일 안의 파일 전체(이 PC 약 4.9GB, 9초 남짓)로 읽는다. 대화 노드가 먼저 보이고 선은 그 뒤에 생긴다.
2. **지운 워크트리의 실제 일도 missed가 된다.** 지시대로 폴더가 없어진 CLI 대화는 missed다. 합친 뒤 지운 워크트리(`.claude/worktrees/p*`)의 작업자 대화도 들어가므로, 모두 지우기 전에 사람이 목록을 본다. 지우기는 휴지통으로 가서 되돌릴 수 있다. 지금 실제 기록에는 최근 14일 안에 그런 대화가 없다.
3. 띄움 찾기는 기록의 글만 본다. `echo claude -w x` 같은 글도 띄움으로 읽고, `input.command`가 아닌 도구로 띄운 것과 120초 뒤에 시작한 대화는 못 맞춘다. 이름 없는 `claude -w`는 첫 지시로만 맞춘다.
4. 판 세션이 띄운 판 밖 대화의 선(판 세션 → 대화 노드)은 코드로는 긋지만(열린 판 세션의 대화 ID를 노드로 바꿈) 창 시험으로 보지 않았다.
5. 실제 기록 읽기 수는 실제 판의 board.db를 읽지 않아 판 세션의 대화와 손 보관을 가리지 못했다. 그 대화는 올림이나 보관으로 셌다.
6. 홈 폴더·드라이브 루트에서 한 CLI 대화는 올림으로 분류되지만 그 영역을 열지 않으므로 캔버스와 사이드바에 없다(지금 실제 기록 0개).
7. 띄움 선이 중간 카드 뒤로 지나갈 수 있다(`p13-1-2`의 부모 → feat-x).
8. 휴지통에 이 시험의 고정 자료 복사본(대화 ID가 a013으로 끝나는 파일과 폴더)이 남아 있다. 비우지 않았다. 시험 claude가 `~/.claude.json`에 `mtask-p13-open`·`-cli` 프로젝트 항목을 남겼을 수 있다.
9. ARCH는 모듈 행만 더했다. 4절 J, 6절 API 표, 7.1 요소 표(대화 노드, 워크트리 배경, 띄움 선)는 바꾸지 않았다.
