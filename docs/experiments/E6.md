# E6. 터미널 노드(xterm.js)에서 한글 IME 입력

2026-10-29에 P2 창(`app/`)으로 했다. 결론부터 적으면 **자동화한 부분은 모두 됐다.** CDP 조합 이벤트로 Microsoft 한국어 IME와 같은 순서(자모가 쌓이는 조합 → 음절 확정)를 흉내 냈다. 조합 중에는 제어기로 아무것도 보내지 않았다. 확정된 음절만 한 번씩 보냈고, Claude Code 입력칸에 "한글가나다"가 그대로 나왔다. 조합 중 글자 지우기와 조합 취소도 맞았고, 판 배율이 1이 아닐 때(0.6)도 같았다. 명령 바(일반 입력칸)도 됐다.

다만 **실제 IME 창, 한/영 전환, 조합 중 Enter와 방향키는 자동화하지 못했다.** 4절 점검표로 사람이 확인한다.

## 1. 방법

| 항목 | 값 |
|---|---|
| 창 | P2 창(Electron 45.1.0, xterm.js 6.0.0), 개발용 프로필, 세션 `a`(`--model haiku`) |
| 도구 | Playwright의 Electron 지원으로 창을 띄우고, CDP 세션의 `Input.imeSetComposition`(조합 중 글자)과 `Input.insertText`(확정) |
| 기록 | 창 안에서 `terminal.input`으로 나가는 글을 모두 기록했다. 입력칸은 xterm 버퍼에서 `❯`로 시작하는 줄을 읽었다 |
| 스크립트 | `app/test/e2e/e6.mjs`. 원본 `experiments/p2/e6.txt`, 스크린숏 `e6-*.png` |

친 글은 끝난 뒤 지웠고 제출하지 않았다. 노드 터미널에 키보드로 "typed-from-node 한글"을 친 경우(`insertText` 경로)는 P2 완료 기준 2에서 따로 보았다(`experiments/p2/c2-spawn.txt`).

## 2. 결과

| 사례 | 넣은 이벤트 | 조합 중 보낸 것 | 확정 뒤 보낸 것 | 결과(배율 1, 0.6 같음) |
|---|---|---|---|---|
| 한글 | 조합 ㅎ → 하 → 한, 확정 한, 조합 ㄱ → 그 → 글, 확정 글 | 없음 | `한`, `글` | 입력칸 `❯ 한글` |
| 받침이 다음 음절로 | 조합 ㄱ → 가 → 간, 확정 가, 조합 나, 확정 나 | 없음 | `가`, `나` | `가나`(간이 남지 않음) |
| 조합 중 지우기 | 조합 ㄷ → 다 → 단 → 다(지움), 확정 다 | 없음 | `다` | `다` |
| 조합 취소 | 조합 ㅋ → 빈 글 | 없음 | 없음 | 입력칸에 변화 없음 |
| 명령 바 | 한글과 같은 순서 | | | 입력칸 값 `한글` |

- 마지막 입력칸: `❯ 한글가나다`(두 배율 모두)
- 조합 중에는 xterm의 조합 창(`.composition-view`)이 커서 자리에 조합 중 글자를 보였다(`e6-zoom1-composing.png`, `e6-zoom06-composing.png`). 배율 0.6에서도 커서 자리를 따라갔다.
- 판은 xterm.js의 조합 처리를 그대로 쓴다. 창 쪽에서 더한 것은 없다. 노드 터미널의 키 처리(Ctrl+G 막기, Ctrl+V 붙여넣기)는 조합 이벤트를 건드리지 않는다.

## 3. 확인하지 못한 것

CDP의 조합 이벤트는 브라우저 안의 조합 이벤트만 만든다. 아래는 실제 IME와 키보드가 있어야 한다.

- 실제 Microsoft 한국어 IME의 후보 창과 그 위치
- 한/영 키(또는 오른쪽 Alt), Shift+Space 전환
- 조합 중 Enter: 조합만 확정하는가, 바로 제출까지 하는가. Claude Code 입력칸에서 Enter는 제출이다
- 조합 중 방향키, Backspace, Esc
- 조합 중 판을 끌거나 확대·축소했을 때
- Win+H 음성 입력(명령 바는 일반 입력칸이라 될 것으로 본다)

## 4. 사람이 확인할 점검표

개발용 프로필로 창을 띄우고(`cd app && npm start`), 새 세션을 하나 띄운 뒤 그 노드 터미널을 눌러 초점을 준다. 끝나면 입력칸의 글은 지운다. 각 항목에서 화면에 보이는 것과 Claude Code 입력칸의 결과를 본다.

1. 한글 모드에서 "안녕하세요"를 친다. 조합 중 글자가 커서 자리에 보이고, 입력칸에 "안녕하세요"가 한 번만 들어가는가(자모가 남거나 두 번 들어가지 않는가)
2. "닭"(겹받침), "값을"(받침이 다음 음절로)을 친다. 결과가 맞는가
3. "한"까지 조합한 채 Backspace를 한 번 누른다. "하"로 돌아가는가. 한 번 더 누르면 "ㅎ", 다시 누르면 사라지는가
4. "한"까지 조합한 채 Enter를 누른다. 결과를 적는다: (가) "한"만 확정되고 제출되지 않음 (나) "한"이 확정되고 바로 제출됨 (다) "한"이 사라짐
5. 한/영 키로 바꿔 가며 "abc한글def"를 친다. 순서와 글자가 맞는가
6. 판 배율을 0.6쯤으로 줄이고(가까이 얼굴이 유지되는 정도) 1번을 다시 한다. 조합 중 글자와 후보 창이 커서 근처에 뜨는가
7. 조합 중에 마우스로 판의 빈 곳을 끌어 옮긴다. 조합 중 글자가 사라지거나 엉뚱한 곳에 확정되지 않는가
8. 명령 바(Ctrl+K)에서 "@이름 안녕하세요"를 치고, 조합 중 Enter가 조합 확정만 하고 보내지 않는지, 한 번 더 Enter를 눌러야 보내지는지 본다
9. 명령 바에서 Win+H로 한국어 음성 입력을 해 본다

## 5. 계획에 반영할 것

1. PLAN 7절 P0 표의 E6: "자동화한 부분은 됨(조합 중 보내지 않음, 음절마다 한 번, 배율 무관). 실제 IME 점검표는 사용자 확인 대기"로 바꾼다.
2. BRIEF 6절 위험 1: 위 결과를 적는다. 점검표 4번(조합 중 Enter)의 결과에 따라 노드 터미널에서 조합 중 Enter를 따로 다룰지 정한다.
