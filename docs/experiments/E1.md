# E1. node-pty(ConPTY)로 `claude.exe`를 띄워 입력하고 제출할 수 있는가

2026-10-29에 했다. 결론부터 적으면 **된다.** node-pty 1.1.0의 ConPTY 프리빌드로 `claude.exe`를 띄워 출력을 받고, 글을 넣고, Enter로 제출하고, `/exit`로 종료 코드를 받았다. 다만 판이 띄우는 세션에는 시작 대화상자, 환경 변수, 화면 모델 세 가지 손질이 필요하다. 아래에 적었다.

## 1. 환경

| 항목 | 값 |
|---|---|
| OS | Windows 11 Pro 10.0.26200 |
| Node | v24.19.0, npm 12.0.2 |
| node-pty | 1.1.0. `prebuilds/win32-x64`에 `conpty.node`, `pty.node`, `winpty-agent.exe`가 들어 있어 빌드 도구 없이 바로 불러온다. npm 12가 설치 스크립트를 막았다고 경고하지만, 그 스크립트는 프리빌드 유무만 확인하므로 `require('node-pty')`는 그대로 된다. |
| Claude Code | 2.1.312, `%USERPROFILE%\.local\bin\claude.exe` |
| 시험 폴더 | 세션 스크래치패드 아래 새 폴더(`scratchpad/proj`). 데스크톱 앱 세션과 기존 세션은 쓰지 않았다. |
| 스크립트 | `experiments/common.cjs`(공통), `experiments/e1.cjs`. 원본 결과는 `experiments/e1-result.json` |

띄운 방법은 다음과 같다.

```js
pty.spawn('%USERPROFILE%/.local/bin/claude.exe', ['--session-id', uuid, '--no-chrome'], {
  name: 'xterm-256color', cols: 120, rows: 40, cwd: projDir, env: cleanEnv, useConpty: true,
});
```

## 2. 절차와 결과

세션 하나로 아래 순서를 돌렸다. 시각은 `spawn` 호출부터 잰 값이다.

| 단계 | 한 것 | 결과 |
|---|---|---|
| 첫 출력 | `onData` 첫 호출 | 58ms |
| 준비 | 배너와 입력 상자가 그려지고 1.2초 조용해질 때까지 | 2,280ms. 그때까지 1,705바이트, 9조각 |
| 쉬는 동안 | 준비 뒤 5초 가만히 둠 | 출력 0바이트, 0조각 |
| 글 넣기 | `write('Reply with exactly the phrase zebra-kite-lamp and nothing else.')` | 62ms 뒤 화면에 그 글이 보임 |
| 제출 | `write('\r')` | 216ms 뒤 대화 기록(`~/.claude/projects/.../<session-id>.jsonl`)에 user 항목, 1,407ms 뒤 assistant 항목 `"zebra-kite-lamp"`. 화면의 `· done` 표시는 1,405ms |
| 턴 출력량 | Enter부터 답까지 | 1,094바이트, 20조각 |
| 크기 조정 | `resize(90, 30)` | 2,171바이트 다시 그림. 프로세스 살아 있음 |
| 종료 | `write('/exit')` 뒤 `write('\r')` | 2,018ms 뒤 `onExit`에 종료 코드 0 |

세션 전체 출력은 5,892바이트, 43조각이었다. 조각 크기는 최소 3, 중앙값 32, p90 332, 최대 1,547바이트다.

`--session-id`로 넘긴 UUID가 그대로 대화 기록 파일 이름이 됐다. 파일은 `~/.claude/projects/<cwd를 '-'로 바꾼 이름>/<session-id>.jsonl`에 생겼다.

## 3. 관찰

### 3.1 새 폴더에서는 시작 대화상자가 뜬다

- **신뢰 확인:** 처음 쓰는 폴더에서는 "Quick safety check … Is this a project you created or one you trust?" 대화상자가 먼저 뜬다. 기본 선택이 **"No, exit"** 라서 Enter만 보내면 종료 코드 1로 끝난다. 아래 화살표(`\x1b[B`)를 보낸 뒤 Enter를 보내면 "Yes, I trust this folder"가 골라진다. 대화상자가 그려지는 중(spawn 뒤 약 0.4초)에 키를 보냈을 때는 선택이 어긋나 "No, exit"로 끝났고, 출력이 0.8초 이상 조용해진 뒤 보냈을 때는 제대로 됐다. 답은 `~/.claude.json`의 `projects[<폴더>].hasTrustDialogAccepted`에 저장되어 같은 폴더에서는 다시 묻지 않는다.
- **Chrome 확장 확인:** 신뢰를 통과하면 "Claude in Chrome extension detected … ❯ No, keep browser tools off / Yes, use my browser" 대화상자가 또 뜬다. `--no-chrome`을 넘기면 뜨지 않는다.
- **렌더러 되돌림:** 시작 중에 프로세스를 강제로 끈 다음 실행에서는 "Claude Code's fullscreen renderer didn't finish starting last time on this machine, so this launch is using the classic renderer"라고 나오며 클래식 렌더러로 돈다. 다음 실행에서는 다시 전체 화면 렌더러를 쓴다.

### 3.2 부모 Claude Code 세션의 환경 변수를 지워야 한다

이 실험은 Claude Code 세션 안에서 돌렸다. `process.env`를 그대로 물려주면 자식 `claude`가 `CLAUDE_CODE_CHILD_SESSION` 표시를 보고 **대화 기록 저장을 끈다**("⚠ Transcript saving is off — inherited CLAUDE_CODE_CHILD_SESSION marker"). 당시 물려받은 변수는 `CLAUDECODE`, `CLAUDE_CODE_CHILD_SESSION`, `CLAUDE_CODE_ENTRYPOINT`, `CLAUDE_CODE_EXECPATH`, `CLAUDE_CODE_MESSAGING_SOCKET`, `CLAUDE_CODE_MESSAGING_TOKEN`, `CLAUDE_CODE_SESSION_ATTENDED`, `CLAUDE_CODE_SESSION_ID`, `CLAUDE_AGENT_SDK_VERSION`, `CLAUDE_EFFORT`, `CLAUDE_PID`였다. 이 이름들을 지우고 띄우자 기록이 정상으로 남았다. 백엔드가 Claude Code 세션에서 개발 중에 실행될 수 있으므로, 세션을 띄울 때 `CLAUDECODE`, `CLAUDE_CODE_*`, `CLAUDE_PID`, `CLAUDE_EFFORT`, `CLAUDE_AGENT_SDK_*`를 환경에서 빼야 한다.

### 3.3 화면은 글자 흐름이 아니라 커서 이동으로 그린다

- 전체 화면 렌더러는 대체 화면(`?1049h`)을 켜고, 줄바꿈 대신 커서 위치 지정으로 그린다. 공백도 `ESC [ n C`(커서 오른쪽 이동)로 표현해서, ANSI 시퀀스를 단순히 지우면 "Accessingworkspace"처럼 공백이 사라진다. 상태나 마지막 줄을 글자로 읽으려면 진짜 화면 모델(E4의 @xterm/headless)이 필요하다. 이 실험에서는 커서 이동을 공백으로 바꾸는 임시 처리로 감지만 했다.
- 켜는 모드: 대체 화면(`?1049`), 괄호 붙여넣기(`?2004`), 마우스 추적(`?1000`, `?1002`, `?1003`, `?1006`), 포커스 알림(`?1004`), `?2031`. 괄호 붙여넣기는 E3(글 넣기 방식)과 바로 이어진다.
- ConPTY 자체가 `?9001h`(win32-input-mode)를 보낸다. 이 모드를 지원하지 않아도 일반 VT 입력이 그대로 통했다.
- 쉬는 세션은 출력이 전혀 없다(5초에 0바이트). 전체 화면 렌더러에서는 한 턴의 출력량도 1KB 남짓이라, PLAN 2.2에서 걱정한 ConPTY 출력량은 이 조건에서는 문제가 아니었다. 클래식 렌더러로 돌 때는 스피너가 계속 다시 그려져 출력이 더 많다.

### 3.4 그 밖에

- pty가 열려 있는 동안 Node 이벤트 루프가 살아 있어서, 자식이 끝난 뒤에도 스크립트가 끝나지 않았다. 명시적으로 `process.exit`를 불렀다. 백엔드는 상주 프로세스라 문제가 아니지만, 시험용 CLI에서는 신경 써야 한다.
- 강제 종료는 `taskkill /PID <pid> /T /F`로 했다. 우리가 띄운 PID만 끄며, 이름으로 끄지 않았다. `claude`가 정상 종료한 뒤에 부르면 "already-exited"로 넘어간다.
- `/exit` 뒤 종료까지 2초가 걸렸다. 그 사이 `SessionEnd` hook이 온다(E2).

## 4. 계획에 반영할 것

1. **실행 계획(PLAN 5절)에 추가:** `--no-chrome`을 기본으로 넘긴다. 환경에서 부모 Claude Code 표시 변수를 뺀다.
2. **신뢰 대화상자는 사람이 답한다.** "마지막 Enter는 사람이 누른다" 원칙에 맞게 판은 자동으로 답하지 않는다. 대신 세션 상태에 "시작 대화상자 대기"가 필요하다. 전달 대기열(B1)은 이 상태에서는 보내지 않는다. 이 상태는 hook으로 알 수 없으므로 화면 모델에서 "Enter to confirm" 같은 글자로 잡거나, 판이 띄우기 전에 `~/.claude.json`의 `hasTrustDialogAccepted`를 읽어 처음 쓰는 폴더라고 미리 알려 준다(읽기만 한다).
3. **준비 판정:** SessionStart hook은 http로 오지 않는다(E2). 첫 출력 뒤 출력이 1초 남짓 조용해지면 ready로 보되, 대화상자가 떠 있지 않은지 화면 모델로 함께 본다.
4. **키 입력 시점:** 화면이 그려지는 중에 보낸 키는 어긋날 수 있다. 전달 대기열은 출력이 잠깐(수백 ms) 조용해진 뒤에 글을 넣는다.
5. **E4의 입력:** 전체 화면 렌더러의 대체 화면과 커서 이동 방식 그리기를 @xterm/headless가 재현하는지가 E4의 핵심이다.

## 5. 남은 질문

- 클래식 렌더러(`/tui default`)로 고정했을 때 출력량과 화면 모델 재현이 어떻게 다른지. 백엔드가 어느 쪽을 기준으로 할지는 E4 뒤에 정한다.
- 긴 글, 여러 줄, 한글 입력은 E3에서 본다. 이 실험의 입력은 영문 한 줄이었다.
