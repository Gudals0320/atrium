# E9. 권한 요청과 질문의 선택지에 `agent.send_keys`로 답할 수 있는가, 답한 뒤 어떤 hook이 오는가

2026-10-29에 했다. 결론부터 적으면 **모든 선택지에 답할 수 있다.** 숫자 키, 화살표와 Enter, `esc`, `tab`(승인에 지시 덧붙이기), `space`(여러 개 고르기)가 모두 통했고, 자유 입력은 `pane.send_text`로 글을 넣은 뒤 Enter로 됐다. 승인하면 PostToolUse hook이 오고 턴이 이어진다. **그러나 거부(`esc`, "No", 질문 취소)에는 hook이 하나도 오지 않는다.** herdr 상태만 blocked에서 idle로 바뀐다. 승인 카드와 waiting 상태는 hook이 아니라 herdr 상태로 닫아야 한다.

## 1. 방법

| 항목 | 값 |
|---|---|
| herdr | 0.9.5, 이름 있는 세션 `multitask-e9`. 깨끗한 환경으로 띄우고 끝난 뒤 지웠다 |
| Claude Code | 2.1.312, `--permission-mode manual`, `--settings`(http hook), 폴더 `experiments/proj` |
| 도구 | `experiments/lab-daemon.cjs`, `lab.cjs`, `labfn.sh`. 원본은 `e9-timeline.json`, `e9-run.log`. `e9-timeline-try1.json`은 구독 오류로 herdr 상태가 빠진 첫 시도(P1과 같은 결과) |

사례마다 글을 보내고, `agent.wait { until: ["blocked"] }`로 기다린 뒤 화면을 읽고, `agent.send_keys`로 답하고, 그 뒤 hook과 herdr 상태 이벤트를 모았다. 만든 파일은 끝난 뒤 지웠다.

## 2. 결과

### 2.1 도구 권한 요청

Write 권한 요청 화면은 아래와 같다.

```
 Do you want to create e9-a.txt?
 ❯ 1. Yes
   2. Yes, and switch to accept edits (auto-approve file edits and common file commands) for this session (shift+tab)
   3. No

 Esc to cancel · Tab to amend
```

| 사례 | 보낸 키 | 결과 | 답한 뒤 hook | herdr 상태 |
|---|---|---|---|---|
| P1 Write | `esc` | 거부. 화면 "User rejected write to e9-a.txt", 턴 끝 | **없음** | blocked → working → idle |
| P2 Write | `3` | 거부, 턴 끝 | **없음** | blocked → idle |
| P3 Write | `1` | 승인, 파일 생김 | PostToolUse(Write) → Stop | blocked → working → idle |
| P4 Write | `down`, `enter` | 승인 + 이 세션을 acceptEdits로 바꿈 | PostToolUse(Write) → Stop. 이후 모든 hook의 `permission_mode`가 `"acceptEdits"` | blocked → working → idle |
| P5 Write(P4 뒤) | 없음 | 묻지 않고 실행 | PreToolUse → PostToolUse. PermissionRequest 없음 | blocked 없음 |
| P6 PowerShell | `tab`, `pane.send_text "after running, also say AMENDED"`, `enter` | 승인 + 지시 덧붙임. 모델이 출력 뒤 "AMENDED"를 말함 | PostToolUse(PowerShell) → Stop. **덧붙인 글은 어느 hook에도 없음** | blocked → working → idle |
| P7 Bash | `4`(No) | 거부. 화면 "Interrupted · What should Claude do instead?" | **없음** | blocked → idle |

- **선택지 수와 문구는 도구와 상황마다 다르다.** Write는 3개, Bash(`mkdir -p e9-dir`)는 4개(`Yes` / `Yes, and always allow access to C:\…\proj from this project` / `Yes, and switch to auto mode` / `No`), PowerShell은 2개(`Yes` / `No`)였다. `tab`을 누르면 PowerShell의 1번이 "Yes, and tell Claude what to do next"로 바뀌고, 친 글이 그 줄에 나타났다.
- **PermissionRequest의 `permission_suggestions`는 화면 선택지와 다르다.** Write: `[setMode acceptEdits(session)]`. Bash: `[addDirectories proj(session), setMode acceptEdits(session)]`. 화면의 "auto mode" 선택지는 제안 목록에 없다. 카드의 선택지는 화면에서 읽어야 한다.
- 이 PC에서는 PowerShell 도구의 모든 명령에 "Command contains malformed syntax that cannot be parsed: pwsh exited with code 1: <깨진 글자>" 경고가 붙었고, 그래서 "다시 묻지 않기" 선택지가 나오지 않았다. Claude Code 쪽 문제로 보이며 이 실험 범위 밖이다.
- `shift+tab`은 권한 모드를 manual → accept edits → plan → manual 순으로 돌렸다.

### 2.2 AskUserQuestion

단일 선택 화면은 아래와 같다.

```
 ☐ Color

Which color?

❯ 1. Red
     Red
  2. Green
  …
  4. Type something.
  5. Chat about this

Enter to select · ↑/↓ to navigate · Esc to cancel
```

| 사례 | 보낸 키 | 결과 | 답한 뒤 hook |
|---|---|---|---|
| Q1 단일 선택 | `down`, `enter` | "Green" | PostToolUse(`tool_input.answers: {"Which color?": "Green"}`) → Stop |
| Q2 단일 선택 | `3` | 숫자만으로 바로 고르고 제출됨, "Blue" | PostToolUse → Stop |
| Q3 자유 입력 | `4`, `pane.send_text "Purple 보라색"`, `enter` | 4번 줄이 "4. Purple 보라색"으로 바뀐 뒤 제출 | PostToolUse(`answers: "Purple 보라색"`) → Stop |
| Q4 취소 | `esc` | 화면 "User declined to answer questions", 턴 끝 | **없음.** herdr blocked → idle |
| Q5 "Chat about this" | `5` | 도구가 답 없이 끝나고 모델이 무엇을 묻고 싶은지 되물음 | PostToolUse **없음**, Stop 옴 |
| Q6 여러 개 고르기(3개) | `space`(1번 켬), `3`(3번 켬), `down`×4(Submit으로), `enter`, 확인 화면에서 `enter` | "Apple, Cherry" | PostToolUse(`answers: {"Which fruits?": "Apple, Cherry"}`) → Stop |
| Q7 질문 두 개 | `2`, `1`, 확인 화면에서 `enter` | "Green", "Small" | PostToolUse(`answers: {"Which color?": "Green", "Which size?": "Small"}`) → Stop |

- 여러 개 고르기에서 `space`는 커서가 있는 항목을, 숫자는 그 번호 항목을 켜고 끈다(제출하지 않는다). 목록 아래 "Submit"에서 Enter를 누르면 **확인 화면**("Ready to submit your answers? ❯ 1. Submit answers 2. Cancel")이 한 번 더 나온다. 질문이 여러 개일 때도 마지막에 같은 확인 화면이 나온다. 단일 질문 하나일 때는 확인 화면이 없다.
- 질문이 여러 개면 숫자 키로 답하는 즉시 다음 질문으로 넘어간다(위쪽 탭 `← ☒ Color ☐ Size ✔ Submit →`).
- 여러 개 고르기의 답은 쉼표와 공백으로 이은 글 하나로 온다.
- Q6에서 오래 기다리는 동안 `Notification(permission_prompt)`이 blocked 뒤 약 24초에 왔다. P7(Bash)에서는 약 6초(E2와 같다). 질문과 권한 요청의 알림 시점이 다를 수 있다.

### 2.3 ExitPlanMode(계획 승인)

`shift+tab`으로 plan 모드로 바꾸고 한 단계짜리 계획을 시켰다. Claude Code는 계획을 `~/.claude/plans/<이름>.md`에 Write로 쓰고(PostToolUse(Write), `permission_mode: "plan"`), ToolSearch로 ExitPlanMode를 불러온 뒤 PreToolUse·PermissionRequest(ExitPlanMode)를 냈다. 화면 선택지는 `1. Yes, and use auto mode` / `2. Yes, manually approve edits` / `3. Tell Claude what to change`(shift+tab으로 의견과 함께 승인)였다. `2`를 보내자 PostToolUse(ExitPlanMode, `tool_response.plan`에 계획 전문)가 오고, 모드가 manual로 돌아가 다음 Write에서 다시 권한 요청이 떴다. 시험이 만든 계획 파일 `~/.claude/plans/fuzzy-shimmying-blossom.md`는 Claude Code가 만든 것이라 그대로 두었다.

### 2.4 키 보내기에서 주의할 점

- **`agent.send_keys`는 상태를 확인하지 않는다.** idle일 때 `1`을 보내자 입력칸에 "1"이 들어갔다(`backspace`로 지웠다). `agent.prompt`와 달리 막지 않는다.
- 키 이름은 쓰기 전에 검사한다. `foo`, `pageup`은 `invalid_key: unsupported key …`로 거부됐고 아무것도 들어가지 않았다. 통한 이름: `enter`, `esc`, `up`, `down`, `tab`, `shift+tab`, `space`, `backspace`, 숫자, `ctrl+c`, `ctrl+g`, `alt+x`, `f5`, `home`, `shift+enter`, `ctrl+j`.
- **`ctrl+g`는 Claude Code의 외부 편집기(메모장)를 연다.** 시험 중 메모장 창이 실제로 떴고, 시험 claude의 자식 프로세스(cmd → notepad)만 PID로 찾아 닫았다. 화면에는 "Save and close editor to continue..."가 나왔다. 질문 화면에도 "ctrl+g to edit in Notepad"가 보인다.
- `shift+enter`, `ctrl+j`는 CSI-u 형태(`ESC[13;2u`, `ESC[106;5u`)로 들어갔고, 편집기가 열린 동안 화면에 그 글자가 그대로 보였다. 더 보지 않았다.

## 3. 계획에 반영할 것

1. **3절 waiting의 해제 규칙:** waiting은 hook이 아니라 herdr 상태가 blocked에서 working이나 idle로 바뀔 때 끝낸다. 거부, 질문 취소, "Chat about this"에는 PostToolUse가 없다. hook만 보면 waiting이 영영 남는다.
2. **A1의 "답하기"와 9.4 `session.answer`의 키 순서를 정한다.** 커서 위치에 기대지 않도록 숫자 키를 기본으로 쓴다.

   | 카드 | 키 |
   |---|---|
   | 권한 승인 | `1` |
   | 권한의 그 밖 선택지(이 세션 자동 승인 등) | 그 번호 숫자 |
   | 권한 거부 | `esc`(선택지 번호가 바뀌어도 같다) |
   | 승인하면서 지시 덧붙이기 | `tab`, `pane.send_text <글>`, `enter` |
   | 질문 하나, 단일 선택 | 그 번호 숫자(바로 제출) |
   | 자유 입력 | "Type something" 번호, `pane.send_text <글>`, `enter` |
   | 여러 개 고르기 | 고를 번호 숫자들, `down`을 (선택지 수 + 1)번, `enter`, 확인 화면에서 `enter` |
   | 질문 여러 개 | 질문마다 번호 숫자, 확인 화면에서 `enter` |
   | 계획 승인 | 그 번호 숫자 |
   | 질문 취소 | `esc` |

3. **카드의 선택지 출처:** 질문은 hook(`PreToolUse(AskUserQuestion).tool_input.questions`)으로 그린다. 권한 요청은 선택지 수와 문구가 도구마다 다르고 `permission_suggestions`와도 다르므로 화면(`pane.read { source: "detection" }`)에서 읽는다.
4. **보내기 전 확인:** `agent.send_keys`는 상태를 보지 않으므로, 판은 보내기 직전에 `agent.get`으로 blocked인지, 카드의 요청(PreToolUse의 `tool_use_id`)에 아직 PostToolUse가 오지 않았는지 확인한다. 아니면 보내지 않고 카드를 닫는다.
5. **거부 기록:** 판에서 거부했으면 판이 보낸 키로 남긴다. 터미널에서 직접 거부한 경우는 hook이 없으므로 대화 기록에서 읽는다(대화 기록에 남는 모양은 P1에서 확인한다).
6. **카드에서 답할 수 없는 것:** "Chat about this", "Tell Claude what to change"는 대화로 이어지므로 카드는 "터미널에서 답하기"로 보낸다.
7. **금지 키:** 판은 `ctrl+g`를 보내지 않는다. 노드 터미널에서 사용자가 누른 `ctrl+g`도 메모장을 띄우므로, xterm.js에서 막을지 P2에서 정한다.
8. **노드 머리줄:** hook 본문의 `permission_mode`(`default`, `acceptEdits`, `plan`)를 표시한다. 카드의 선택이나 `shift+tab`으로 바뀐 모드가 여기에 나타난다.
