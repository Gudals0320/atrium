# E7. herdr 서버를 다시 시작하거나 강제 종료하면 claude 세션, 이어 가기, `--settings` hook은 어떻게 되는가

2026-10-29에 했다. 결론부터 적는다.

- **서버가 끝나면 그 서버의 claude도 함께 끝난다.** 정상 종료(`server stop`)와 강제 종료(서버 PID만 `taskkill /F`) 모두, 셸과 claude까지 남김없이 끝났다. 고아 프로세스는 없었다. claude는 두 경우 모두 SessionEnd hook(`reason: "other"`)을 보냈다.
- **서버를 다시 띄우면 herdr가 세션을 이어 간다.** 작업 공간, 패널 ID, 에이전트 이름이 그대로 돌아오고, 저장된 세션 ID로 `claude --resume <id>`를 자동 실행한다. 약 5초 뒤 idle이 된다. 대화 기록은 같은 파일에 이어진다.
- **그러나 기본 이어 가기는 판의 실행 인자를 버린다.** 명령줄이 `claude --resume <id>`뿐이라 `--settings`(hook), `--no-chrome`, `--permission-mode`가 빠진다. 판은 그 세션의 hook을 더 받지 못한다.
- **`pane.report_agent_session`의 `resume_argv`로 이어 가기 명령을 등록하면 herdr가 그대로 쓴다.** 이때 hook은 다시 오지만, `workspace.create`의 `env`로 넘긴 토큰이 되살아나지 않아 `Authorization` 헤더가 비었다.
- **끝나지 않은 턴은 잃는다.** 권한 요청을 기다리던 턴은 "User rejected"로 남았고, 출력 중이던 턴은 답 없이 끝났다.

## 1. 방법

| 항목 | 값 |
|---|---|
| herdr | 0.9.5, 이름 있는 세션 `multitask-e7`. 깨끗한 환경으로 띄우고 끝난 뒤 지웠다 |
| 도구 | `experiments/lab-daemon.cjs`(herdr 세션을 쥐고 HTTP로 한 단계씩 조작, hook 수신기 포함), `lab.cjs`, `labfn.sh`, `e7-pids.sh`. 원본은 `e7-timeline.json`, `e7-run.log` |
| 세션 | A(`e7a`): 한 턴을 끝내고 idle. B(`e7b`): Write 권한 요청에서 blocked. 둘 다 `experiments/proj`, `--session-id`, `--no-chrome`, `--permission-mode manual`, `--settings` |

hook 수신기는 도우미 데몬 안에 있어서 herdr 서버를 껐다 켜도 같은 주소로 계속 받았다.

| 단계 | 한 것 |
|---|---|
| 1 | 정상 종료: `herdr --session multitask-e7 server stop` |
| 2 | 다시 시작, A에 글 보내기. 그 뒤 A와 B에 `resume_argv` 등록 |
| 3 | A가 200줄을 출력하는 중에 서버 PID만 강제 종료(`taskkill /PID <서버> /F`, `/T` 없이) |
| 4 | 다시 시작, A에 글 보내기 |
| 5 | hook이 살아 있는 상태에서 서버 강제 종료 |
| 6 | 다시 시작, B에 글 보내기 |
| 정리 | A, B에 `/exit`, 서버 종료, `herdr session delete multitask-e7` |

## 2. 결과

### 2.1 프로세스

서버 아래 구조는 `herdr.exe`(서버) → `OpenConsole.exe`(패널마다 하나) → `powershell.exe`(Windows PowerShell 5.1, herdr 프롬프트 hook 포함) → `claude.exe`였다.

| 단계 | 끈 뒤 8초 안에 | hook |
|---|---|---|
| 1 정상 종료 | 서버, OpenConsole 2개, 셸 2개, claude 2개 모두 끝남 | SessionEnd 2개(`reason: "other"`), `server stop`이 돌아온 때(약 1.9초) |
| 3 강제 종료(A 출력 중) | 모두 끝남 | 없음. 이때 claude는 `--settings` 없이 이어진 상태였다(2.3) |
| 5 강제 종료(hook 있음) | 모두 끝남 | SessionEnd 2개(`reason: "other"`), 종료 뒤 약 30ms |

서버만 죽여도 콘솔이 닫히면서 셸과 claude가 끝났다. claude는 콘솔이 닫힐 때 SessionEnd hook을 보낼 만큼은 정리하고 끝난다.

### 2.2 되살리기

- herdr는 `%APPDATA%\herdr\sessions\<세션>\session.json`에 패널마다 `cwd`, `agent_name`, `managed_agent_kind`, `agent_session { source: "herdr:claude", kind: "id", value: <세션 ID> }`를 저장한다. `resume_argv`를 등록하면 `agent_resume { argv }`가 더해진다. 작업 공간의 `env`와 처음 실행 인자는 저장하지 않는다.
- 저장은 바뀔 때마다 바로가 아니라 이벤트에 따라 띄엄띄엄 한다(서버 로그의 "session saved": 07:36:20, 36:53, 37:17, 38:13, 38:45, 40:33 UTC). 바뀐 직후 강제 종료되면 그 변경을 잃을 수 있다(추정, 확인하지 않음).
- 다시 시작하면 서버가 57~66ms에 뜨고, 패널(`w1:p1`, `w2:p1`)과 에이전트 이름(`e7a`, `e7b`)이 그대로 돌아왔다. 상태는 `unknown`에서 서버가 뜬 뒤 5.1~5.7초에 `idle`이 됐다.
- 대화 기록은 같은 파일(`~/.claude/projects/…/<세션 ID>.jsonl`)에 이어졌다. 새 파일은 생기지 않았다.
- 재시작 뒤 초점은 첫 작업 공간에 있어서, B의 턴이 끝났을 때 상태는 `done`, A는 `idle`이었다(E0 3.2와 같은 규칙).
- E1에서 본 "fullscreen renderer didn't finish starting" 되돌림 문구는 강제 종료 뒤에도 나오지 않았다.

### 2.3 이어 가기 명령과 hook

| 시점 | claude 명령줄 | 판의 hook | `Authorization` | `X-MT-Session` | 본문 `session_id` |
|---|---|---|---|---|---|
| 처음 | `--session-id <id> --no-chrome --permission-mode manual --settings <파일>` | 옴 | 맞음 | 맞음 | 맞음 |
| 단계 2(기본 이어 가기) | `--resume <id>` | **안 옴.** herdr 상태 이벤트만 옴 | - | - | - |
| 단계 4(`resume_argv` 등록 뒤) | `--resume <id> --no-chrome --permission-mode manual --settings <파일>` | 옴 | **틀림(빈 토큰)** | **빈 값** | 맞음 |
| 단계 6(한 번 더) | 단계 4와 같음 | 옴 | 틀림 | 빈 값 | 맞음 |

- 등록은 `pane.report_agent_session { pane_id, source: "herdr:claude", agent: "claude", seq: <현재 ms>, agent_session_id, resume_argv: ["claude", "--resume", <id>, …] }`로 했다. herdr 문서의 설명대로 첫 요소는 명령 이름이어야 한다.
- 이어 간 claude가 시작할 때 사용자 설정의 herdr SessionStart hook(`herdr-agent-state.ps1`)이 세션을 다시 보고하지만(`resume_argv` 없이), 등록한 `agent_resume`은 지워지지 않았다. 단계 6에서도 명령줄에 `--settings`가 남아 있었다.
- 헤더의 `$MT_TOKEN`, `$MT_SESSION`은 작업 공간 `env`에서 왔는데, 재시작 뒤 셸에는 그 값이 없었다. 본문의 `session_id`로는 세션을 계속 알아볼 수 있었다.
- 첫 등록 때 Windows 경로의 역슬래시가 빠진 채(`C:Workspacemultitask…`) 저장된 적이 있다. 같은 값을 다시 등록했을 때는 역슬래시가 그대로 남았다. 원인은 확인하지 못했다(이쪽 셸 따옴표 처리일 수 있다). 슬래시 경로(`C:/Workspace/…`)는 문제없었다.
- SessionStart http hook은 이어 갈 때도 오지 않았다(E2와 같다).

### 2.4 끊긴 턴

- B가 Write 권한 요청을 기다리던 중 정상 종료 → 재시작 뒤 화면에 "User rejected write to e7-b.txt"로 남고 B는 idle이었다.
- A가 200줄을 출력하던 중 강제 종료 → 재시작 뒤 화면에 그 지시만 있고 답은 없었다. A는 idle이었다.
- 두 경우 모두 hook이나 herdr 상태로는 "끊겼다"를 알 수 없다. 화면이나 대화 기록에서 읽어야 한다.

## 3. 계획에 반영할 것

1. **B3(새 세션 시작)에 단계를 더한다:** `agent.start` 직후 `pane.report_agent_session`으로 `resume_argv`(`claude --resume <id> --no-chrome --permission-mode <모드> --settings <파일>`)를 등록한다. 등록하지 않으면 herdr가 한 번만 다시 시작해도 그 세션의 hook을 영영 잃는다. 경로는 슬래시로 쓴다. 등록 뒤 `session.json`의 `agent_resume`을 읽어 저장을 확인한다(판 전용 세션의 파일, 읽기만 한다).
2. **hook 토큰을 작업 공간 `env`에 두지 않는다(B3 1번, 5절 실행 계획):** `env`는 재시작 뒤 되살아나지 않는다. 토큰과 세션 표시는 설정 파일 안에 값으로 직접 쓰고, 수신기는 본문 `session_id`로도 세션을 확인한다.
3. **설정 파일의 수명(BRIEF "상태 수집"의 "실행할 때마다 임시 설정 파일"):** 설정 파일은 이어 가기 때 다시 읽히므로 세션이 판에 있는 동안 지우지 않는다. `%LOCALAPPDATA%\multitask\sessions\<세션 ID>.json`처럼 고정 위치에 두고, 판이 세션을 닫을 때 지운다. hook URL이 그 안에 있으므로 백엔드 포트를 고정하는 규칙(1절)이 더 중요해진다.
4. **C3(herdr 재시작)을 구체화한다:** 패널 ID와 에이전트 이름이 그대로 돌아오므로 판은 그것으로 노드를 다시 찾는다. 상태는 재시작 뒤 약 5초 동안 `unknown`이다(starting으로 본다). 끊긴 턴은 hook으로 알 수 없으므로, 재시작 직전 상태가 working이나 waiting이던 세션은 "재시작으로 끊긴 턴"으로 표시하고 대화 기록 꼬리를 보여준다.
5. **3절 exited:** SessionEnd `reason: "other"`는 herdr 서버가 끝날 때도 온다. 판은 이것과 herdr 소켓 끊김이 함께 오면 "herdr가 꺼짐"으로, `prompt_input_exit`이면 정상 종료로 구분한다.
6. **정리(D2):** herdr 서버를 끄면 claude도 끝나므로 판이 claude를 따로 정리할 필요는 없다. 서버를 끌 때는 세션들이 이어 가기로 다시 뜬다는 점(끊긴 턴 포함)을 확인 창에 적는다.
7. **단계:** C3를 P3에서 P1으로 당긴다. 적어도 1번(`resume_argv` 등록)과 2번(토큰 위치)은 P1의 실행 계획 모듈에 들어가야 한다.
8. **열린 질문:** PC를 재부팅한 뒤에도 같은지는 보지 않았다. `session.json`이 저장되기 전에 강제 종료되면 등록을 잃는지도 확인하지 않았다.
