# E2. http hook이 이벤트마다 도착하는가, 상세가 들어오는가, 얼마나 걸리는가

2026-10-29에 했다. 결론부터 적으면 **쓸 수 있다.** `--settings`로 넘긴 임시 설정 파일의 `type: "http"` hook이 `UserPromptSubmit`, `PreToolUse`, `PermissionRequest`, `PostToolUse`, `Notification`, `Stop`, `SubagentStop`, `SessionEnd`에서 도착했고, `transcript_path`, `last_assistant_message`, 질문과 권한 상세가 모두 들어왔다. hook 하나는 Claude Code 쪽에서 재서 중앙값 5ms, 최대 25ms였다. 예외는 하나다. **`SessionStart`는 http hook을 부르지 않는다.** 같은 설정 파일의 command hook은 돈다.

## 1. 방법

| 항목 | 값 |
|---|---|
| 환경 | E1과 같다. Claude Code 2.1.312, node-pty 1.1.0, Node 24.19.0 |
| 수신기 | Node `http` 서버. `127.0.0.1`의 빈 포트. `POST /hooks/claude`를 받으면 바로 200(빈 본문)을 돌려주고 기록한다. |
| 설정 파일 | 이벤트마다 같은 http hook 하나. `timeout: 2`, 헤더 `Authorization: Bearer $MT_TOKEN`, `X-MT-Session: $MT_SESSION`, `allowedEnvVars: ["MT_TOKEN", "MT_SESSION"]`. 토큰과 세션 ID는 환경 변수로 넘겼다. 등록한 이벤트: SessionStart, UserPromptSubmit, PreToolUse, PostToolUse, PostToolUseFailure, PermissionRequest, PermissionDenied, Notification, Stop, StopFailure, SubagentStart, SubagentStop, PreCompact, PostCompact, SessionEnd |
| 실행 인자 | `--session-id <uuid> --no-chrome --permission-mode manual --settings <파일> --debug=hooks --debug-file <로그>` |
| 시간 측정 | 수신기의 도착 시각(Enter 기준), 수신기 처리 시간, 그리고 Claude Code의 `--debug=hooks` 로그에 찍힌 "HTTP hook POST" → "HTTP hook response" 간격 |
| 스크립트 | `experiments/e2.cjs`(모드 full, delay, down, notif), `experiments/e2-start.cjs`. 원본 결과는 `experiments/e2-result-*.json`, `experiments/e2-debug-*.log` |

사용자의 `~/.claude/settings.json`은 고치지 않았다. 거기 걸린 SessionStart command hook 두 개는 그대로 돌았다(각 230ms, 290ms 안팎).

다섯 번 돌렸다.

| 실행 | 내용 |
|---|---|
| full | 턴 3개. (1) "pong"만 답하기, (2) AskUserQuestion으로 질문하게 하기, (3) `echo hook-test-123` 실행시키기. 그 뒤 `/exit` |
| delay | 수신기가 PreToolUse 응답을 1.5초 늦게 돌려줌. Claude가 기다리는지 확인 |
| down | hook URL이 아무도 듣지 않는 포트. 턴이 막히는지 확인 |
| notif | 파일 쓰기(Write)로 권한 요청을 띄우고 12초 기다림. `Notification`이 오는지 확인 |
| start | SessionStart에 http hook과 command hook을 함께 걸고 프롬프트 없이 `/exit` |

## 2. 결과

### 2.1 도착한 이벤트(full 실행)

Enter를 보낸 시각 기준이다.

| 턴 | 이벤트 | 도착 | 비고 |
|---|---|---|---|
| T1 | UserPromptSubmit | +61ms | `prompt` 전문 |
| T1 | Stop | +3,754ms | `last_assistant_message: "pong"` |
| T2 | UserPromptSubmit | +30ms | |
| T2 | PreToolUse(AskUserQuestion) | +4,891ms | `tool_input.questions[]`에 질문, 선택지, `multiSelect` |
| T2 | PermissionRequest(AskUserQuestion) | +4,906ms | PreToolUse 15ms 뒤. 사람이 답하기 전 |
| T2 | PostToolUse(AskUserQuestion) | +5,662ms | Enter(첫 선택지) 뒤 30ms. `tool_input.answers`에 답 |
| T2 | Stop | +8,227ms | `"You answered: Red."` |
| T3 | UserPromptSubmit | +26ms | |
| T3 | PreToolUse(PowerShell) | +3,900ms | `tool_input.command: "echo hook-test-123"` |
| T3 | PermissionRequest(PowerShell) | +3,975ms | |
| T3 | PostToolUse(PowerShell) | +9,544ms | Enter(Yes) 뒤 약 0.6초. `tool_response.stdout` |
| T3 | Stop | +11,822ms | `"hook-test-123"` |
| 종료 | SessionEnd | `/exit` Enter 뒤 약 60ms, 프로세스 종료 1.5초 전 | `reason: "prompt_input_exit"` |

- 오지 않은 것: **SessionStart**(5회 모두), SubagentStart, PreCompact, PostCompact, PostToolUseFailure, PermissionDenied, StopFailure. 뒤의 다섯은 그 상황을 만들지 않았다.
- 모든 요청이 `POST`, `Content-Type: application/json`이었다. 26개 모두 `Authorization` 헤더의 토큰과 `X-MT-Session` 헤더의 세션 ID가 환경 변수 값 그대로 들어왔다. 본문 크기는 751~1,437바이트였다.
- 모든 본문에 `session_id`(넘긴 UUID와 같음), `transcript_path`, `cwd`, `scratchpad_dir`, `prompt_id`, `hook_event_name`이 있었다. `permission_mode`는 SessionEnd에만 없었다. `--permission-mode manual`로 띄웠는데 값은 `"default"`로 온다.
- `transcript_path`의 파일은 첫 UserPromptSubmit 때부터 모든 이벤트에서 이미 존재했다.
- 도구 이벤트의 필드: PreToolUse는 `tool_name`, `tool_input`, `tool_use_id`. PermissionRequest는 `tool_name`, `tool_input`과 때때로 `permission_suggestions`(notif 실행에서 `[{type: "setMode", mode: "acceptEdits"}]`)이고 `tool_use_id`는 없다. PostToolUse는 `tool_response`, `duration_ms`가 더 있다. Stop은 `last_assistant_message`, `stop_hook_active`, `background_tasks`, `session_crons`.

### 2.2 hook 하나에 걸리는 시간

Claude Code의 debug 로그에서 POST 시작과 응답 수신 사이를 쟀다. 네 실행의 정상 응답 25건이다.

| 최소 | 중앙값 | p90 | 최대 |
|---|---|---|---|
| 1ms | 5ms | 16ms | 25ms |

수신기 쪽 처리(도착부터 응답 전송까지)는 0~1ms였다. 비교로, 사용자 설정의 command hook 두 개(node 스크립트, PowerShell 스크립트)는 SessionStart마다 각각 205~257ms, 290~323ms가 걸렸다. PLAN 2.2의 "PowerShell command hook은 이벤트마다 약 0.2초"가 다시 확인됐고, http hook은 그 1/20~1/50이다.

### 2.3 막힘과 실패(delay, down 실행)

- **hook은 동기다.** 수신기가 PreToolUse 응답을 1.5초 늦추자 debug 로그의 간격이 1,516ms로 늘었고, 도구는 응답을 받은 뒤에야 돌았다(PostToolUse가 그 뒤 0.6초에 도착). 백엔드는 hook을 받으면 **먼저 200을 돌려주고 처리는 그 뒤에** 해야 한다. `timeout: 2`(초)는 이 2초짜리 보호막이다.
- **수신기가 없어도 Claude는 막히지 않는다.** 아무도 듣지 않는 포트로 보내자 debug 로그에 `connect ECONNREFUSED`가 2~8ms 만에 찍혔고, 턴은 1.6초 만에 정상으로 끝났다. 다만 **화면에는 오류가 보인다.** "UserPromptSubmit hook error", "Stop hook error: connect ECONNREFUSED 127.0.0.1:51586", "SessionEnd hook [http://…] failed"가 터미널에 그려졌다. 백엔드를 다시 시작하는 동안 판이 띄운 세션들에는 이 글이 쌓인다.

### 2.4 Notification과 내부 에이전트(notif 실행)

- 권한 요청(Write)을 12초 동안 두자 `Notification`이 **PermissionRequest 6.0초 뒤**에 왔다. `notification_type: "permission_prompt"`, `message: "Claude needs your permission"`. 즉 waiting의 첫 신호는 PermissionRequest이고, Notification은 "아직 기다린다"는 늦은 신호다. full 실행에서 5초 안에 답했을 때는 오지 않았다.
- Stop 1.2초 뒤에 `SubagentStop`이 하나 왔다. `agent_id`가 있고 `last_assistant_message`가 "delete hook-test.txt"였다. 사용자가 시킨 하위 에이전트가 아니라 Claude Code 내부 보조 에이전트(다음 프롬프트 제안으로 보이나 확인하지 않았다)의 것이다. 상태 계산기는 SubagentStop을 본 세션의 ready 신호로 쓰면 안 된다.
- 같은 `echo` 명령인데 모델이 `Bash` 도구를 고른 실행(delay)에서는 권한 요청 없이 바로 돌았고, `PowerShell` 도구를 고른 실행(full)에서는 권한 요청이 떴다. Windows에서는 도구 이름이 둘 다 나온다. 권한 상세를 보여줄 때 두 이름을 같이 다룬다.

### 2.5 SessionStart(start 실행)

같은 `--settings` 파일에 SessionStart http hook과 command hook(`cmd /c echo … > 파일`)을 함께 걸었다. command hook은 돌아서 파일이 생겼고, debug 로그에도 `SessionStart:startup [cmd /c …]`로 찍혔다. http hook은 debug 로그에 아예 나타나지 않았다. 같은 파일의 SessionEnd http hook은 왔다. 즉 `--settings` 문제가 아니라 Claude Code 2.1.312가 SessionStart에서 http hook을 부르지 않는 것이다.

## 3. 계획에 반영할 것

1. **상태 모델(PLAN 3절):** ready의 신호에서 `SessionStart`를 뺀다. 시작 직후의 ready는 E1의 방식(첫 출력 뒤 조용함, 대화상자 없음)으로 잡는다. 꼭 hook으로 받고 싶으면 SessionStart에만 command hook으로 `curl.exe`(프로세스 시작 약 34ms)를 걸어 같은 URL에 POST한다. `SubagentStop`은 상태를 바꾸지 않는다.
2. **waiting 판정:** `PermissionRequest`와 `PreToolUse(AskUserQuestion)`이 첫 신호다. 둘은 15~75ms 간격으로 같이 온다. `Notification(permission_prompt)`은 6초 뒤에 오는 보조 신호로만 쓴다.
3. **hook 수신기(PLAN 5절):** 토큰 확인 뒤 즉시 200을 보내고 이벤트로 넘긴다. 설정 파일의 `timeout`은 2초로 둔다. 헤더 보간은 `$VAR` 형태와 `allowedEnvVars`로 동작이 확인됐다.
4. **백엔드 재시작(PLAN C2):** 백엔드가 내려가 있는 동안 세션 화면에 hook 오류 글이 쌓인다. 짧은 재시작이라면 포트를 같은 번호로 다시 열어 오류를 줄이고, "지난번 비정상 종료" 표시에 이 사실을 함께 적는다.
5. **마지막 답(PLAN A2):** `Stop.last_assistant_message`로 충분하다. 대화 기록 파일은 첫 이벤트부터 존재하므로 "마지막 지시"도 바로 읽을 수 있다.
6. **도구 이름:** 권한 상세에서 `Bash`와 `PowerShell`을 같은 부류로 다룬다.

## 4. 남은 질문

- `StopFailure`, `PostToolUseFailure`, `PermissionDenied`, `PreCompact`의 본문은 보지 못했다. 필요해지면 그 상황을 만들어 확인한다.
- `--settings`의 hook이 사용자 설정의 같은 이벤트 hook과 어떻게 합쳐지는지는 "둘 다 돈다"까지만 확인했다(SessionStart에서 사용자 command hook 두 개와 우리 command hook이 모두 돌았다).
- Notification 6초는 한 번 잰 값이다. 설정으로 바뀌는지 모른다.
