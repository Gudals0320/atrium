# E3. 여러 줄, 수 KB 글을 `agent.prompt`와 `pane.send_input`으로 넣으면 그대로 제출되는가

2026-10-29에 했다. 결론부터 적으면 **글은 잃지 않고 한 번에 제출된다.** 100KB(1,728줄)까지 `agent.prompt` 한 번으로 들어갔고, 턴도 한 번만 돌았다. 그러나 **UserPromptSubmit hook의 `prompt`는 보낸 글과 글자 그대로 같지 않은 경우가 많다.** Claude Code가 4줄 이상이거나 800자를 넘는 붙여넣기를 입력칸에서 `[Pasted text #N +M lines]`로 접고, 제출할 때 `<pasted_content id="…">` 태그로 감싸기 때문이다. 감싼 안쪽은 줄바꿈 CRLF가 LF로, 탭이 공백 4칸으로 바뀌는 것 말고는 그대로였다. 접히지 않는 짧은 글은 끝의 공백과 줄바꿈만 잘렸다. 대화 기록의 user 항목은 10건 모두 hook `prompt`와 같았다.

## 1. 방법

| 항목 | 값 |
|---|---|
| herdr | 0.9.5, 이름 있는 세션 `multitask-e3`(본 실험), `multitask-e3b`(접힘 기준). 부모 Claude Code 환경 변수를 뺀 환경으로 띄우고 끝난 뒤 지웠다 |
| Claude Code | 2.1.312. `--session-id`, `--no-chrome`, `--permission-mode manual`, `--settings`(E2와 같은 http hook) |
| 시험 폴더 | `experiments/proj` |
| 스크립트 | `experiments/e3.cjs`, `e3-analyze.cjs`, `e3-threshold.cjs`, 공통 `herdr-lib.cjs`. 원본 결과는 `e3-result.json`, `e3-analysis.json`, `e3-threshold-result.json` |

사례마다 글을 보내고, UserPromptSubmit과 Stop hook을 기다린 뒤, hook의 `prompt`와 대화 기록의 마지막 user 항목을 보낸 글과 글자 단위로 비교했다. 모든 글은 "도구를 쓰지 말고 OK만 답하라"로 시작하게 해서 턴을 짧게 했다. 시험 글에는 한글, 이모지, 중국어·일본어, 탭, 빈 줄, 줄 끝 공백, 따옴표, 역슬래시, `$`, 백틱, HTML 태그를 섞었다.

## 2. 결과

### 2.1 사례별 결과

"응답"은 herdr 요청이 돌아온 시간, "제출"은 요청 시작부터 UserPromptSubmit hook 도착까지다. P3과 P4는 Enter 전에 일부러 기다린 시간(1.2초, 0.3초)이 제출 시간에 들어 있다.

| 사례 | 넣은 방법 | 글 | 제출 횟수 | 접힘·감쌈 | 감싼 안쪽(또는 글)과 보낸 글 | 응답 | 제출 |
|---|---|---|---|---|---|---|---|
| A1 | `agent.prompt` | 5줄(LF), 148B | 1 | 감쌈 | 같음 | 326ms | 395ms |
| A2 | `agent.prompt` | 5줄(CRLF), 144B | 1 | 감쌈 | CRLF → LF | 324ms | 350ms |
| A3 | `agent.prompt` | 한 줄 4,193B | 1 | 감쌈 | 같음 | 328ms | 357ms |
| A4 | `agent.prompt` | 350줄 20KB, 섞인 글 | 1 | 감쌈 | 탭 → 공백 4칸, 나머지 같음 | 398ms | 432ms |
| A5 | `agent.prompt` | 1,728줄 100KB | 1 | 감쌈 | 탭 → 공백 4칸, 나머지 같음 | 893ms | 1,888ms |
| A6 | `agent.prompt` | 3줄, 앞뒤 공백과 끝 줄바꿈, 112B | 1 | 안 감쌈 | 끝의 `"  \n"` 3자만 잘림. 앞 공백은 남음 | 323ms | 359ms |
| P1 | `pane.send_input { text, keys: ["enter"] }` | 3줄(LF), 121B, 괄호 붙여넣기 없음 | 1 | 안 감쌈 | 같음 | 1.8ms | 42ms |
| P2 | `pane.send_input { text, keys: ["enter"] }` | 한 줄 4,193B | 1 | 감쌈 | 같음 | 19ms | 125ms |
| P3 | `pane.send_input`로 `ESC[200~…ESC[201~` 직접 감싸 넣고, 화면 확인 뒤 `pane.send_keys ["enter"]` | 350줄 20KB | 1 | 감쌈. 화면에 `❯ [Pasted text #7 +349 lines]` | 탭 → 공백 4칸, 나머지 같음 | 87ms | 1,328ms |
| P4 | `pane.send_text` 뒤 0.3초 있다가 `pane.send_keys ["enter"]` | 한글 3줄 | 1 | 안 감쌈 | 같음 | 1.3ms | 335ms |

- 10건 모두 대화 기록의 user 항목이 hook `prompt`와 글자 하나 다르지 않았다. hook 본문은 A5에서 92KB였고 수신기가 문제없이 받았다.
- 한글, 이모지, CJK, 줄 끝 공백, 빈 줄, 따옴표, 역슬래시, `$`, 백틱은 감싼 경우와 안 감싼 경우 모두 그대로였다.
- 모델은 10건 모두 "OK"로 답했다. 감싼 글 안의 지시도 따랐다.

### 2.2 감싸는 모양

접힌 붙여넣기는 제출할 때 아래처럼 바뀐다. 입력칸에 따로 친 글이 없으면 앞부분은 빈 줄 두 개다.

```
"\n\n<pasted_content id=\"8afe\">\n" + 붙여 넣은 글 + "\n</pasted_content id=\"8afe\">\n"
```

- `id`는 16진수 4자리다. 한 세션 안에서는 모든 붙여넣기에 같은 값이 쓰였고(`multitask-e3`에서 `8afe`, `multitask-e3b`에서 `6ff5`), 세션마다 달랐다.
- 입력칸에 글을 먼저 친 뒤 붙여 넣으면 그 글이 감싸기 앞에 붙을 것으로 보이나, 확인하지 않았다.

### 2.3 접히는 기준(`multitask-e3b`, `agent.prompt`)

| 글 | 접힘·감쌈 |
|---|---|
| 2줄, 3줄 | 안 감쌈, 보낸 글과 같음 |
| 4줄, 5줄(31~37자) | 감쌈 |
| 한 줄 500자, 799자 | 안 감쌈, 같음 |
| 한 줄 801자, 1,000자, 2,000자 | 감쌈 |

기준은 **4줄 이상 또는 800자 초과**다. 정확히 800자는 보지 않았다.

### 2.4 그 밖의 관찰

- **`agent.prompt`의 응답 시간**은 작은 글에서 약 0.32초로 일정하고(E0의 322ms와 같다), 글이 커지면 늘었다(20KB 0.40초, 100KB 0.89초). 판의 전달 대기열은 응답을 기다리는 동안 다른 세션 전송을 막지 않게 한다.
- **괄호 붙여넣기 없이 넣은 LF**는 제출하지 않고 입력칸에 줄을 더했다(P1, P4). 제출은 Enter 키에서만 일어났다. 반대로 **CR이 든 글**을 괄호 없이 넣으면 줄마다 따로 제출된다(E4 2.5). xterm.js가 붙여넣기 때 줄바꿈을 CR로 바꾸므로 이 차이가 중요하다.
- **괄호 없이 한꺼번에 들어온 긴 글도 붙여넣기로 본다.** P2는 `pane.send_input`으로 4KB를 넣었을 뿐인데 감싸졌다. P4의 3줄 한글도 화면에 "paste again to expand"가 나왔다. Claude Code는 입력이 한 번에 몰려 오면 붙여넣기로 판단한다.
- 감싼 글은 모델에게 "사람이 친 글"이 아니라 "붙여 넣은 자료"로 보인다. 이번에는 모델이 그 안의 지시를 따랐지만, 판의 명령 바에서 보낸 긴 지시가 늘 같은 대접을 받는다고 단정할 수는 없다.

## 3. 계획에 반영할 것

1. **B1 규칙 6(제출 확인):** hook `prompt`와 보낸 글을 그대로 비교하지 않는다. `<pasted_content id="…">…</pasted_content id="…">` 감싸기를 벗기고, 보낸 글은 CRLF → LF, 탭 → 공백 4칸으로 바꾼 뒤 비교한다. 감싸지 않은 경우는 양쪽 끝 공백을 잘라 비교한다. 대화 보기(9.2 중간 얼굴)에 사용자 지시를 보여줄 때도 감싸기를 벗긴다.
2. **B1의 "여러 줄과 수 KB 글은 E3에서 확인한다"를 결과로 바꾼다:** `agent.prompt` 한 번으로 100KB, 1,728줄까지 한 턴으로 제출된다. 4줄 이상 또는 800자 초과는 `<pasted_content>`로 감싸져 들어간다.
3. **명령 바:** 보내기 전에 줄바꿈을 LF로 맞춘다. 판의 기본 전달 경로는 `agent.prompt`로 하고, `pane.send_input`·`pane.send_text`를 쓸 때는 글에 CR을 넣지 않는다.
4. **hook 수신기(5절):** 본문 크기 상한을 1MB 이상으로 둔다. 100KB 글에서 UserPromptSubmit 본문이 92KB였다.
5. **열린 질문으로 더한다:** 긴 지시가 붙여 넣은 자료로 감싸져 모델에게 전달되는 것이 지시 수행에 영향을 주는지. 필요하면 짧은 지시 한 줄을 먼저 치고 긴 글을 붙이는 방식을 P1에서 시험한다.
