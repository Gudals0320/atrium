# E10. 처음 쓰는 폴더의 신뢰 대화상자에서 herdr 상태는 무엇인가, `~/.claude.json`으로 미리 알 수 있는가

2026-10-29에 했다. 결론부터 적으면 **herdr 상태는 `blocked`다.** 시작 뒤 약 3.6초에 바뀌었고, 일반 규칙 `live_blocked_form`이 "esc to cancel" 글자로 잡았다. 권한 요청과 같은 상태라서 상태만으로는 구분할 수 없지만, **hook이 하나도 오지 않고 `agent.get`의 `launch_pending`이 계속 `true`이며 `agent_session`이 없다**는 점이 다르다. **`~/.claude.json`으로 미리 알 수 있다.** 단 폴더 자신만이 아니라 상위 폴더까지 봐야 한다. `esc`로 나가면 claude가 끝나고 `~/.claude.json`은 바뀌지 않았다.

## 1. 방법

| 항목 | 값 |
|---|---|
| herdr | 0.9.5, 이름 있는 세션 `multitask-e10`. 깨끗한 환경으로 띄우고 끝난 뒤 지웠다 |
| Claude Code | 2.1.312, 평소와 같은 인자(`--session-id`, `--no-chrome`, `--permission-mode manual`, `--settings`) |
| 시험 폴더 | 이 세션의 스크래치패드 아래에 새로 만든 빈 폴더 `e10-fresh-163433`. 끝난 뒤 지웠다 |
| 도구 | `experiments/e10-predict.cjs`(`~/.claude.json` 읽기만), `lab-daemon.cjs`, `lab.cjs`, `labfn.sh`. 원본은 `e10-timeline.json`, `e10-run.log` |

`workspace.create`와 `agent.start`로 띄운 뒤 1초마다 `agent.get`을 8번 읽고, 화면과 `agent.explain`을 읽고, `esc`로 나갔다. 대화상자에는 그 밖의 입력을 넣지 않았다. 막힌 상태에서 `agent.prompt`가 거부되는지는 대화상자에 글이 들어갈 위험이 있어 시험하지 않았다.

## 2. 결과

### 2.1 `~/.claude.json`으로 예상하기

`~/.claude.json`의 `projects`는 슬래시 경로(`C:/Workspace/multitask`)를 키로 쓴다. 항목은 97개였고 모두 `hasTrustDialogAccepted: true`였다. `e10-predict.cjs`는 폴더와 모든 상위 폴더의 키를 찾는다.

| 폴더 | 자기 항목 | 신뢰한 상위 폴더 | 예상 | 실제 |
|---|---|---|---|---|
| 새 폴더 `…/scratchpad/e10-fresh-163433` | 없음 | 없음 | 뜬다 | 떴다 |
| `C:/Workspace/multitask/experiments/proj` | **없음** | `C:/Workspace/multitask`, `C:/Workspace` | 안 뜬다 | 안 떴다(E0, E3, E4, E7, E9) |

`experiments/proj`는 자기 항목이 없는데도 대화상자가 뜨지 않았다. Claude Code는 상위 폴더의 신뢰를 물려준다. 폴더 자신의 키만 보면 잘못 예상한다.

### 2.2 herdr 상태와 화면

| 시각(`agent.start` 기준) | 일 |
|---|---|
| 0 | `agent.start` 응답 13.9ms, `agent_started`, `launch_pending: true`. herdr 문서의 `agent_not_ready`는 오지 않았다 |
| +0.2초 | `pane_agent_detected(agent: claude)` |
| 0~3초 | `agent.get` 상태 `unknown` |
| +3.6초 | `pane.agent_status_changed: blocked`. 그 뒤 약 40초 동안 그대로 |

- `agent.get`은 내내 `launch_pending: true`, `state_labels` 비어 있음, `agent_session` 없음이었다. 사용자 설정의 herdr SessionStart hook이 아직 돌지 않았다는 뜻이다. 정상 시작이면 약 4초 안에 idle이 되고 `agent_session`이 생긴다(E0 3.1).
- `agent.explain`: `matched_rule: live_blocked_form`(우선순위 980, 영역 `after_last_horizontal_rule`, 근거 글자 "esc to cancel"), `visible_blocker: true`. 신뢰 대화상자 전용 규칙이 아니라 "esc to cancel"이 보이는 양식 전반을 잡는 규칙이다.

### 2.3 hook

대화상자가 떠 있던 약 40초 동안 판의 hook은 하나도 오지 않았다(UserPromptSubmit, Notification 포함). `esc`로 나갈 때 SessionEnd도 오지 않았다. 신뢰를 받기 전에는 `--settings`의 hook이 돌지 않는 것으로 보인다.

### 2.4 나가기

- `esc` 한 번에 claude가 끝나고 패널이 PowerShell 프롬프트로 돌아왔다. 이벤트는 `pane_agent_detected(released: true, final_status: idle)`, 상태 `idle`, 0.3초 뒤 `unknown` 순서였다. `agent.list`에서 빠졌다.
- `~/.claude.json`의 수정 시각(16:34:01)은 시작 전과 같았고, 새 폴더의 항목은 생기지 않았다. 대화 기록 파일과 `~/.claude/projects` 아래 폴더도 생기지 않았다.

## 3. 계획에 반영할 것

1. **3절 trust_wait의 신호:** "herdr 상태가 이 경우 무엇인지는 E10에서 확인"을 아래로 바꾼다. 띄우기 전에 `~/.claude.json`의 `projects`에서 폴더와 **모든 상위 폴더**의 `hasTrustDialogAccepted`를 읽어 예상한다(키는 슬래시 경로, 읽기만 한다). 띄운 뒤에는 herdr `blocked` + hook 없음 + `agent.get`의 `launch_pending: true`, `agent_session` 없음 + 화면의 "Quick safety check"로 확인한다.
2. **3절 waiting 규칙:** herdr `blocked`만으로 waiting을 정하지 않는다. 같은 `blocked`가 신뢰 대화상자에서도 나온다. PermissionRequest나 PreToolUse(AskUserQuestion, ExitPlanMode) hook이 함께 있으면 waiting, 없고 `launch_pending`이면 trust_wait로 본다. 둘 다 아니면 "알 수 없는 대화상자"로 화면을 보여준다.
3. **B3(새 세션 시작):** "처음 쓰는 폴더면 신뢰 확인이 필요하다"를 미리 보여줄 때 상위 폴더 규칙을 쓴다. 이 PC는 `C:/Workspace`가 신뢰돼 있어 그 아래 프로젝트는 묻지 않는다.
4. **trust_wait에서의 답:** 판은 신뢰를 대신 누르지 않는다(BRIEF "마지막 Enter는 사람이 누른다"). 카드는 "터미널에서 답하기"로 보낸다. 사용자가 카드에서 직접 "신뢰"를 누르게 할지는 열린 결정에 둔다. 넣는다면 키는 `down`, `enter`다(E1). 기본 선택이 "No, exit"라서 Enter만 보내면 claude가 끝난다.
5. **신뢰 거부로 끝난 세션:** `esc`나 "No, exit"로 끝나면 hook 없이 herdr 해제 이벤트만 온다. 판은 이것을 exited("신뢰하지 않아 끝남")로 보여주고, 패널은 셸로 남는다.
6. **B3 3번(첫 지시 보내기):** `agent.start`가 신뢰 대화상자에서도 `agent_not_ready` 없이 바로 돌아오므로, 첫 지시는 `agent.start` 응답이 아니라 ready(herdr idle)를 기다려 보낸다. 지금 계획과 같다.
