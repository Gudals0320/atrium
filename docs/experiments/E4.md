# E4. 제어기 프레임을 xterm.js에 넣으면 Claude Code 화면이 제대로 그려지는가

2026-10-29에 했다. 결론부터 적으면 **그려진다.** 전체 화면 렌더러(기본)와 클래식 렌더러 모두, `herdr terminal session control`의 프레임을 넣은 `@xterm/headless` 화면이 herdr 자신의 화면 모델(`pane.read`)과 모든 체크포인트에서 줄 단위로 같았다(unicode11 애드온을 켰을 때). 실제 xterm.js(브라우저)로 다시 그린 화면도 표, 한글, 이모지, 문법 색, 권한 대화상자가 바르게 나왔다.

다만 **프레임은 Claude Code의 원래 출력이 아니라 herdr가 자기 화면 모델을 다시 그린 것**이다. 대체 화면, 괄호 붙여넣기, 마우스 추적 같은 터미널 모드가 xterm.js에 전해지지 않는다. 그래서 판이 세 가지를 직접 해야 한다. (1) unicode11 애드온을 켠다. (2) 붙여넣기를 괄호 붙여넣기로 감싸 보낸다. 감싸지 않으면 줄마다 따로 제출된다. (3) 마우스 휠을 SGR 마우스 시퀀스로 바꿔 보낸다. 그러면 전체 화면 렌더러가 스스로 스크롤한다. 클래식 렌더러는 지나간 출력을 xterm 스크롤백으로 받을 수 없으므로 판은 전체 화면 렌더러를 쓴다.

## 1. 방법

| 항목 | 값 |
|---|---|
| herdr | 0.9.5, 이름 있는 세션 `multitask-e4`, `multitask-e4b`. 깨끗한 환경으로 띄우고 끝난 뒤 지웠다 |
| 화면 모델 | `@xterm/headless` 5.5.0, `@xterm/addon-unicode11` 0.8.0. 브라우저 확인은 `@xterm/xterm` 5.5.0(DOM 렌더러)을 Edge headless로 띄워 스크린숏 |
| 렌더러 | 전체 화면은 기본값. 클래식은 작업 공간 `env`에 `CLAUDE_CODE_DISABLE_ALTERNATE_SCREEN=1`(Claude Code 실행 파일의 안내 문구에 나오는 변수) |
| 스크립트 | `experiments/e4.cjs`(체크포인트 비교), `e4b.cjs`(휠, PageUp, 붙여넣기, 칸 비교), `e4-shot.cjs` + `e4-render.html`(브라우저 스크린숏). 원본은 `e4-result.json`, `e4b-result.json`, `e4-frames-*.json`, `e4-shot-*.png` |

claude를 띄우기 전에 제어기를 120×40으로 붙여 시작부터 모든 프레임을 받았다. 프레임마다 xterm 두 개(유니코드 6 기본값, unicode11)에 넣었다. 체크포인트마다 프레임이 조용해지기를 기다린 뒤 xterm의 보이는 줄과 `pane.read { source: "visible" }` 글자를 비교했다. `e4b`에서는 `pane.read { format: "ansi" }`를 새 xterm에 넣어 칸 단위(글자, 전경·배경색, 굵게, 기울임, 밑줄, 반전, 흐림)로도 비교했다.

## 2. 결과

### 2.1 글자 비교

어긋난 줄 수다(120×40 화면, 90×30으로 줄인 뒤는 30줄).

| 체크포인트 | 전체 화면, 유니코드 6 | 전체 화면, unicode11 | 클래식, 유니코드 6 | 클래식, unicode11 |
|---|---|---|---|---|
| 시작 직후 | 0 | 0 | 0 | 0 |
| 턴 중(스피너) | 0 | 0 | 0 | 0 |
| 150줄 출력 뒤 | 0 | 0 | 0 | 0 |
| 마크다운 표, 코드 블록, 한글, 이모지 | 5 | 0 | 5 | 0 |
| 권한 대화상자 | 3 | 0 | 3 | 0 |
| 권한 답한 뒤 | 3 | 0 | 3 | 0 |
| 90×30으로 크기 바꾼 뒤 | 3 | 0 | 3 | 0 |
| `/exit` 뒤 셸 | 0 | 0 | 0 | 0 |

- 유니코드 6에서 어긋난 줄은 모두 이모지(🎉 🚀 ✅)가 든 줄이다. xterm 기본값은 이모지를 한 칸으로 세어 뒤 글자가 밀린다(`🎉  🚀`, `✅─`). 한글은 두 설정 모두 맞았다. **unicode11 애드온이 필요하다.**
- 칸 단위 비교(`e4b`, 빈 칸을 공백과 같게 봄)에서 4,800칸 중 다른 칸은 체크포인트 6개 중 5개에서 0칸, 하나에서 1칸(색 하나)이었다. 색과 글꼴 속성도 맞는다.

### 2.2 실제 xterm.js 화면

`e4-shot-fullscreen-6.png`(마크다운, 한글, 이모지), `e4-shot-fullscreen-7.png`(권한 대화상자), `e4-shot-classic-7.png`(클래식)를 눈으로 확인했다. 표 테두리, 한글 두 칸, 이모지 두 칸, 코드 블록 문법 색, 대화상자 선택지, 입력칸과 상태 줄이 터미널에서 보이는 그대로 그려졌다. 대화상자 안의 깨진 글자("pwsh exited with code 1: ◆◆◆…")는 Claude Code가 PowerShell 구문 검사 오류를 잘못 디코딩한 것으로, herdr 화면 모델에도 같은 글자로 있다(E9 2.1). 그리기 문제가 아니다.

### 2.3 프레임의 성격

| 항목 | 전체 화면 | 클래식 |
|---|---|---|
| 세션 전체 프레임 | 256개, 135KB | 281개, 117KB |
| 첫 프레임 | 전체(`full: true`), 5,130B | 전체, 5,130B |
| 크기 바꾼 뒤 | 전체 프레임 하나(6.9KB) 뒤 차이분 | 전체 프레임 하나(7.8KB) 뒤 차이분 |
| 늦게 붙은 관찰기 | 전체 프레임 하나(12KB)로 제어기 화면과 줄 0, 칸 0 차이 | 같음(12KB, 0, 0) |

- 첫 프레임은 `ESC[?2026h ESC[?25l ESC]8;; ESC\ ESC[2J ESC[1;1H …`로 시작한다. 프레임마다 동기 출력(`?2026`)으로 감싸고, 커서 숨김·보임, OSC 8 링크, 화면 지우기만 쓴다.
- **프레임에 없던 것:** 대체 화면(`?1049`), 괄호 붙여넣기(`?2004`), 마우스 추적(`?1000`, `?1002`, `?1003`, `?1006`), 포커스 알림(`?1004`), 창 제목(OSC 0/2), 스크롤 영역. E1에서 node-pty로 받은 Claude Code의 원래 출력에는 이 모드들이 있었다. 그래서 xterm의 버퍼는 늘 `normal`이고, `term.modes`의 `bracketedPasteMode`는 `false`, `mouseTrackingMode`는 `none`이었다.
- 크기가 같은 동안 xterm 스크롤백은 0줄이었다. herdr가 화면을 제자리에서 다시 그리기 때문이다. 전체 화면에서는 Claude Code가 스스로 스크롤하므로 문제가 없다. 클래식에서는 화면 위로 밀려난 출력이 xterm 어디에도 남지 않는다.

### 2.4 휠과 PageUp(`e4b`, 전체 화면)

150줄을 출력한 뒤 제어기 stdin의 `terminal.input`으로 키를 넣고, 프레임이 도착하기를 기다려 보이는 `row N` 범위를 읽었다.

| 입력 | 보이는 범위(프레임) | herdr 화면 모델 |
|---|---|---|
| 출력 직후 | row 118~150 | 같음 |
| 휠 위로 5번(`ESC[<64;60;20M`) | row 54~87 | 같음 |
| 휠 아래로 5번(`ESC[<65;60;20M`) | row 118~150 | 같음 |
| PageUp(`ESC[5~`) | row 101~134 | 같음 |
| PageUp 한 번 더 | row 84~117 | 같음 |
| PageDown 두 번 | row 118~150 | 같음 |

herdr는 xterm.js가 마우스 모드를 모르는 상태에서도 SGR 마우스 시퀀스를 패널로 넘겨 주고, 전체 화면 렌더러는 그것으로 대화를 스크롤한다. 반면 xterm.js를 그대로 두면 휠은 xterm 자신의 빈 스크롤백을 움직일 뿐이다. 클래식 렌더러에서는 휠도 PageUp도 화면을 바꾸지 못했다(row 119~150 그대로).

### 2.5 붙여넣기(`e4b`)

| 넣은 글(제어기 `terminal.input`) | 결과 |
|---|---|
| 괄호 없이 `"Reply with only OK.\rpaste line two\rpaste line three"`. xterm.js가 괄호 붙여넣기 모드가 꺼져 있을 때 붙여넣기로 보내는 모양이다 | **첫째·둘째 줄이 각각 따로 제출됐고**, 셋째 줄은 입력칸에 남았다 |
| `ESC[200~ … \r … \r … ESC[201~` | 한 번만 제출됐고, 줄바꿈은 LF로 들어갔다 |

판이 아무것도 하지 않으면 사용자가 노드 터미널에 여러 줄을 붙여 넣는 순간 줄마다 따로 제출된다.

## 3. 계획에 반영할 것

1. **P0 표의 E4:** "됨. 조건: unicode11, 붙여넣기 감싸기, 휠 변환, 전체 화면 렌더러"로 바꾼다.
2. **9.2 가까이 얼굴(xterm.js 설정):** `allowProposedApi: true`로 만들고 `@xterm/addon-unicode11`을 켠다(`unicode.activeVersion = '11'`). 프레임의 `width`·`height`가 바뀌면 그 프레임을 쓰기 전에 xterm 크기를 맞춘다.
3. **화면 중계의 입력 쪽:** herdr가 터미널 모드를 넘겨 주지 않으므로 판이 대신한다.
   - 붙여넣기: xterm.js의 붙여넣기를 가로채 `ESC[200~ … ESC[201~`로 감싸 `terminal.input`으로 보낸다. 또는 붙인 직후 로컬 xterm에 `ESC[?2004h`를 써서 xterm이 감싸게 한다(제안, 브라우저에서는 확인하지 않음).
   - 휠: xterm.js의 휠 처리를 막고 SGR 마우스 시퀀스(위 `ESC[<64;x;yM`, 아래 `ESC[<65;x;yM`)로 바꿔 보낸다.
   - 키보드의 PageUp/PageDown은 그대로 통한다.
4. **렌더러:** 판은 전체 화면 렌더러를 기본으로 하고 `CLAUDE_CODE_DISABLE_ALTERNATE_SCREEN`을 넘기지 않는다. 클래식으로 떨어지면(E1의 되돌림 문구) 노드에 알린다. 클래식에서는 지나간 출력을 노드 안에서 볼 수 없다.
5. **C1(화면 다시 붙이기):** "제어기의 첫 프레임이 전체 화면이다"를 "첫 프레임(약 5~12KB) 하나로 화면이 칸 단위까지 복원된다"로 구체화한다.
6. **10절 위험:** "프레임은 herdr가 다시 그린 화면이라 터미널 모드가 클라이언트에 오지 않는다"를 더한다. herdr를 올릴 때 이 동작이 바뀌는지 어댑터 시험에 넣는다.
7. **다음 실험:** 이 결과는 headless와 스크린숏 기준이다. 실제 Electron 창에서 붙여넣기, 휠, 한글 IME(E6)를 함께 본다. E5의 부하 측정에는 턴 하나 100~135KB의 프레임 양을 기준으로 쓴다.
