# E12. 터미널 노드에서 화면 밖 글까지 고르려면 글을 어디서 얻는가

2026-11-05에 했다(P42). 터미널 노드의 화면은 herdr가 다시 그린 프레임이고 xterm scrollback은 0이다(E4). 끌어 고른 채로 휠을 굴리거나 가장자리로 끌어 화면 밖 글까지 고르려면, 화면 프레임 말고 글의 기록이 있어야 한다. 기록을 어디서 얻을지 견주고 길을 골랐다. 결론부터 적는다.

- **셸은 herdr가 기록을 준다.** `pane.read`의 `recent`(기본값)와 `recent-unwrapped`가 셸의 지난 출력 전체를 준다(300줄 출력 뒤 300줄, 15ms 안팎). `--format ansi`로 색도 받는다.
- **Claude Code(전체 화면)는 herdr에 기록이 없다.** 판이 제어기를 붙인 동안에는 `recent`도 보이는 화면(40줄)뿐이다. 붙은 클라이언트가 없을 때는 읽을 때마다 0.7초쯤 걸리고, 결과가 41줄과 166줄(배너부터 대화 전체) 사이에서 들쭉날쭉했다. 쓸 수 없다.
- **Claude Code는 SGR 휠 한 번에 2~3줄 스크롤한다.** 한 번에 여러 번 보내면 덜 움직인다(3번에 5줄, 5번에 7줄). 위로 스크롤하면 맨 윗줄에 사용자 질문이 머리줄로 고정되고, 대화 영역 끝 줄에 "Jump to bottom (ctrl+End) ↓" 안내가 겹친다.
- **대화 기록(JSONL)의 글은 화면 글과 다르다.** 답이 마크다운 원문(`1\n2\n…`)이라 화면의 들여쓰기(`  118`), 그린 표, 도구 줄이 없다.
- **이 Claude Code(2.1.318, haiku)는 답을 다 만든 뒤 한꺼번에 그린다.** 일하는 동안 화면에서 바뀌는 것은 스피너 줄("✢ Meandering… (13s · …)")과 팁 줄이다.
- 그래서 **claude 등은 프레임을 이어 붙인 문서에 선택을 붙이고, 셸은 herdr 기록을 xterm scrollback에 넣는다.**

## 1. 방법

| 항목 | 값 |
|---|---|
| herdr | 0.9.5(protocol 22), 이름 있는 세션 `atrium-dev-p42`. 개발용 판(포트 47860)이 띄웠다 |
| 패널 | 판이 띄운 셸(PowerShell) 노드와 claude 노드(`--model haiku`, 1~150을 한 줄에 하나씩). 시험 폴더는 새로 만든 폴더 |
| 읽기 | `herdr pane read <패널> --source visible|recent|recent-unwrapped --lines 5000`을 같은 패널에 여러 번. 판의 제어기가 붙은 때(`atrium attach`로 붙여 둠)와 붙지 않은 때를 견줬다 |
| 휠 | 제어기(`terminal session control --takeover`) stdin으로 `ESC[<64;60;20M`(위)·`ESC[<65;…M`(아래)을 1·3·5번씩 보내고 `visible`의 첫 번호 줄을 읽었다 |
| 대화 기록 | 시험 폴더 대화의 JSONL에서 assistant 글을 꺼내 화면 글과 견줬다(읽기만) |
| 스크립트 | git 밖 `experiments/p42/tools/`의 `probe-read.cjs`, `probe-repeat.cjs`, `probe-wheel.cjs`, `probe-jsonl.cjs`, `probe-stream.cjs`. 결과는 같은 폴더의 `e12-*.json` |

## 2. 결과

### 2.1 herdr가 주는 글

| 패널, 때 | `visible` | `recent` | `recent-unwrapped` | 시간 |
|---|---|---|---|---|
| 셸, `cls` 뒤 300줄 출력 | 41줄(화면) | 302줄(1~300과 프롬프트) | 301줄 | 13~16ms |
| claude, 판 제어기가 붙음 | 41줄 | 41줄(화면만) | 40줄 | 10~16ms |
| claude, 붙은 클라이언트 없음(12번 읽기) | 41줄 | 41줄 7번, 166줄 5번 | 같음 | 680~790ms |

- 셸의 `recent`는 화면 너비로 감긴 줄이다. 끝의 빈 줄은 빠지고 화면 줄이 맨 끝에 온다. 그래서 지금 화면과 기록 끝을 줄마다 맞추면 화면 위의 줄 수를 알 수 있다.
- claude의 166줄은 붙은 클라이언트가 없을 때만 나오고 어느 쪽이 나올지 정해지지 않는다. 판은 노드를 보는 동안 제어기를 붙이므로 이 글을 쓸 수 없다.
- 제어기 프레임은 E4대로 화면만 다시 그린다. 프레임에 scrollback이 없다.

### 2.2 Claude Code의 SGR 휠(120×40)

| 보냄 | 첫 번호 줄 | 움직인 줄 |
|---|---|---|
| 처음 | 0번 줄 118 | |
| 위로 1번 | 1번 줄 116(0번 줄은 질문 머리줄이 가린다) | 3 |
| 위로 1번 | 113 | 3 |
| 위로 1번 | 110 | 3 |
| 아래로 1번 | 113 | 3 |
| 위로 3번(한 번에) | 108 | 5 |
| 아래로 5번(한 번에) | 115 | 7 |

판의 창 시험에서 프레임마다 잰 움직임도 3줄과 7~10줄이 섞였다. 그래서 몇 줄 움직였는지 짐작하지 않고 앞 화면과 새 화면을 견줘 찾는다.

### 2.3 일하는 중의 화면

`probe-stream.cjs`로 0.5초마다 화면을 읽었다. 강 이야기 80줄을 시킨 턴에서 30초 동안 바뀐 것은 스피너 줄의 글자(✢ ✽ ✶ · *)와 시간·토큰 수뿐이었고, 답은 턴이 끝날 때 한꺼번에 나타났다. 1~1500을 시킨 창 시험의 스크린숏도 같았다. P38의 "고른 자리의 글이 바뀌면 지운다"는 고른 범위에 스피너 줄이 들어가거나 턴이 끝나 화면이 바뀌는 순간 선택을 지운다. 고치기 전 판으로 재현하면 일하는 중에 고른 두 줄이 0.4초 안에 지워져 Ctrl+C가 클립보드를 바꾸지 못한 때가 있었다(`experiments/p42/repro-working.json`).

## 3. 길 견주기

| 길 | 셸 | claude(전체 화면) | 고름 |
|---|---|---|---|
| 복사 모드 겹치기(노드 위에 DOM 글) | herdr 기록으로 된다 | 기록 출처가 없다. 휠로 Claude Code를 스크롤해 이어 붙인 글을 DOM 앞에 더하면서 브라우저 선택을 지켜야 한다. 색도 따로 그려야 한다 | 안 고름 |
| xterm에 기록 넣기 | 첫 프레임 앞에 herdr 기록을 쓰고, 새 출력으로 밀려난 줄을 scrollback으로 보내면 xterm 자체 scrollback이 된다. 판 안에서 스크롤한다 | 스크롤은 앱이 하고 xterm 버퍼의 끝은 늘 Claude Code 화면이라, 화면 아래로 내려간 글을 담을 수 없다 | 셸 |
| 프레임 이어 붙이기(문서) | 셸은 앱이 스크롤하지 않아 지난 출력을 볼 수 없다 | 프레임마다 앞 화면과 견줘 움직인 줄 수를 찾고 본 줄을 문서에 모은다. 휠과 가장자리 자동 스크롤은 지금처럼 SGR로 보낸다 | claude 등 |
| 대화 기록(JSONL) | 없음 | 화면 글과 다르다 | 안 고름 |
| Claude Code 자신의 마우스 선택 | 없음 | 보지 않았다. 마우스 끌기 시퀀스를 넘기면 Claude Code가 고르고 복사할 수 있겠지만, 복사가 판 밖에서 일어나고 Ctrl+C가 판 규칙과 겹친다 | 안 봄 |

고른 두 길은 P42 창 시험(`app/test/e2e/p42-select.mjs`)으로 확인했다. 배율 1과 0.75에서 가장자리 밖으로 끌어 자동 스크롤한 claude 88~96줄, 셸 75줄이 기대한 글과 글자까지 같았다. 결과는 git 밖 `experiments/p42/p42-select.json`에 있다.

## 4. 남은 것

- 문서 이어 붙이기는 화면이 통째로 바뀌면(크기 바뀜, Claude Code가 대화를 다시 그림) 이어지지 않는다. 그때는 선택이 같은 문서 줄에 남는다.
- 셸 기록은 빠른 출력이 한 프레임에 지나가면 그 줄이 화면에 한 번도 보이지 않는다. 출력이 멈춘 뒤 herdr 기록으로 다시 맞춘다.
- herdr를 올릴 때 `recent`가 셸 기록을 계속 주는지, 제어기가 붙은 claude 패널에서 여전히 화면만 주는지 다시 본다.
